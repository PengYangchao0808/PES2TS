# Demo24 扫描选择器：TS/IRC 真值辅助诊断

日期：2026-10-01。目标：24 条反应最终对应 24 份唯一主拉伸计划，每条反应最多启动一次首轮主扫描；候选库不等于执行清单。

## 结论

当前实现完成的是候选枚举和合同验收，并没有完成该目标要求的化学决策层。502 条记录可以逐条复现，预算内有 144 条；24 条反应的首选中，有 11 条不满足“从已成键端沿键长增大的方向逼近 TS”的严格拉伸要求。仍无实际约束扫描结果，不能把任何候选称为物理验证成功。

本次用 24 条真实 TS 几何与双分支 IRC，得到每条反应一个主拉伸**诊断假设**。24 行均有已成键起点与大于 0.05 Å 的起点→TS 键长增加，但这不证明单坐标约束扫描能走到目标 TS。两条假设的 TS 键长超出另一端点键长；九条起点→TS 分支的距离回摆比例超过本诊断的 0.10 检查阈值，需要进一步查看逐帧曲线。这些假设不具有执行资格。

## 证据来源与边界

- 每条反应通过 `load_ts_geometry(..., allow_truth=True)` 与 `load_irc_frames(..., allow_truth=True)` 读取；访问记录追加到 `data/manifests/truth_access_log.jsonl`，caller=`demo24_truth_algorithm_diagnostic_20261001`。
- 原子行使用现有 P1 `map_to_atoms.ts_irc_index`，逐原子核验元素；用 TS 几何定位 IRC 的 TS 帧，拆解双分支，依据 P1 分支归属重组为 R→TS→P。24 条均无布局质量警告，TS 对齐残差均小于 0.03 Å。
- R/P 端点和算法候选来自冻结的 `tests/fixtures/p0_demo24`；未修改生产选择器、冻结数据或复核状态。
- 当前 RDKit 为 2026.03.3，fixture pin 为 2026.03.6。502 总数和旧验收记录一致，但不是在固定版本环境下重跑其 1356 项测试。
- 已读取 16 条 train 与 8 条 valid 的真值；这次是明确的真值辅助诊断，不能继续把本组 valid 作为未见真值的盲测成绩。
- 只有 TS 几何和 IRC；未读取虚频本征向量，未声称已做 OptTS/频率/IRC 的重新计算。

## 已确认的算法与接线问题

### 1. 缺少“一反应一主计划”决策层

`selector._assemble_candidates` 对驱动组合×方向/装配×时间表枚举。随后按排序保留前六个在预算内，其余继续记录。结果为 502 条记录，其中 358 条 `PRUNED_BY_BUDGET`、144 条预算内记录。该规则只限制数量，并不选择一个化学主方案。

现有排序没有“起点是否已有主拉伸键、向 TS 的运动是否为拉伸”的决策字段。它依次比较事件覆盖、几何检查、装配/能力、约束数、随动事件数、成本，最后按 map 词典序。默认 R/P 复核状态在 selector 中均硬编码为 false，方向判定被挡住，再以 R→P 的稳定枚举顺序处理平局。不能把这个稳定顺序当作化学优先级。

**实测**：11/24 首选不是明确的 B 拉伸，4/24 本诊断的主拉伸假设已被当前前六预算规则裁掉：RXN_0000017762、RXN_0000100736、RXN_0000149368、RXN_0000161724。该诊断选择是用真值设定的核查参照，不是经验证的最优计划。

### 2. 多组分原始坐标被当作共同坐标系，装配结果没有进入几何可行性

selector 调用了方向/装配模块，却在 `_assemble_candidates` 中继续把原始 `materials` 交给 `assess_geometry_feasibility`；没有使用 `direction_result` 内装配后的坐标。不同独立组分之间的原始距离可能只是坐标原点造成的偶然数值，不应作为约束扫描端点。

**RXN_0000109608** 是直接反例：反应物由两个独立组分构成，首选 B(3,4) 的 fixture 端点范围为 **1.424→1.493 Å**，而真值 IRC 对应 **3.181→1.495 Å**，TS 为 **1.830 Å**。当前范围既没有覆盖 TS，增减方向也与真实 IRC 相反。不能简单指责为原子映射错误；主要问题是跨组分相对放置未进入实际规划几何。

多组分反应优先从已成键、整体几何完整的一侧拉伸，有助于避开另一侧的初始靠近/装配歧义；仍须核验所有监测键和片段位置。

### 3. 正常检查说明被错误提升为失败码

`schedules.assert_schedule_integrity` 返回正常说明，例如 `driver_ids_resolved=1`、`no_difference_coordinates`、`double_distance_records_distinct`。selector 遍历 `scheduled.integrity_notes`，对每条说明都追加 `SCHEDULE_INTEGRITY` 失败。

**实测**：502 条候选累计 662 条 `SCHEDULE_INTEGRITY` 原因。正常注释和真实异常混淆，会污染冻结拒绝、失败树和科学统计。正常返回说明应进 diagnostics；真正的异常应是单独的 typed failure。

### 4. monitor 与 target_test 绑定错误

`_candidate_payload` 调用 `_monitor_payload(record, monitor_ids, pool)`，实际传入的是 monitor ids，而不是 `pool_candidate.target_test_coordinate_ids`。内部再依据原子集合包含关系选目标，没有核对坐标类型或单位。

**实测**：450/502 条候选包含类型错配。RXN_0000007104 中，`A:1+11+3` 被绑定到 `target:B:1+3`，`B:3+11` 又绑定到 `target:A:1+11+3`。监测量不应靠原子集合包含关系猜测其数值目标；应使用显式事件/测量身份和同量纲映射。

### 5. 原始笛卡尔直线插值碰撞不能作为物理路径不可行的充分证据

几何可行性对原始 R/P 坐标做笛卡尔直线插值，在驱动原子子集里检查碰撞。分子旋转、构象变化和独立组分原点会使直线插值发生碰撞，而真实受约束优化路径可以弯曲。生产逻辑将此写为硬失败，并影响排序。

**实测**：174 条候选带 `PATH_COLLISION`；其中 138 条在相同驱动原子子集及相同 R∪P 非键对定义下，真实 IRC 全程没有小于 0.8 Å 的距离。这证明“这个插值碰撞”不等于“该反应没有无碰撞路径”；并不能证明这 138 个具体约束方案都能算通。应先对齐/装配，再做局部投影或短程受约束预优化；直线插值异常宜标为预检风险。

### 6. 同步线性约束不一定包含真实 TS

RXN_0000007104 的 H 转移：断键 B(1,11) 在 TS 的端点归一化进度为 **0.257**；成键 B(3,11) 为 **0.811**。如果强制两个距离共享同一线性进度 λ，真实 TS 不能同时满足这两条约束。这里更合理的首轮假设是单独拉伸供体 N–H，另一条键作为监测；必要耦合应由证据决定，不能因为“同一事件”就同步硬驱动。

22/24 反应存在多驱动线性候选，其真实 TS 驱动进度差大于 0.25。该阈值仅为诊断筛选，不是物理成功判据。对多个驱动共同施加同一个 smoothstep 只是共同重参数化，不能修正驱动间相对时序。只有各驱动具有不同进度曲线，才能改变它们共同约束的几何路径。

### 7. 端点键长不能保证覆盖 TS

本诊断主假设中，RXN_0000059834 的 B(1,10) 从 P 的 1.866 Å 到 TS 的 3.483 Å，但 R 为 2.789 Å；RXN_0000194484 的 B(2,10) 从 P 的 1.094 Å 到 TS 的 2.152 Å，R 为 2.103 Å。若只以另一个端点的距离作为拉伸终点，存在扫描尚未越过 TS 就终止的风险。

生产规划不能直接用 TS 真值设范围；应使用键型/反应类型的物理范围、动态扩展与预算停机条件。本次真值仅提供反例。

### 8. release_gate 不是可执行性或化学通过门

`all_release_gates_pass` 主要核对非全部预算裁剪，以及 fallback 策略名存在。实测 24/24 返回 true，同时 502/502 带 `DIRECTION_NOT_READY`，所有 proposal 的 `execution_eligible=false`。该门只表示策略引用闭合，不能在报告中解释成“算法可执行”或“化学选择已通过”。

## 建议的修复与验收顺序

1. 修复装配坐标传播、正常说明→失败码、monitor→target_test 显式绑定；保留真实 review/backend 拒绝。
2. 增加主计划选择层：每个 reaction_id 只允许一个 `primary`，备选仅留在审计库；首轮执行 manifest 唯一 reaction_id 数=24、主计划数=24、每反应最大主尝试=1。任何不合格案例必须显式 blocked，不能用降低门槛凑满。
3. 主计划优先选已成键端的有效拉伸坐标；事件随动没有物理证据时作为 monitor，不直接升级多驱动同步约束。确需耦合的反应允许一份主计划内有必要的多个坐标，并单独说明。
4. 验收从“合同正确、有记录、能拒绝”增加到“坐标与化学变化相符、方向为目标拉伸、范围覆盖核查 TS、monitor 量纲正确、预算没有裁掉主计划”。TS/IRC核查用于开发验证，不加入生产选择器输入。
5. 完成化学复核和后端能力冒烟，然后执行24份主计划；用真实路径、TS优化、频率与IRC记录实际成功/失败，不用离线测试通过率替代科学结果。

## 0. 摘要

**一句话**：代码库已经从「单一 Classic 流水线」长成「G0–G4 主干 + V4/V5.1–V5.4 历史战役 + V5.5 新骨架」的三层结构——**主干健康、历史层庞大但受宪法保护、门禁在 HEAD 上有一处红灯**；归档的正确动作是「冻结标签 + 明确状态 + 移入 archive 区」，而不是删除历史代码。

六个关键数字：

| 指标 | 值 | 说明 |
|---|---|---|
| Python 文件 / 行数 | **991 / 443,792** | AST 清点；git 跟踪 981 个（差异见 §2.4） |
| 主包 `pes2ts_core` | 365 文件 / 162,756 行 | 其中 `pesn` 185 文件 / 91,073 行（56%） |
| 测试 | 345 文件 / 148,231 行 | `tests/legacy/pesn` 150 / 63,644；`tests/legacy/agent_ops` 42 / 23,773 |
| 脚本 | 225 文件 / 123,791 行 | `archive/v5x_scripts/agent_ops` 66 / 60,778 最大 |
| 新骨架 `pes2ts_v5` | 42 文件 / 4,358 行 | 14 架构齐备，**`tests/v5` 缺失**、未接真实数据 |
| 本地门禁 | **1 红 3 绿** | `truth_guard` FAIL（4 处 `.eval()`）；docs / 链接 / G–V 映射 / registry 测试均绿 |

五条结论：

1. **架构分层清晰，但「历史层」占代码大头**：V4 + V5.1–V5.4 相关代码约 10 万行（含测试/脚本），V5.5 新骨架仅 4.3k 行；归档需求真实存在。
2. **宪法要求「历史只读、不删不改」**（P1 + CODE_MAP §3 V4 规则），因此 V4 dual_ts 全家（59 文件 / 33,006 行）与 V5.4.x 模块**不应删除**，应冻结并标注。
3. **HEAD 上 `truth_guard` 红灯是唯一 CI 级阻断**：4 处 `torch` 的 `.eval()` 被 AST 守卫判为 `DYNAMIC_EXEC_RISK`（误报语义，但门禁是真红）；建议 `model.eval()` → `model.train(False)`（等价语义、不削弱守卫）后复绿。
4. **`CODE_MAP` 已落后于现实**：78 个 `.py` 引用中 39 个不存在（全部为 V5.2-R/V6/V7 planned，未实现）；同时新增的 `pes2ts_v5/`、`scripts/datastore/`、`scripts/infra/` 未入图。归档前应升级 `CODE_MAP`（或加 SUPERSEDED 指针），否则后来者会按图找错。
5. **G–V 注册表与新路线的 V6/V7 编号冲突仍是治理遗留**（M3）：注册表中 `V6.0/6.1/6.2`、`V7-A/B/C` 全部 `archived` 旧语义，而 v2.0 定义新 V6.0–V6.3/V7.0–V7.3；V6 启动前必须修订，否则 run 记录的 `campaign_id` 无法解析。

## 7. 归档建议（按宪法 §12.5 / ADR-0035）

### 7.1 四类处置

| 类别 | 对象 | 动作 | 理由 |
|---|---|---|---|

| **B 冻结封存（不删、不改）** | V4 双端线（`contracts/dual_ts.py`、`features/dual_ts_*`、`models/dual_egnn*`、`offline/*/dual_ts_*`，59 文件 / 33,006 行）；V5.4.1/2/3 models | 打只读标签（已有 `archive/pre-v55-legacy-20261123`）+ 在 CODE_MAP/文档标注 `Frozen` | P1「历史产物只读」；CODE_MAP §3 明文「不删除、不改语义」 |

### 7.2 不建议做

- ❌ 不删除 V4 与 V5.4.x 代码（违反 P1/CODE_MAP 规则）；
- ❌ 不移动 `tests/` 中的历史测试（它们是回归证据；只做归属标注）；
- ❌ 不在同一提交里「移动 + 改逻辑」（宪法 §12.1 要求声明/ADR/证据/同步）；
- ❌ 不把 `scripts/local/` 的补丁当作能力证据（未版本化）。

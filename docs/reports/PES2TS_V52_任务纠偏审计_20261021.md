# PES2TS V5.2 任务纠偏审计 — Stop 应发生在目标端点，而不是 TS

> 生成：2026-10-21 · 编制：supervisor（只读审计，无新训练）
> 结论等级：**任务定义层根因确认**；决策见 [ADR-0030](../design/decisions/ADR-0030-V5.2全路径导航与端点停止.md)
> 数据：`outputs/pesn/30h_campaign/data/` 六表（dataset_sha256=4635c330…，50 曲线 / 12034 行）+ 本地代码 HEAD 94b7da9
> 全部数字由直接重算得到，脚本化可复现；本文是 ADR-0030 的证据基础。

## 0. 一句话结论

V5.2 的 Stop 头学的任务是"靠近 TS 就停"，而 PES2TS 的任务是完整路径导航"到达目标端点才停"；更严重的是，**真正的终点到达样本被 `terminal` 状态排除在 Stop 训练之外**。Stop AUC≈0.5 是标签-任务错配的必然结果，不是"Stop 难学"或"容量不足"。

## 1. 终点样本没有进入 Stop 训练（核心发现）

训练入口 `scripts/campaigns/r3_v52_run.py:158-160`：

```python
dataset = KeyAtomDatasetV3(
    args.data_dir, split_manifest=args.split,
    label_statuses=("ok",))
```

`sample_view.csv` 的 200 个端点行（50 曲线 × 2 端点 × 2 intent）实测状态：

| 端点行角色 | 数量 | label_status | 旧 stop 标签 | 是否进入 V5.2 训练 |
|---|---:|---|---|---|
| 到达目标端点（forward@B / reverse@A） | 92 | `terminal` | 0 / 偶然 1 | **否（被排除）** |
| 从端点出发（forward@A / reverse@B） | 90 | `ok` | 0（Move） | 是（作为负例） |
| gauge / conflict | 18 | `masked`/`conflict` | — | 否 |

- 到达端点行 92 个中 90 个 stop=0、1 个 stop=1（TS 窗口偶然命中）、1 个 Mask；
- 即：**"应该 Stop"的样本被排除，"应该 Move"的样本以负例进入训练**——Stop 头从未见过正确的终点正例。

## 2. `terminal` 语义混用：no_future_contact ≠ 反应终点

`teacher_manifest.json`：

> `terminal`: path exhausted below d0 → `label_status=terminal, mask=true`

实测 1123 个 terminal 行：

| 统计 | 值 |
|---|---:|
| 距最近端点的节点距离 中位 / 最大 | 6 / 47 |
| 距最近端点 ≤5 节点的行 | ~430 |

terminal 的真实含义是"沿 intent 方向剩余路径不足一个 d0 contact"（Move 教师无目标），**不是**"当前构型是反应端点"。它大量分布在目标端点附近——恰是 Endpoint Stop 最需要的区域——却被 `label_statuses=("ok",)` 全部排除。`key_atom_teacher.py` docstring 遗留的 "TS-terminal" 措辞进一步加重了混用（函数本身不绑定 TS；R3 builder 传入的是完整曲线）。

## 3. 旧 Stop 正例全部在 TS 附近

`key_atom_dataset_v3.py:956-960` 用 `d_key_TS`（Kabsch 对齐后 K 几何到参考 TS 的 RMSD）生成三态标签（≤0.04 正 / ≥0.12 负 / 中间 Mask）：

| 统计 | 值 |
|---|---:|
| 正例行 / 独立 (curve,node) 正例 | 405 / 196 |
| 每曲线正例中位数 | 6 |
| 正例 d_key_TS 中位 | 0.021 Å |
| 端点行中的正例 | 2 / 200（偶然） |

Move 教师在 TS 处继续前进（正确），Stop 教师却在 TS 附近要求停止——两个头描述的不是同一个导航任务。

## 4. Move 教师是全路径的、正确的

| 统计 | 值 |
|---|---:|
| ok Move 行 | 9655 |
| Move 目标指向远离 TS 的行 | 4414（45.7%） |
| 距 TS ≤5 节点行中远离 TS | 623 / 972（64.1%） |
| approach 侧目标越过 TS | 248 / 5337（4.6%） |

对 Full-Path Navigation 而言，"穿越 TS 后继续远离 TS"是**正确监督**。此前把这些行当作"教师冲突"证据的解释不成立；据此提出的 approach-side filter / TS-directed Move / TS-neighborhood Stop 修复方案正式撤回。

## 5. "q 不可学习"结论降级为 exploratory

战役后线性探针（`stats/q_informativeness_probe.json`，MAE 0.4722 vs 常数 0.4724，改进 0.0%）存在两个混淆：

1. **双侧池化**：signed q 在 TS 两侧/双 intent 下符号相消；
2. **48 条曲线**：dev folds 0–2 仅 30 条（ok 行 28 条），疑触 sealed folds 3/4，违反封存纪律的可信使用。

快速复核（exploratory，48 曲线全量，仅方向判断）：

| 子集 | corr(q, d_key_TS) |
|---|---:|
| 全部行 | −0.147 |
| approach 侧 | −0.793 |
| approach 侧曲线内中位 | −0.932 |
| away-side | +0.840 |

approach 侧（= 当前 intent 的起始侧，即朝 TS 接近的半程；术语区别于已撤回的 approach-side filter）上用 key-pair 距离的 HistGradientBoosting：常数基线 MAE 0.2498 → 0.2425（corr 0.326）；曲线内 pairwise ordering mean 0.728 / median 0.796（逐曲线 0.01–1.0，方差大）。

**结论修正**："q 的绝对回归很难"成立；"q（及其排序信息）完全不可学习"不成立。q 保留为辅助量 + directed ordering（ADR-0030 §2.4）；dev-only、approach 侧的正式探针列入 D1。

## 6. Endpoint Stop 标签可行性（窗口预检）

对全部 12034 行计算 \(d_{\rm end}=\operatorname{RMSD}_K(X, X_{\text{target endpoint}})\)（forward→B，reverse→A）：

| 窗口 (pos/neg) | 正例 | 负例 | Mask | 每曲线正例 min/med/max | 起点误正例 | TS 误正例 |
|---|---|---|---|---|---:|---:|
| 0.10 / 0.30 | 1781（14.8%） | 8399 | 1854 | 9 / 32 / 90 | 0 | 2/100 |
| 0.12 / 0.30 | 1995（16.6%） | 8399 | 1640 | 14 / 35.5 / 95 | 0 | 2/100 |
| 0.15 / 0.30 | 2287（19.0%） | 8399 | 1348 | 17 / 42.5 / 106 | 0 | 2/100 |

- 起点/TS 的 d_end 分布：起点中位 1.01 Å（min 0.48）；TS 中位 0.60 Å；目标端点 = 0；
- 主候选 **0.10/0.30 Å**：正例规模健康（vs 旧 TS 标签 4.6%），起点零误正例；
- 2 个 TS/端点几何退化样本须 flag/mask：`RXN_0000001174`（TS node 55，d_end=0.066）、`RXN_0000001675`（TS node 76，d_end=0.019）。

## 7. 20 步 rollout 预算不足

按每条曲线关键原子路径总弧长 / d0=0.08 Å 估算所需步数（48 条 ok 曲线）：

| 统计 | 值 |
|---|---:|
| 总关键原子弧长 min / 中位 / max | 0.89 / 1.74 / 4.66 Å |
| 估算步数 中位 / max | 22 / 58 |
| 需要 >20 步的曲线 | 71% |

V5.3 的 20×0.08 预算对 71% 曲线不足；"弧长饱和 62%"至少部分是预算限制，不能全部归因模型。V5.2-R 采用长度感知预算 B=max(40, ⌈1.5·L_key/0.08⌉) 并单独报告 `budget_limited`。

## 9. 对既有文档结论的处置

| 旧结论 | 处置 |
|---|---|
| "H1 确立：q 单帧不可辨识（架构无关）" | **降级为 exploratory**（双侧池化 + 疑用 sealed folds） |

| approach-side / TS-directed / TS-neighborhood 修复草案 | **正式撤回** |

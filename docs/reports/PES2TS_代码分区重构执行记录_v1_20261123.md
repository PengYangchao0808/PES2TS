## 1. 背景：为什么必须重排

重构前仓库 Python 约 **44.4 万行 / 991 文件**（[代码探查报告 v1](PES2TS_代码探查报告_v1_20261123.md)：443,792 行；其中 `pes2ts_core` 365/162,756、`tests` 345/148,231、`scripts` 225/123,791、`pes2ts_v5` 42/4,358）。核心问题不是"代码多"，而是**战役版本堆叠**：

1. 每轮战役（V5、V5.1-R3、V5.2-R、V5.3-MP、V5.4.1/2/3、V5.6）新增一套脚本目录 + config 目录 + 训练入口，同一件事有多份实现；
2. 多个 driver 各自写训练步（`.backward()` / `optimizer.step()`），训练循环语义随战役漂移；
3. 文件名即版本号（`v541_*.py`、`run_v5_1_r3.py`），活跃区无法回答"当前入口是哪一个"；
4. `archive` 与活跃代码边界模糊，活跃区 import 历史战役模块。

[ADR-0036](../design/decisions/ADR-0036-功能分区与单一训练引擎.md) 的决策是：**五功能区 + 单向依赖 + 四个合同 + 五道硬门**，让"当前代码"有唯一位置、唯一入口，并让结构性退化在 CI 变红。

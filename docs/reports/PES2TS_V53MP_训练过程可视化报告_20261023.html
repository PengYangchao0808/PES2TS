§00

先读这一页：5 分钟从化学反应到损失函数

这一页从零开始解释本项目的缩写和术语。读完它，后面的图和数据会容易很多。如果只有 3 分钟：读 §00.1、§00.2 和最后的「只记三件事」。

§00.1化学：模型到底在学什么？

一场化学反应可以画成一条能量曲线（多维时就是势能面，PES）：反应物 A 在一个低能量的谷底，产物 B 在另一个谷底，中间隔着一座山。山顶就是过渡态（transition state，TS）。山顶不是普通的最高点：沿反应方向它是能量最高点，沿其他方向它是能量最低点；数学上是一个一阶鞍点，对应一个虚频（振动频率为虚数；TS 应只有一个虚频）。从 A 翻过 TS 到 B 的路径叫 IRC（intrinsic reaction coordinate，内禀反应坐标）。

模型不直接「猜 TS 的坐标」。它做两件事：

  • MOVE（移动头）：看当前几何，预测关键原子下一步往哪里挪一点。关键原子就是那些成键/断键的原子；其余原子在本轮评估中保持不动。每次挪动有上限（0.20 Å），避免一步跨太大。
  • PROCESS（过程头）：判断当前几何在路径上的位置（进度 q）、是否已经到达目标端点（p_end）、以及两帧谁更靠后（ordering，先后排序）。

为什么不让模型直接输出 TS？

  1. 监督太稀疏：一条反应路径只有一个 TS 点，而局部位移在每一帧都有目标；
  2. 部署接口本来就是「从当前帧往产物走一步」，不是「一次性吐出 TS 坐标」；
  3. 推理时只能看到当前几何 + 合法的反应拓扑，不能看到产物坐标、TS 坐标、能量或梯度——直接回归 TS 既不符合接口，也容易在实现中把参考坐标带进输入。

学习局部位移场可以在每一步都得到监督，也更符合实际使用方式。

物理意义

模型输出的不是「TS 在哪」，而是「从当前这帧出发，关键原子下一步该往哪个方向、走多远」。它像一个局部导航，而不是一张终点照片。

§00.2模型：输入、输出、损失

输入是一张「原子图」：节点是原子，边是键/近邻关系；此外还有合法的反应拓扑（哪些键是目标键、方向如何）。共享主干是一个图神经网络（StarEGNNV3，55,441 个参数），把每个关键原子编码成一个向量 z。然后分两个头：

  • 移动头：输出每个关键原子的三维位移 û（Å）。
  • 过程头：输出 q̂（进度，−1 到 +1）、endpoint logit（终点完成度：到没到；过 sigmoid 得 p_end，终点概率）、ordering score s（先后排序）。

训练就是给这些参数找一组值，让输出尽量接近教师信号；损失函数衡量「差多少」。教师信号不是人标的，是从参考反应路径算出来的目标值（位移、q、终点标签、先后顺序）。

ML 一句话

这是一个监督学习问题——输入当前几何，输出位移/进度/终点概率，用损失函数把输出拉向教师目标。不是强化学习，也不是直接生成 TS。

§00.3数学：四个损失项，各管一件事

总损失（C 臂的完整形式；A 臂只保留 L_move，B 臂加 rank/q）：

L_total L = L_move + λ_rank·L_rank + λ_q·L_q + λ_endpoint·L_endpoint
四个损失项（简化公式；符号见附录 A.1）
项管什么公式（简化）直白解释
L_move下一步往哪走L_atom + 0.5·L_pair + 0.02·L_cos
L_atom = mean Huber_0.25(‖û−y‖ / 0.08 Å)		每个关键原子的位移要接近教师；键长变化也要接近；方向别反。Huber 让少数离谱样本不至于带偏训练。

L_q走到哪了mean Huber_0.1(q̂ − q)q 是 −1（反应物）到 +1（产物）的进度条；Huber 让大误差不被少数样本主导。

三个小定义：

  • Huber：误差小的时候像平方误差，误差大的时候像绝对值误差；好处是不让少数离谱样本主导梯度。
  • softplus：log(1+e^x)，是 max(0, x) 的平滑版；ranking 损失在「顺序已经对了且差距足够」时接近 0。
  • BCEWithLogits：二分类的交叉熵；pos_weight 是正例权重，用来对付类别不平衡（此处 ≈ 4.7 ≈ 负例数 ÷ 正例数）。

λ（每项损失的权重）是音量旋钮：λ 太大，辅助任务会抢共享主干的梯度，可能伤害 MOVE；λ 太小，辅助任务学不动。本次没有在 dev 上网格搜 λ，而是用一个小探针测量「这项损失在共享主干上占多少梯度」：endpoint 校到 2.0%，q / rank 在 0.5 上限只到 1.4% / 0.48%，如实记录「没达到目标区间」，然后按上限跑。这是为了避免在测试集上调参。

怎么读

为什么不能横向比总 loss？A 的 loss 只有 L_move；B/C 的目标函数多了 rank/q/endpoint，所以总 loss 天然不同（具体见 §02–§03），不要横向比。跨臂只看下游指标（RMSE/zero、ordering、AUPRC、guard）。

§00.4数据：训练、选模型、考试

  • 训练池 20,000 条反应：2k ⊂ 5k ⊂ 20k，按同一排序嵌套；这样 2k/5k/20k 的差别只有数据量，数据内容不换。
  • inner-val（训练池内部的验证子集）8,192 条样本：从训练池里留出，用来选 checkpoint（模型参数快照）和校准 τ_end（终点判定阈值）；不是最终考试集。
  • dev（独立开发集）589 条曲线 / 135,926 帧：所有报告数字都在这里；训练时没见过。
  • confirm（封存确认集）2,000 条曲线：只列了名字，本次没读没建；等最终确认时才用。
  • seeds 17/29/43（随机种子）：不同的随机初始化和采样顺序；3 个 seed 用来看「结果稳不稳」，不是用来算 p 值。
ML 一句话

训练集用来学参数，inner-val 用来选模型/调阈值，dev 用来报告，confirm 留到最后。任何在 dev 上反复调参都会让 dev「变脏」；本次的 λ 是在 inner-train 的梯度探针上定的，不在 dev 上调。

三个容易误读的地方：

  1. AUPRC 0.24 不是「24 分」：正例只占 17.5%，随机猜的 AUPRC 大约就是 0.175；0.24 是比随机高约 40%，但 AUROC 0.60 只是中等信号。
  2. guard 负值是好事：guard =（新模型 RMSE − 旧基线 RMSE）/ 旧基线 RMSE ×100%；负值表示新模型误差更小。+2% 才是「变差了 2%」。
  3. 2k 不是「小数据点」：2k 只有 100 次更新、1 个 seed，而且 B/C 全在冻结段；它只证明管线跑通，不参与规模判断。
只记三件事
  1. 模型不是「直接画 TS」，而是学「下一步往哪走」（MOVE）+「走到哪 / 到没到」（PROCESS）。
  2. 数据规模是主变量：5k → 20k，ordering 从 0.57 到 0.80；Move RMSE/zero 从 0.924 降到 0.883。
  3. 训练指标好 ≠ 能部署：endpoint 头在 s29 上 seed 分裂，闭环 0.10 Å 到达率很低；No-Move 控制权未授予。
§01

读法：三臂与三级规模

这一节在问什么：三个臂到底差在哪？为什么 2k 不算规模点？为什么要有 A 臂？

这不是一张 leaderboard。V5.3-MP 的问句是：数据规模是不是主变量？过程监督会不会伤害 MOVE？endpoint 头是否值得单开一臂？三臂的差别只有目标函数——数据、初始化、评估集完全相同。

A 只学 MOVE；B 加上 directed pairwise ordering（rank）与进度回归（q）；C 再加上 endpoint 分类。规模从 2k 冒烟走到 5k 规模门，再到 20k 主结果。2k 的 B/C 100 次更新全部落在 encoder 冻结段内；A 臂没有冻结段，但 2k 仍只是 100 步冒烟。B/C 的 process 头没有机会影响表征——它只回答「管线是否跑通」，不回答「过程监督是否有效」。

怎么读

2k 的 B/C 只训练 100 步，而且全在 encoder 冻结段（前 400 步共享主干参数不更新）；它不是「小数据效果差」的证据，而是「管线能跑通」的烟雾测试。真正的规模比较看 5k → 20k。

实验条件

固定 init（全部 run 逐比特同一初始参数）：R3 F2-bidir winner（上一代最佳配置，F2 双向）5372d9b12807c3f0
backbone：StarEGNNV3 · 55,441 参数
评估：dev 589 曲线 / 135,926 帧 · inner-val 选择 · confirm 2,000 与 sealed 全程未触碰
分母：Move 指标 557 个可定义 cluster · endpoint 113,040 个非 mask 行

物理意义

A/B/C 不是三个不同的网络结构，而是同一网络结构、同一份数据、同一个初始化下的三组目标函数；训练后参数不同。A 臂只学 MOVE，是对照；如果 B/C 的 ordering 比 A 好，不能是标签泄漏，只能是 process 监督真的起了作用。

§02

训练动力学

这一节在问什么：训练有没有发散 / NaN？四个损失项各自在学什么？为什么 B/C 的总 loss 比 A 大？

20k 的 9 个 run 都跑满 15,400 次更新。B/C 的前 400 步 encoder 冻结；A 臂没有冻结段（freeze_effective = 0），从头可训。三条总 loss 不在同一量纲：A 只有 L_move，B/C 还叠加 rank、q、endpoint。图 2 因此分三格、各自纵轴——跨臂比较只看下游指标，不看总 loss。

图 3 把目标拆开。最值得看的是左上：冻结段之后，三臂的 L_move 几乎重合，从约 0.25 降到 0.22——过程监督没有在训练中挤走 MOVE。rank 项从 1.31 降到约 0.80（逐 seed 0.54–0.97）；q 项在 0.05 附近；endpoint 项只在 C 臂出现，从约 0.70 降到 0.30–0.60，seed 间展开明显。

inner-val 的最低点都落在训练末端（A：14,700 / 14,900 / 15,400；B/C：15,300–15,400），没有早停；选择窗口在训练末端。

数学注 L_atom = mean Huber_0.25(‖û − y‖ / 0.08 Å) L_rank = mean softplus((0.1 − (q̂j − q̂i)) / 0.1)

L_move 里的 Huber_0.25 对小误差像平方、对大误差像绝对值，所以少数离谱样本不会把训练带偏；0.08 Å 是归一化尺度，让不同反应的位移误差可比。L_rank 的 softplus 是「平滑的 hinge」：顺序已经对了且差距 ≥0.1 时，损失接近 0。

§03

MOVE：基本盘

这一节在问什么：模型有没有学会「往哪走」？它比「完全不动」好多少？多任务学习有没有把 MOVE 挤坏？

图 4 是 20k 的 Move 基本面。三臂的 RMSE/zero 都在 0.88–0.90，sign 均值 0.86–0.87，dead-zone 0.048–0.059；R3 zero-shot 的对应值是 1.004、0.673、0.093。换句话说，20k 训练把中位 RMSE 改善了约 10–12%，这不是某一个 seed 的偶然：A 的三 seed 极差不到 0.001，B/C 也不到 0.01。

数字例子

以 A 臂 20k 为例：R3 zero-shot 的 RMSE 是 0.0802 Å，模型是 0.0706 Å——总体 RMSE 相对改善约 12%（这是 guard 的算法）。RMSE/zero 是另一种算法：先在每个反应上算「模型 ÷ 不动」的比值、再取中位，得到 0.883，即误差降低约 11.7%；所以 0.883 不是 0.0706 / 0.0802 的直接相除。RMSE/zero 的好处是：不同反应的绝对位移大小不同，除以「不动」的 RMSE 后可以横向比较。

三个辅助指标

sign：教师说某个键应该缩短 0.05 Å；模型缩短了 → 对；拉长了 → 错；几乎没动 → 也算错（与 dead-zone 互补）。SRE：教师说三个键分别变 50% / 30% / 20%；模型只动了一个键 → 比例分布错，SRE 高；SRE = 0 是完美，SRE = 1 是完全没动。dead-zone：教师认为该动（≥0.005 Å）、模型却几乎没动（<0.005 Å）的比例；越低越好。

图 5 是硬门。9 个 run 的 guard 全部落在 −9.90% 到 −12.01%，离 +2% 的破防线很远。A 的改善最大（均值 −11.98%）；B/C 因 rank/q 项各让出约 1.6–1.7 个百分点，仍大幅优于基线。

怎么读

guard 的例子：guard =（模型 RMSE − R3 RMSE）/ R3 RMSE ×100%。以 A 臂 20k 为例：0.0706 vs 0.0802 → 约 −12.0%（A 臂三 seed 均值 −11.98%）；负值是好事。硬门是 ≤+2%（最多允许变差 2%）。

规模轨迹：5k 的 RMSE/zero 是 0.923–0.928，20k 是 0.882–0.904；guard 九 run 均值从 −7.7% 走到 −12.0% ~ −10.3%。2k 只有 100 次更新、1 个 seed，且 B/C 全在冻结段——图 6 用空心点标记，不把它当作规模点。

§04

PROCESS：信号在 20k 变清晰

这一节在问什么：模型能不能判断「走到哪了」「到没到」「谁在前谁在后」？为什么 5k 只有弱信号、20k 才清楚？

图 6 的中间一格是这份报告的核心。A 臂的 ordering cross-TS 从 2k 到 20k 都贴在 0.50；B/C 在 5k 只到 0.57，在 20k 到 0.80。full 口径同样从 0.55 走到 0.71。q_head 的 corr 中位数从 5k 的 0.02–0.04 走到 20k 的 0.21–0.28（逐 run 中位数）。三条证据指向同一件事：过程监督不是没学到，而是需要规模才学得稳。

怎么读

q 的定义：以反应物为 −1、TS 为 0、产物为 +1；反向反应取负号。q 是进度条，不是停止按钮——到 TS（q=0）仍要继续走；q 也永远不作为停止判据。

ordering 的例子：同一反应的两帧，靠近产物的那帧应该 q̂ 更大；如果反了，就罚。0.5 = 抛硬币，0.8 = 80% 的 pair 排对。cross-TS 是「一帧在 TS 左边、一帧在右边」的更难子集。

注意 2k 的 B/C 是随机水平，这是预期：100 次更新全部在 encoder 冻结段，process 头没有机会影响表征。5k 的信号弱但方向一致；20k 的信号强且三 seed 一致。

图 7 是 endpoint。C 臂的 AUPRC 是 0.237–0.255，prevalence 0.1747；AUROC 0.591–0.602。A/B 的 endpoint 头未训练，AUPRC 停在 prevalence 附近、AUROC 约 0.50，正好是对照。但 C 的 seed 间不稳定：s17/s43 的 τ_end 是 0.58/0.71，dev 误停接近 0；s29 的 τ 只有 0.219，起点/TS 误停 0.631/0.622。这不是可以部署的停止头。

endpoint 的标签不是「到了 / 没到」这么简单：0.10 Å 内且目标键编辑完成才算正例；0.10–0.30 Å 多数 Mask（标签不确定）；TS 附近 0.04 Å 永远负例。这样才能避免把「靠近 TS」误标成「到终点」。

τ_end 的校准

在 inner-val 上选一个阈值，使 precision 达到 0.9，然后冻结。precision 高 = 说「到了」时更可信；但 recall 可能低。s29 的 τ = 0.219 太低，导致在 dev 上过度停——这是校准 / 泛化问题，不是训练崩溃。

怎么读

AUPRC 的基线不是 0.5，而是 prevalence ≈ 0.175；0.244 是比随机高约 40%，但 AUROC 0.60 只是中等信号。不要把它读成「准确率 24%」。

§05

代价：联合监督的 Move 账

这一节在问什么：多任务学习有没有「负迁移」——学 process 会不会把 MOVE 挤坏？代价多大？还值不值？

图 8 把联合监督的代价单独拿出来。以 RMSE/zero 均值计，B vs A +1.81%，C vs B +0.14%，C vs A +1.95%。代价几乎全部由 rank/q 项承担；endpoint 的增量在噪声内。换个方向看，C 的 sign（0.873）不低于 A（0.859），dead-zone（0.050）低于 A（0.059）——这不是单向的伤害。

物理意义

共享主干像一条高速公路，MOVE 和 PROCESS 的梯度都要走这条路。辅助任务太强，会挤占 MOVE 的车道；guard 就是测「MOVE 被挤了多少」。C vs A 的 +1.95% 是代价，但相对 R3 基线仍是 −12.0% ~ −10.3% 的改善，所以是「轻微负迁移」，不是失败。

把基线放回来：三臂相对 R3 zero-shot 仍是 −12.0% 到 −10.3%。20k 的数据收益大于联合监督的代价；但这是 dev 上的描述性结果，3 个 seed、单一 init，不做显著性声明。

§06

成本与稳定性

这一节在问什么：训练花了多少？为什么不同 run 的时间不能直接比？中断有没有破坏结果？

21 个 run 合计 27,576 GPU 秒 ≈ 7.66 GPU 小时：2k 1,829 s、5k 13,048 s、20k 12,699 s。20k 单 run 519–2,008 s；A 臂更慢（1,248–2,008 s），因为早期代码路径；C_s17 的 519 s 是断点续跑段（12,500→15,400 + 终评），首段成本未计入账本。按 S3 报告的估算，S3 实际量级约 14,000–14,200 s（≈3.9 GPU-h）。

成本数字不能当臂间效率比较：5k 的 9 个 run 跨了多次 I/O 与缓存优化，单 update 从 0.845 s 降到 0.088 s；5k 的 A_s17 3,583 s 与 B/C 的约 715 s 主要差在代码版本，不是臂。

怎么读

GPU 秒是墙钟时间，不是纯计算时间；时间差首先反映代码版本，其次才是算法差异。中断的 run 不删除：标记 interrupted、断点续跑、账本保留。

稳定性：0 NaN、0 scientific_failure、9/9 checkpoint sha 三方一致；S3 attempt 账目 15/15（9 个计划 + 6 次外部尝试：4 起外部事件——两次 host OOM 各消耗 2 次、一次外部终止、一次主机重启）。中断 run 都被 reconcile 为 interrupted 后断点续跑，没有删除或改写。

§07

训练之后：闭环压力测试（独立门）

这一节在问什么：训练好的模型，真的能从一帧开始一步步走到产物吗？为什么离线指标好，闭环却不一定行？

闭环是另一个门，不是训练指标。864 个纯几何 episode（24 条 dev 曲线 × 双向 × 3 臂 × 3 seed × 双预算），无物理调用。0.10 Å 端点到达率 A 1.4%、B/C 0%；0.30 Å 到达率 A 16.7%、B 6.9–7.6%、C 4.9–5.6%（两口径）；多数 episode 有碰撞。C 的在线停在 s29 上 96 次里停了 82 次（s17/s43 只停 10/6 次）。离线指标变好，不等于闭环能走通。

物理意义

rollout（闭环逐步走）：从 dev 的一帧出发，模型每步输出位移，应用后重新编码，再走下一步；信任域（trust region）每步最大 0.20 Å。0.10 Å 是很紧的窗口（大约是一个小键振动的量级）；模型是纯几何，没有能量 / 物理校正，误差会累积。所以闭环到达率低不等于训练失败，但说明还不能部署。

A.2容易误读的地方

  1. AUPRC ≠ 准确率：AUPRC 不是 accuracy；正例少时，随机基线是 prevalence。0.244 要跟 0.175 比（比随机高约 40%），不是「24 分」。
  2. guard 负值 = 改善：guard 是「退化百分比」，不是「提升百分比」；−12% 表示比 R3 zero-shot 好 12%。
  3. 总 loss 不可跨臂比较：三臂目标函数不同；跨臂只看下游指标（RMSE/zero、ordering、AUPRC、guard）。
  4. 2k 不是规模点：100 updates / 1 seed，且 B/C 全在冻结段；只证明管线跑通。
  5. seed 不是 p 值：3 个 seed 用来看稳定性；本报告明确不做显著性声明。

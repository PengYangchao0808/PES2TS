## 1. 当前定位与不变边界

PES2TS 是化学约束、真实物理闭环、成本敏感的 TS 搜索决策工作流。PES-N 是共享的 reactive-state decision kernel；PES-R 评价 STOP，PES-G 比较 STOP/MOVE/FALLBACK；Classic 是基线和经过验收的 backup。用户入口可以分别发布，学习内核与输出语义统一，不再要求独立训练两个模型。

ReactionEditGraph 定义目标事件与允许动作；PES-N 提供预测估计，控制器据此显式选择下一步计算；真实 QC 给出响应；OptTS/Freq/双向 IRC/端点身份给出科学真值。所有生产 QC 在 PES2TS 内仍唯一经 ACP，RPH 可消费候选并参与验证展示。模型不定义 TS、不替代 PES、梯度或鞍点优化器。

算法、数学定义、接口草案和十五项原则的工程映射以 [PES-N 未来开发计划](PES2TS_PES-N未来开发计划_v2_20261005.md)为实施细化；阶段边界以阶段定义为准；规范冲突以宪法为准。报告保留历史证据，不能由新计划追认能力。

| 阶段 | 交付重点 | 放行证据 |
|---|---|---|

| G1 | 端点图、事件、原子角色、坐标与合法动作编译 | 边界合同、24 条复核、独立来源及新模板验收 |

| G3.P / G3-P1 | 合格 IRC → 教师标签/基线 → 共享编码器 → 研究冻结 | 数据/分裂/坐标/隔离访问门；可与 G2 并行，研究头不能当真实价值 |
| G3.0 | 1000 个冻结输入漏斗；多来源 STOP 标注子集 | 失败/拒绝/删失不丢失；帧数和真实标签数分列 |
| G3.1 | 单点 p_seed、完整精修成本、Q_STOP 和校准 | 同池同预算严格选点、跨来源测试、资源计量 |
| G3.2 | 上下文增强、模仿与有界 Classic 残差 | 单点可用；合法残差候选；离线接入证据，未自动成为默认 |
| G4.0 | 相容转移上的保守离线 Q | 动作支持、离线偏差、Classic/BC 对照及风险校准 |
| G4.1 | 冻结模型的真实 QC 闭环，train 内困难状态采集 | 每步反馈、全量计费、Shield/回退；新模型离线更新后再冻结 |
| G4.2 | 跨生成器及整反应族/交叉留出；外部宿主 | 成功率门下系统成本收益、拒答与部署/回滚证据 |

G0 既有底座完成；G1 边界和 G2 真实闭环仍按原证据推进；G3/G4 未因文档改版而完成。G2.T 是小批测试，不新增主干阶段。科学里程碑 M0–M5 的定义只引用宪法 §10.2，不保留另一套 M-A–M-E 当前门。

G3.P 不依赖 G2 调教/科学出口，也不阻塞正式 STOP 线；编码器可在 G3.1 用从零/冻结/微调对照交接。G3.0 的正式规模化仍经 G2 门，G3.1 真实标签和 G3.2/G4 接入门继续按阶段定义。本期实施和版本目标见 [G3-P1](PES2TS_G3_P1_IRC教师预训练与模型版本计划_v1_20261006.md)。

轻量G4研究原型可与正在实施的G3-P1及人工复核并行，入口以宪法P5/§6.5和[轻量计划](PES2TS_轻量控制与RL衔接计划_v1_20261007.md)为准。首版改有限步长/提交时机，共用原生执行与质量检查；研究代理能力单独声明，以上正式阶段表及默认门保持。

## 3. 现有工作流如何承接

- **C 清理**：保留实验层归档、重复逻辑收口、旧接口废弃登记、标定台账和文档一致性任务。先保存可回放基线；不为“工作区干净”删除未审阅工作。代码收口另行执行。
- **R 研究**：旧BFGS与AB3原生对照已留档；近期固定原生G2，在同执行器上先比较规则/BC/一个小离散Q的有限步长与候选提交。模型升级不掩盖QC配方/预算变化；IRC驻定性、曲率、相位/驱动重编译按明确失败机制与收益后置。
- **X 执行**：继续 [ACP 执行统一方案](PES2TS_ACP执行统一与旧代码清理方案_20261003.md) 的 X1′–X5′、请求身份、RecipeEquivalence/ReplayParity、真实能力收据和展示接缝。保留不可变旧产物，不原地迁移约 19.1 万条历史轨迹，不复活本地引擎路径。

G1 六项补齐继续按 [边界审计](PES2TS_G1_G2边界审计与补齐任务_20261003.md) 执行。G2-AB1/AB2 和战役的已实施记录保留；新原生优化是增量验收，不重写旧战役结果。旧 R2 本地校正器研发不再是未来生产优化器的默认主线；作为历史数值对照保留。

## 4. 发布单元（以下名称是目标发布身份）

| 发布单元 | 内容与边界 | 发布门 |
|---|---|---|
| pes2ts-data | 白名单输入、图任务、状态来源、分裂清单 | 哈希/来源/拒绝/隔离完整；不能把辅助映射洗成 truth-free |
| pes2ts-classic | 规则控制、Shield、原生 QC 接口和基线配方 | G2 真实闭环；能力不足诚实拒绝 |
| pesn-core | pesn内api/contracts/features/models/inference/bundle；只接当前观测，白名单运行资产 | G3.P 可先发布研究 encoder/教师头；G3.1 起发布真实 STOP 能力；runtime无offline/源数据/QC依赖，模型卡/校准/延迟/兼容另验收 |
| pesn-training | 同一预测器产品的pesn/offline：数据/分裂/标签/训练/模型评测/导出工具 | scope/审计/可复现/恢复/冻结评测；开发依赖单独声明，不能进入runtime分发 |
| pes2ts-host | 内核接入、导航/批量 STOP 排序、ACP/RPH 适配 | 相应 G 阶段证据；宿主执行不进入内核 |
| pes2ts-eval | 系统严格标签、协议条件化结局、全量成本与全流程独立评测 | 不回流当前生成；train 导出可审计；holdout 冻结；本期教师/模型指标归pesn/offline/evaluation |
| pes2ts-acp-bridge | 正式请求/产物、任务身份、真实冒烟与展示 | 每项能力单独收据，unknown 不等于可用 |

PES-R 可继续作为 `rank` 入口，PES-G 可继续作为生成/导航入口；两者依赖同一版本化 PES-N bundle。没有 MOVE-Q 权重时只能声明 STOP 能力。轻量内核可独立部署的目标，不代表当前已创建独立包或已有外部宿主接通。

G3-P1所有新增业务代码统一归`pes2ts_core/pesn/`，不把教师构建放在通用evaluation，也不把训练器放进控制器。runtime只能依赖本产品在线集及许可纯工具；既有G0/G1/坐标编译通过offline适配。配置、测试、可选依赖声明与B2窄真值桥登记是配套范围，现有产品不搬迁。文件清单、API、B0–B7和产品缺口归属见[模块划分](../design/PES2TS_预测器产品与G3代码模块划分_v1_20261007.md)。

G3.P 包没有真实 STOP 权重时仅声明教师研究能力，不能称上述 STOP 已可用。研究 bundle 发布和宿主控制默认切换是不同门；未开放头统一 unsupported，模型文件出现不自动触发生产接入。

### 4.1 软件、模型及数据版本

软件包版本沿用 `pes2ts_core/version.py` 的当前 `0.1.0`；本次只是规划，不 bump 软件。模型目标采用 `pesn-irc-v0.1.0`（G3.P）→`pesn-stop-v0.2.0`（G3.1）→`pesn-residual-v0.3.0`（G3.2）→`pesn-offlineq-v0.4.0`（G4.0）→`pesn-closedloop-v0.5.0`（G4.1）→`pesn-core-v1.0.0`（G4.2），各项待独立验收。

数据发布、schema、FeatureSpec/LabelSpec/split/protocol、run_id 和权重 hash 分别记录，不用软件版本代表模型能力。候选 `-rc.N` 与冻结研究包分开，不覆盖旧包；预训练/微调新来源或任务语义改变时发布新模型/数据版本。完整规则以 [G3-P1 §2](PES2TS_G3_P1_IRC教师预训练与模型版本计划_v1_20261006.md)和[合同草案](../contracts/PES2TS_PESN_IRC教师数据与模型包合同_v1.md)为细化。

按[ADR-0011](../design/decisions/ADR-0011-三模块产品架构与统一可视化.md)，用户面对一个PES2TS工作台，运行职责整合为拓扑约束、控制器和ACP计算器接缝，横向展示输入、检查、运行和结果。上表是工程发布/复用单元，预测器在线与离线分发属于同一产品。优先复用已有G1/G2实现及ACP Workbench；完整目标、部分事件和坐标设想分别通过能力与评价资格门。组件映射、UI责任及Classic→STOP→价值导航的分期见[产品架构设计](../design/PES2TS_三模块与可视化产品架构_v1_20261005.md)，具体代码、schema和UI另验收。

## 5. 合同与兼容迁移

保留 `ReactionCase → GenerationPlanV2 → TrajectoryRecord → PathBundle → SeedProposal → ValidationResult` 旧链可读；不覆盖旧 schema 或已冻结产物。新适配层版本化引入：

| 新合同族 | 主要语义 |
|---|---|
| ChemicalControlSpec | 目标图/事件、原子及坐标角色、允许 MOVE 与辅助约束规则 |
| ReactiveState / PESNTrajectory | 完整 X/E/g/q、方法/电子态/单位、质量与来源；缺失显式 |
| Action / Transition | 命令 Δq、父子状态、约束优化环境、接受/拒绝、追加费用 |
| SeedProtocol / SeedOutcome | preparation/OptTS/Freq/IRC/身份协议、预算、七态标签与完整费用 |
| DecisionEstimate / ShieldDecision / Trace | p/C/Q、适用域与不确定性、规则裁决及可回放选择 |
| PESNModelBundle | 特征/归一化、权重、头能力、协议、校准、训练来源与适用域 |
| IRC TeacherState/Label/Split/TrainingRun | 隔离教师样本及路径标签、分裂/污染/run；不改变生产状态或动作转移资格 |
| PESNInput / TeacherPrediction | 预测器只读当前观测及研究输出；逐头availability、mask/reason、输入/模型hash；不含执行选择 |

具体字段以新计划 §8 与后续正式 schema 为准；本表是未来合同登记，不是已实现类。单点可评价不免除目标图、方法、原子序、电荷/自旋和输入资格要求。MD/NEB/Opt 等来源优先进入 STOP 数据，只有动作和转移机制相容才进入共同 MOVE-Q。

兼容命令语义仍可保留 `plan / generate / rank / validate / report`；搜索模式在 controller 内做 STOP 选择，无需再加一个独立 rank 模型；外部轨迹通过 rank adapter 评价同一 STOP。能力/schema/model/protocol/split 和物理产物均带版本及哈希，重跑写新记录。

## 6. 评测、发布与回滚

主指标是总 QC 费用/严格目标成功数，同时约束成功率与覆盖。费用包括失败、probe、回退、准备和整条验证；训练/数据费用及摊销单列。零成功时比值未定义；默认每个目标反应至多计一次成功，不用重复收敛扩充分母。

同池排序固定 G/协议/预算；导航比较全流程。必须保留规则峰、事件峰、Classic、仅 STOP、残差以及完整 Q 策略对照，并用共享/独立模型消融检查负迁移。整反应族与跨生成器分别留出及交叉测试；同一反应换来源不算化学泛化。

Demo24 已有真值开发暴露，整集作开发回归并保留历史 16 train/8 valid 标记及污染记录；45 个 unassigned 不流入训练或独立测试。新独立队列承担泛化结论。未验证不是负例；基础设施故障、预算删失与验证失败分别建模和报告。

发布前冻结成功率非劣界限、费用改善门、支持域、预算及校准；在 train 内选择，不能查看 holdout 后修门。首版优先约 10^5–10^6 参数，决策开销/QC 工作流目标 <1%；同时披露全部 ensemble、特征和 Shield 成本，达不到目标如实报告。

每个模型/协议新版本单独验收。性能或校准不满足门时保持 Classic 默认；保留旧配方、旧 bundle 和回放证据。fallback 仍通过 Shield/ACP/预算门。未知能力不进入候选动作集合。

## 0. 摘要与核心结论

**一句话**：本地不是"缺数据"，而是**五类资产 + 五层划分 + 三套口径**同时存在——DFT 原始/隔离真值（Zenodo 六件）、WSL 50k/20k 建库表、新同步的 xTB 单点标签集、派生中间件与 70 GiB 运行产物。本方案把它们编成一本**可核对、可冻结、可执行**的数据账本：先统一口径与通道登记，再建 xTB 索引与帧级对齐视图，最后用 V5.5 契约把"数据地基"锁死，供 V5.6-B 的 G1 对照与 V6 预热使用。

### 0.2 五条结论

1. **资产账本已具备冻结条件**：五类资产均有计数、哈希与产出处；缺口是"一本账"（本方案 §1 与 V5.5 的 `data_asset_registry.json`）。
2. **xTB 数据集可用的口径只有一个**：**2,877,830 行 = 实际单点计算数**；2,912,712 是名义上限（24 × 121,363）；**34,486,722 是 `Σ n_points` 记账值，不是单点数**（见 §5.1 裁决）。
3. **落位唯一**：xTB 只进 **V5.6-B / V5.7-B 的 G1 cached-QC** 与 **V6.0 之后的 SFT 预热**；不进 V5.5 主表、不进任何冻结测试集、不进 V6 在线回路。
4. **最大技术缺口是 join**：xTB 行只有 `reaction_id + direction + frame_index + coords_sha256`，V5 `idx_v2` 用 `curve_id + node_index`，两者**没有现成 crosswalk**；必须先产出经哈希冻结的 `frame_key ↔ (curve_id, node_index)` 映射（§3）。
5. **最大治理缺口是 dev 覆盖**：xTB 只覆盖 `train_fit`，dev 589 无 xTB 标签 → V5.6-B 的 G1 对照只能在 pool 内做；族外推（family_holdout / 父 valid/test）的评测协议仍未冻结（划分标准 §"最大口径缺口"），本方案不解除该缺口。

### 2.3 能量/梯度通道登记（本方案新增的强制表）

> 依据 `docs/contracts/PES2TS_contracts_v1.md:44`、`docs/contracts/PES2TS_ACP字段映射_v1.md:64`：不同来源的能量/梯度是**独立通道**，禁止混合或跨方法绝对相减。

| 通道 ID | 数据 | 单位 | 来源 | 允许用途 | 禁止 |
|---|---|---|---|---|---|
| `dft_irc_node_energy` | DFT IRC 逐帧能量 | eV | `curve_node_energies.npy` / `dft_energy_ev` | 相对能差 `ΔΔE`（同 route） | 与 xTB 绝对能相减 |
| `dft_irc_node_force` | DFT 逐帧力 | eV/Å | `dft_force_ev_per_angstrom` | 经 `dE/dx = −F/51.4221` 转 Ha/Bohr 后算 `Δg` | 直接与 Ha/Bohr 相加 |
| `xtb_singlepoint_eg` | GFN2-xTB 固定几何 E/g | Ha、Ha/Bohr | 本数据集 `run/results` | G1 cached-QC 特征；Δg/ΔΔE 配对 | 在线推理；当 Move 教师；与 DFT 绝对能相减 |
| `g2_path_scan_energy` | G2 PATH 扫描能（`xtbpath.xyz` 注释） | Ha（相对） | G2/ACP | 路径内单调性/质量判定 | 与本数据集逐帧单点混算 |
| `g2_refined_singlepoint` | ACP 受约束结构上的精化单点能 | Ha | G2/ACP `E_physical` | 计费与路径质量 | 证明结构驻定 |

### 2.4 幂等键与 join 键（当前最大缺口）

| 键 | 所属 | 组成 | 用途 | 现状 |
|---|---|---|---|---|
| `frame_key` | xTB 数据集 | `sha256(canonical{round10(coords), atomic_numbers, method, engine, engine_version, engine_binary_sha256, charge, mult, operation, solvent, compute_options})` | 单点幂等/去重 | ✅ 数据内自洽（1 个反应撞键已排除） |
| `curve_id, node_index` | `idx_v2` | 50k 建库索引（`curve_idx → node_index`） | V5 训练稠密索引 | ✅ 可用（memmap） |
| **crosswalk** | 本方案新增 | `frame_key ↔ (reaction_id, direction, frame_index) ↔ (curve_id, node_index)` | G1 视图的唯一桥 | ❌ **不存在**，必须先建（§3） |

**风险**：两者**不能假定等价**——xTB 的 `frame_index` 是 DFT 帧序号，`idx_v2` 的 `node_index` 是 `node_order` 规范化后的节点序号；直接混用会把能量贴到错帧上（静默错配，最危险的一类 bug）。

### 2.5 truth-access 审计链

- 单一访问器 `pes2ts_core/g0/truth/truth_reader.py`；每次成功读取追加 `data/manifests/truth_access_log.jsonl`。
- 静态守卫 `pes2ts_core/utils/truth_guard.py` 扫描 `pes2ts_core/`、`bin/`；allowlist 仅 4 个模块 + `cli.py` 的 `truth_index` handler。
- 新 xTB 数据集的产出**本身就是 truth_assisted**：其 manifest 记录 `truth_access_caller=xtb_labels.manifest:…`、`unique_ids=121,363`、`records=242,726`、`excluded_ids_read=0`；数据侧引用该包时**不得**再消耗 truth_access 额度（包已冻结），但**必须在输出 manifest 中继承 `truth_assisted/truth_manifest_sha256`**。
- 残余风险：静态 AST 抓不到运行时拼接路径；文件系统权限不阻止直接读；带外读取不可观测 → 报告必须披露。

## 3. xTB 单点数据集接入工程（本方案核心）

### 3.1 接入前四件事（依赖排序，全部可执行）

| # | 事项 | 做法 | 交付物 | 验收 |
|---|---|---|---|---|
| 1 | **帧级对齐** | 以 `frame_key` + `(reaction_id, direction, frame_index)` 与 `idx_v2` 逐帧 join；`node_order` 反查 canonical 序号；覆盖关系"1,363 反应 ⊃ 实得 120,222"不可假定全池 | `frames.parquet` + `xtb_g1_view_manifest.json`（含 `xtb_index_sha256`、`idx_v2_data_manifest_sha256`、`split_manifest_sha256`、`n_joined/n_missing/n_excluded`） | 抽样 1k 帧人工核对 3 例；`n_joined + n_missing + n_excluded = 2,877,830` |
| 2 | **排除清单落地** | 397 `scf_not_converged` + 34,882 缺口桶写成可执行 filter（`short_branch / dft_energy_unavailable / unsupported_layout / duplicate_frame_key`） | `excluded.jsonl`（frame_key, reason）+ manifest 计数 | 无"缺失=0 能量"；计数与 `manifest/index.json` 一致 |
| 3 | **单位/符号归一化** | DFT 侧只有力（eV/Å）：`dE/dx[Ha/Bohr] = −F[eV/Å] / 51.4221`；能量不做任何跨方法换算 | `normalization.json`（含常数与 sha） | 单元测试固定 3 个已知数值 |

### 3.2 三层架构（不要把 24 GB / ≈22 GiB 原始 JSONL 直接塞进训练循环）

```text
[1] 包级 reader/index      pes2ts_v5/data/xtb_singlepoints.py
        └─ 只认 package 目录：index/audit/shard/results；流式 + sha256；不依赖 torch
[2] 帧级对齐视图            scripts/v55/build_xtb_g1_view.py（计划中已命名）
        └─ frame_key ↔ (curve_id, node_index) 冻结映射 + G1 特征表（Parquet/npz）
[3] 训练/评估消费者         pes2ts_v5/data/idx_v2.py（G1 分支）；V6：pes2ts_core/pesn/offline/data/xtb_singlepoints.py
        └─ 只读 [2] 的 Parquet，不碰 24 GB 原始 JSONL
```

理由：24 GB（≈22 GiB）JSONL 不适合每 epoch 随机读；`frame_key` 稳定但不适合训练索引；把"包读取"与"帧对齐"分开才能分别测试、分别冻结哈希。

### 3.5 与 V5 G1 的具体改点

`pes2ts_v5/data/idx_v2.py` 的 `build_sequence()` 当前：`energy` 来自 `curve_node_energies`，`grad_norm = np.zeros_like(q)`；`build_frame_features(..., input_mode)` 在 G1 下把 `has_qc` 设为**全 1 数组**。两处必须改：

1. `has_qc` → **per-frame 数组** `has_xtb[t]`（0/1），否则无标签帧被当成有标签；
2. `grad_norm` → 注入 `xtb_grad_norm[t]`，按 `curve_id + node_index` 从视图 `frames.parquet` 查表；
3. 新增可选参数 `IdxV2Dataset(..., xtb_view: str | Path | None = None)`；`None` 时行为与改动前**逐位一致**（回归门）。

### 4.2 V5.6-B G1 对照的数据供给

- 输入：`frames.parquet`（`curve_id, direction, node_index, xtb_frame_key, e_hartree, g_norm, has_xtb, mask_reason`）+ `normalization.json`。
- 对账：`n_xtb_labeled / n_frames` 必须等于 view manifest；G1 run 的 registry 记录 view sha。
- 覆盖限制：只覆盖 pool 内 `train_fit` 曲线；**dev 589 无 xTB 标签** → G1 对照只能在 pool 内训练/评估，**不得**声称在 dev 上做了 G1 对照。若需要 dev 版，须由作者补算（待裁决 H-2）。

### 4.3 V5.7-B 特征消融

可做的消融：G0 vs G1（有无 xTB E/g 通道）、能量通道 vs 梯度范数通道、`has_xtb` mask 策略（稀疏 vs 插值）。**不做**：把 `g_xTB` 当 Move 教师（跨方法方向一致性未证明，小样本 cos 中位约 −0.19）；把绝对能量当标签。

### 4.4 V6 SFT 预热（后置）

- 适配器 `pes2ts_core/pesn/offline/data/xtb_singlepoints.py`：`XtbFrame → ObservationRef`，梯度 `Ha/Bohr ÷ BOHR_ANGSTROM` 转 Ha/Å；
- 关键原子投影**不在此处做**（来自 G1 / ReactionIntent）；V6 只接收 `(N,3)` E/g 与 key mask；
- **raw vs pre_relaxed**：本数据集是"raw DFT 帧单点"，其 `g_nonkey` 分布与在线 `$fix`+relax 后的状态不匹配（该论证目前只存在于已 SUPERSEDED 的 v1.2 §4.2），因此 raw 只宜作**消融**；若 V6 正式使用，需另立 ADR 把该论证迁入现行 V6 方案，并评估 `pre_relaxed_v1` 的二次计算成本。
- `C_valid` 不得由本数据集计算（需真实闭环计费）。

### 4.5 红线清单

1. 不得把 xTB 单点当"验证过的 TS"或"优化后几何"。
2. 不得用 xTB 梯度替代 DFT 力/当 Move 教师。
3. 不得做 `E_xTB − E_DFT` 的绝对跨方法相减；只允许同几何 `Δg`、同 route `ΔΔE`。
4. 不得用于 train_dev / confirm / family_holdout / parent valid / parent test 的评估调参。
5. 不得进入在线推理/生产决策/对外能力声明。
6. 不得因"已建库"把非 pool 曲线投入训练（训练入口只认 L3 `subsets.pool`）。

## 5. 矛盾裁决与口径统一

### 5.1 数据集"单点数"三口径裁决（M5）

## 8. 风险与红线

### 8.1 技术风险

| 风险 | 表现 | 对策 |
|---|---|---|
| 帧错配 | `frame_index` 当 `node_index` 用，能量贴错帧 | D1 强制 crosswalk + 抽样人工核对 + `coords_sha256` 双校验 |
| 静默 0 能量 | 缺失帧被当 0 | `has_xtb` per-frame + `mask_reason` + excluded ledger；禁止 `np.zeros` 填充 |
| 24 GB JSONL 随机读 | 训练 I/O 抖动 | 三层架构；训练只读 Parquet 视图 |
| 显示/内存 | 8 GB GPU 共享桌面、宿主 commit 紧张 | 小批量+梯度累积；`--mem 16G`；单进程 |
| 单位混淆 | DFT 力 eV/Å 与 xTB Ha/Bohr 混用 | §2.3 通道表 + 单测固定数值 |

### 8.2 科研风险

| 风险 | 对策 |
|---|---|
| 把离线 xTB 当在线真实反馈 | 大纲 §2.5 落位矩阵；`offline_only` 编码进 loader |
| 把代理当真实标签（Trust） | V6 才建真实接受率；离线只用代理并声明 |
| xTB 梯度≠DFT 力（cos 中位 −0.19） | 只做 G1 特征/残差，不做 Move 教师 |
| raw 帧分布不匹配（`g_nonkey` 大） | raw 只作消融；正式 V6 用 `pre_relaxed_v1`（待 H3 裁决） |
| 族外推无协议 | M7：ADR-0037 前不声称 |

### 8.3 治理风险

| 风险 | 对策 |
|---|---|
| 触碰 confirm / 启封测试集 | `sealed_never_read` 机器可读；启封需审批记录 |
| truth 带外读取 | 静态守卫 + 日志披露残余风险 |
| `outputs` 膨胀 | §7.1 清理策略 + 每步登记 |
| 数据版本漂移 | §2.6 版本坐标系；registry 强制 |

**红线（引用 AGENT/宪法 R1–R6）**：不改 G0–G4 能力边界；不做未授权真值访问；不把 offline 结果当在线能力；不用测试集调参；不伪造指标；不把代理当真实。

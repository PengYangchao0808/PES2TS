## 0. 摘要与核心决策

**一句话**：把原来混在 V5 里的"网络架构研究、物理优化验证、真实量子化学闭环"三件事严格拆开——**V5 只做纯离线架构 Benchmark，V6 做真实 xTB 闭环与监督校准，V7 才做强化学习与成本优化**；三个阶段独立验收，最终重新组合为完整的 PES2TS 搜索算法。

| 版本 | 定位 | 学习目标 | 交付物 |
|---|---|---|---|
| **V5 · Architecture** | 纯离线模型架构 Benchmark | 如何预测反应路径的下一步动作 | 1–2 个经过严格测试的轻量网络骨架 |
| **V6 · Calibration** | 真实 xTB 闭环与监督纠偏 | 如何根据真实计算反馈稳定执行动作 | 稳定运行、经过物理验证的 SFT 控制器 |
| **V7 · Optimization** | 强化学习与自适应策略优化 | 如何以最低量化计算成本找到有效 TS | 面向实际反应的低成本 TS 搜索策略 |

**最重要的变化**：原方案中的 **V5.7（Physics-Constrained Optimization）与 V5.8（DFT Validation）全部迁移至 V6**。取消独立 H1 物理验证，不是否认低维反应坐标假设，而是把它作为现阶段的**建模前提**：V5 只检验网络能否学习该表示下的路径决策，V6 验证固定坐标的实际可执行性，V7 再系统研究坐标维度及其动态调整。

**最终路线**：V5 完成 `MLP / GRU / CfC / Selective SSM` 轻量化 Benchmark（Transformer 作重要对照，Neural ODE / LTC / Mamba 留扩展）；**绝不在 V5 追求量化闭环成功率**。V6 以 Classic Controller 为安全基线，用真实闭环数据训练可靠监督控制器并建立端到端效率指标。V7 逐步放开策略自由度：固定坐标下的步长/停止/回退 → 自适应反应坐标与联合策略。

## 1. 三个版本的研究边界（严格解耦）

**原方案最大的问题不是模型选择不合理，而是把神经网络架构研究、物理优化算法验证和真实量子化学闭环混在了 V5 中**，导致实验目标不断扩大，无法判断究竟是哪一项改动贡献了性能提升。新版按下列边界执行：

| 研究内容 | V5 | V6 | V7 |
|---|---|---|---|
| IRC 监督学习 | **核心** | 微调 | 初始化 |
| MLP / GRU / CfC / SSM 比较 | **核心** | 仅少量复核 | 冻结 |
| 不规则采样与离线 Rollout | **核心** | 回归测试 | 回归测试 |
| 实时 xTB 能量/梯度 | 不使用 | **核心** | **核心** |
| 正交松弛、信赖域与回退 | 不验证 | **实现与校准** | 策略优化 |
| DAgger 式纠偏 | 不进行 | **核心** | 可作为辅助 |
| 动态反应坐标选择 | 固定表示 | 固定规则 | **核心探索** |
| RL / Bellman 优化 | 不进行 | 不进行 | **核心** |
| 有效 TS 计算成本 | 不作为验收 | 建立基线 | **核心优化目标** |

> **纪律**：V5 的表现不受真实量化计算限制；V6 不再同时面对模型结构未稳定的问题。三个阶段的科研验收严格串行，工程基础设施可并行（见 §6）。

## 2. V5：纯离线深度学习架构 Benchmark

### 2.1 核心科学问题

V5 不再回答"能否找到真实 TS"，而是限定为：

> **对于反应图约束下的低维路径决策，历史状态、连续路径间隔和不同网络记忆机制，究竟能够带来多少可泛化的预测收益？**

用三个独立假设替代原方案 H1/H2/H3：

| 科学假设 | 关键对照 | 期望回答 |
|---|---|---|
| **H5-A：历史依赖** | MLP vs GRU/CfC/SSM | 反应路径预测是否真正需要记忆？ |
| **H5-B：连续路径参数化** | GRU+Δs vs CfC+Δs | 连续状态更新是否提供独立增益？ |
| **H5-C：结构信息的价值** | 低维描述符 vs StarEGNN v2 | 完整 3D 图编码是否值得其额外开销？ |

**注意**：V5 不需要证明 CfC 最好，而是需要**排除网络架构选择中的主观性**。

### 2.2 V5.5 — Dataset Foundation：重构与冻结轨迹数据

这是优先级最高的工作。保留四层数据结构：

| 层 | 内容 |
|---|---|
| **Reaction** | 反应图、原子映射、反应家族、成断键 |
| **Trajectory** | IRC 方向、路径参数、轨迹来源 |
| **Frame** | XYZ、能量、梯度、反应坐标 |
| **Decision** | 教师位移、方向、步长、阶段标签 |

**四项必须执行的数据工程任务**：

**A. 统一反应与轨迹索引。** 对每条路径保存 `reaction_id`、`family_id`、`trajectory_id`、原子映射和原始数据来源。同一反应不同构象、正反 IRC 分支、重采样和扰动版本必须绑定到同一个数据划分。

**B. 固定数据集划分。** 建立三套主要评估：**Reaction-ID**（同家族新反应）、**Scaffold-OOD**、**Family-OOD**；另设不规则采样及扰动鲁棒性压力测试。已有 **49 簇 OOF** 结果保留作历史比较，但需重新检查簇间是否真正独立。

**C. 统一序列方向与路径参数。** 对 TS 两侧 IRC 分支明确指定搜索方向；路径参数用累计几何弧长或质量加权弧长。网络在时刻 `t` 只能看到过去与当前可观测信息，**不能使用"剩余到 TS 的真实距离"作为推理输入**。

**D. 数据来源严格分层。** 现有 IRC 是主要监督数据。Transition1x 可作扩展来源，但其路径主要来自 NEB 计算，**不能未经处理就全部当作 IRC 教师轨迹**；它含约 10,000 个反应与 960 万个 DFT 构型，应统一采样方法、电子结构方法与监督标签后再使用。V5 可以使用已保存的 QC 能量或梯度，但**不得为训练/测试新增实时 xTB/DFT 调用**。

### 2.3 V5.6 — Model Architecture Arena：统一模型架构

所有模型组织为五个可替换单元：

| 单元 | 选项 |
|---|---|
| **Reaction Encoder** | Low-dimensional Descriptors / StarEGNN v2 |
| **Process / Memory Core** | MLP · GRU · CfC · SSM · Transformer |
| **Move Head** | 方向 / 步长 |
| **Process Head** | 路径阶段 |
| **Trust Head** | 离线风险代理 |

**第一轮固定** Encoder、Move/Process/Trust Heads 和训练数据，**只替换中间记忆模块**；Encoder 对比留到第二轮，不得同时混入主架构排序。

**第一轮模型矩阵（M0–M5）**：

| 编号 | 网络 | 主要意义 | 优先级 |
|---|---|---|---|
| M0 | Stateless MLP | 最简单单帧基线 | 必做 |
| M1 | Window-MLP | 固定历史窗口基线 | 必做 |
| M2 | Time-aware GRU | 离散记忆及变间隔 | 必做 |
| M3 | CfC | 连续间隔状态更新 | 重点 |
| M4 | Diagonal Selective SSM | 轻量选择性记忆 | 重点 |
| M5 | Tiny Causal Transformer | 注意力序列基线 | 必做 |

第二轮按结果决定是否加入 **LTC、Latent Neural ODE、完整 Tiny Mamba**。两点公平性要求：

1. CfC 的优势来自可显式使用**不规则观测间隔**，不意味着它天然满足化学反应动力学；**GRU 必须获得同样的 Δs 信息**，才能公平检验连续架构的独立贡献。
2. 完整 Mamba 保留在扩展组，**独立验证 CPU 递推实现**，不宜把 GPU 专用扫描内核的吞吐率直接推断为 CPU 部署性能。

**实验预算：逐级淘汰，不直接铺开原 48 组训练**：

| 轮次 | 规模 | 说明 |
|---|---|---|
| 第一轮 | **18** = 6 架构 × 3 种子 | 所有模型约 **0.1M** Process Core 参数预算 |
| 第二轮 | **9** = Top-3 × 3 种子 | 前三名扩大到约 **0.5M** Process Core |
| 基础总计 | **27** 次独立训练 | 扩展组（LTC/Neural ODE/Mamba）视结果追加，不计入基础预算 |

同时报告**完整模型参数量**（Encoder 可能比 Process Core 更大）；每个架构记录实际训练成本、显存、CPU 单步延迟与模型依赖。

### 2.4 V5.7 — Offline Generalization：离线泛化与 Rollout

这是 V5 的**核心评估**（而非 xTB 闭环测试）。严格区分三类测试：

| 测试 | 做法 | 衡量 |
|---|---|---|
| **单步 Teacher-forcing** | 真实历史构型 + 已保存特征，预测参考下一步动作 | 局部拟合能力 |
| **历史扰动与不规则采样** | 轨迹稀疏化、非均匀采样、历史片段缺失、输入扰动（不改反应标签） | 隐藏状态与预测稳健性 |
| **纯几何 Open-loop Rollout** | 模型连续预测低维动作并映射到几何构型，**不调用量化软件** | 累计几何误差、关键反应坐标偏离、异常结构比例 |

**关键约束（防未来信息泄漏）**：模型生成新几何构型后，**不能继续把参考 IRC 下一帧的梯度当作该生成构型的真实梯度**。因此建议同时训练：

- **几何输入版本**：可做真正无外部反馈的几何 Rollout；
- **已有 QC 特征版本**：主要做监督回放与特征消融，直到 V6 才能做物理意义上的自主闭环。

**正式评估矩阵**：

| 评估维度 | 具体指标 | 要回答的问题 |
|---|---|---|
| 单步精度 | Move RMSE、方向余弦、步长误差 | 是否预测正确局部位移 |
| 阶段识别 | Macro-F1、PR-AUC | 是否识别路径阶段与 TS 附近区域 |
| 长程稳定 | 5/10/20/50 步累计误差 | 自回归误差是否快速放大 |
| 不规则采样 | 均匀、稀疏、随机间隔 | 连续状态建模是否更稳 |
| OOD 泛化 | Reaction / Scaffold / Family OOD | 能否迁移到未知反应 |
| 鲁棒性 | 扰动恢复、异常几何比例 | 是否容易脱离合理结构 |
| 轻量部署 | CPU P50/P95、内存、参数量 | 是否适合嵌入 ACP-CLI |

保留原有 **RMSE/zero 比值**与 **49 簇 OOF** 指标以维持历史可比性。多步 Rollout **按反应做配对比较与 Bootstrap 置信区间**，不得把同一轨迹的几千帧当作几千个独立测试样本。

### 2.5 V5.8 — Model Freeze：模型冻结与 V6 交付

V5 最终**不能凭单个指标选冠军**，采用三层筛选：

1. **准确性门槛**：Family-OOD、方向预测、多步 Rollout 是否足够可靠。
2. **稳定性门槛**：多随机种子下排名稳定；变步长采样无明显性能崩溃。
3. **成本门槛**：前两项相近时，优先 CPU 延迟更低、结构更简单、依赖更少的网络。

最终保留 **一个主模型 + 一个结构不同的对照模型**（例如 GRU 与 CfC、或 GRU 与 Selective SSM；具体组合由实验决定）。

**唯一硬性交付**不是"证明某架构最好"，而是一份**可复核的架构选择记录**：数据哈希、训练配置、所有随机种子、OOD 结果、模型权重、推理接口。

> **V5 到此结束。不得在 V5 报告中声称已验证真实 TS 成功率、物理收敛性或量化计算加速。**

## 3. V6：真实 xTB 闭环与监督微调

### 3.1 核心科学问题

> **在模型已学会离线 IRC 路径规律之后，如何利用真实量子化学反馈消除分布偏移，并将其转化为稳定的路径搜索控制器？**

V6 不再大规模比较架构，固定 V5 最优模型，重点研究：动作能否被安全执行？真实反馈如何纠正错误路径？Trust/Process 能否从离线代理标签转为真实操作标签？监督微调能否稳定优于纯规则控制器？

### 3.2 V6.0 — Quantum Environment：统一计算环境

```text
V5 Frozen Model
  输入几何/梯度/历史 → Move / Process / Trust
        │
Chemical Safety Layer
  坐标投影 · 信赖域 · 步长截断 · 几何有效性
        │
xTB / Constrained Relaxation
  真实结构松弛与能量、梯度计算
        │
Feedback Controller
  Accept / Reduce / Rollback / Refine / Fallback
        │
  新状态反馈给模型 → 下一步
```

模型只提出候选动作：

```text
a_t^ML = (Δq_t, p̂_t, m̂_t)
```

安全层负责投影：

```text
Δq_t^safe = Proj_{C_t}(Δq_t)
```

随后通过约束优化器，在尽量保持目标反应坐标的同时松弛其他自由度：

```text
R_{t+1} ≈ argmin_R E_xTB(R)   s.t.  q(R) = q_t + Δq_t^safe
```

该最小化是**局部、受约束**的：不保证唯一解，也不保证与目标 IRC 同一分支。因此必须检测优化失败、几何异常与反应通道偏离。**不能把能量上升自动认定为错误**——正常 TS 搜索本来就可能需要沿反应方向上坡。

### 3.3 V6.1 — Closed-loop Pilot：小规模闭环测试

先用 **20–30 个覆盖不同反应类型的开发反应**，比较四个控制器：

| 控制器 | 目的 |
|---|---|
| Classic 固定步长 | 最基本物理基线 |
| Classic 自适应步长与回退 | 检验规则安全层本身的价值 |
| V5 Frozen Model + 相同安全层 | 检验离线模型能否零微调迁移 |
| V5 Model + 安全层 + 监督纠偏 | 检验真实数据微调是否有效 |

本轮**不追求最高成功率**，而是完整记录闭环状态分布。每个动作保存：

`State → Proposed Action → Projected Action → xTB Call → Accepted State → Failure Reason → Next State`

并记录真实 QC 梯度调用、约束优化迭代、失败原因与累计预算。

### 3.4 V6.2 — Closed-loop SFT：建立真实反馈监督数据

这是 V6 最重要的机器学习任务。V5 的 IRC Teacher 主要提供参考运动方向：

```text
u_t* ≈ dq/ds
```

但它不能提供所有真实控制事件的正确标签。三个输出头必须区分监督来源：

| 输出头 | V5 监督 | V6 新增监督 |
|---|---|---|
| **Move** | IRC 方向、步长、Classic 残差 | 真实偏离状态下的专家纠偏动作 |
| **Process** | 路径阶段、近 TS 区域代理标签 | Continue / Reduce / Rollback / Refine 等真实操作结果 |
| **Trust** | 几何偏差、局部预测误差等代理风险 | 给定状态及动作的真实接受率、失败风险 |
| **Seed quality（可选新增）** | 不作为真实成功概率 | 固定 OptTS/IRC 协议下的目标 TS 成功概率 |

**必须避免的严重问题**：不能在 V5 中用理想 IRC 的"接近 TS"标签冒充真实 STOP 成功标签；V6 应区分"值得提交精修"与"实际精修成功"，两者可有不同 Head。

**残差学习与 Dataset Aggregation**：对已有 Classic 控制器：

```text
Δq_t^ML = Δq_t^Classic + δq_θ(S_t)
```

然后用真实闭环偏离状态做 Dataset Aggregation。DAgger 的核心是**收集当前策略实际访问的状态**，再由专家策略提供纠偏监督，而不是把模型失败结果直接当正确动作标签。PES2TS 中专家可以是经过验证的 Classic 回退、局部搜索恢复策略或额外生成的可靠参考动作。

**三轮迭代**：

1. **Round 0 — Frozen Policy**：不更新 V5 权重，收集真实分布偏移与失败样本。
2. **Round 1 — Correction SFT**：混合原始 IRC 数据与可靠闭环纠偏标签，更新 Move/Process/Trust。
3. **Round 2 — Aggregated SFT**：用更新后的模型再次执行真实闭环，补充新失败模式并复训，防止只适应第一轮偏差。

如第三轮仍明显分布漂移可继续迭代，但**不能无限微调到最终测试集**。

### 3.5 V6.3 — Physical Benchmark：真实物理验证

这是 V6 **唯一**能宣布实际物理性能的阶段。按开发集、验证集、最终锁定测试集组织；规模从几十个反应逐步扩大到约 **200 个反应级**独立测试任务（取决于计算资源）。

**主测试对照分两层**：

- **相同路径控制接口**：Classic Controller、V5 Frozen、V6 SFT；统一起始构型、反应坐标规则、量化方法与执行预算。
- **传统方法参照**：GSM、NEB、扫描及 TS 精修算法；按单端/双端输入与任务定义分组。Sella 等局部 TS 优化器应在相同初猜条件下比较，**不能混为完整反应路径搜索算法**。

**严格定义有效 TS**：

```text
∇E(R‡) ≈ 0
且 Hessian 恰有一个显著负曲率模式，并通过正确的反应模式与 IRC 端点连接验证。
```

对 BCB/联烯等可能具双自由基/多参考特征的体系，xTB 可用于开发反馈，但**不能未经更高等级验证就作为最终化学结论**。

**V6 主指标（有效 TS 单位成本）**：

```text
C_valid = Σ_i C_i^total / Σ_i I_i^valid
```

其中每个失败任务、回退计算、精修与验证均计入总成本；若没有任何成功任务，该值不可定义，**必须报告零成功，而不是忽略失败样本**。同时报告：有效 TS 成功率、梯度/能量/Hessian 调用次数、core-hours、P90 成本、固定预算内成功率；必要时用梯度等效调用作辅助指标，但不能隐藏实际时间成本。另对一组预先选定的代表性案例做 **DFT 抽检**，衡量低等级 xTB 结果能否迁移到更可靠电子结构方法。

### 3.6 V6 退出条件

V6 完成不要求战胜所有传统 TS 算法，但必须满足：

1. 真实 QC 闭环能稳定批处理、失败恢复与重复运行。
2. SFT 相对 V5 Frozen 在真实闭环中有**可复现收益**（而非仅改善离线 Loss）。
3. 固定安全层与 Classic Fallback 后，系统能限制异常几何与不可恢复搜索。
4. 建立完整**成功率—计算成本曲线**，并冻结可供 V7 使用的 SFT Baseline。

> **红线**：若 V6 的 SFT 连稳健的 Classic 控制器都无法持续超越，应先修正监督与控制设计，**而不是直接用 RL 试图弥补**。

## 4. V7：强化学习驱动的量化计算成本优化

V7 的创新不再来自换网络，而来自**改变学习目标**：V5 学习已有路径，V6 学习如何可靠执行路径，V7 学习**什么时候应当偏离参考路径**才能更高效定位目标过渡态。

### 4.1 数学目标：从模仿到最小期望成本

把量化计算闭环定义为带预算约束的决策过程：

```text
S_t = {R_t, G, q_t, E_t, g_t, h_t, B_t}
```

其中 `h_t` 为搜索历史，`B_t` 为剩余计算预算。在 V6 稳定接口基础上，V7 才开放完整策略动作：

```text
a_t = (m_t, Δq_t, k_t)
```

- `m_t`：Move / Reduce / Rollback / Refine / Fallback 等策略选择；
- `Δq_t`：方向与步长；
- `k_t`：当前激活的反应坐标集合或有效维度。

目标：

```text
min_π  E_π[C_total]
s.t.    P_π(valid target TS) ≥ p_min
```

并对每个任务设置**相同预算**，避免策略通过大量提前 Abort 轻易降低平均成本。最终报告仍以 `C_valid` 为核心效率指标，并单独报告成功率与覆盖率。

### 4.2 V7.0 — RL Environment：环境与奖励

奖励不应只奖励能量上升。采用分层代价：

```text
r_t = -λ_c·C_t^QC - λ_f·I_t^failure + λ_p·r_t^progress + r_t^terminal
```

- `C_t^QC`：真实当前动作量化计算成本；
- `I_t^failure`：非法动作、错误分支或不可恢复失败；
- `r_t^progress`：保守的阶段进展辅助奖励；
- `r_t^terminal`：目标 TS 通过验证的终局奖励。

要保证**最终成功验证与真实计算成本支配策略排序**。若对能量爬升、接近参考 TS 等代理信号赋过高权重，RL 很可能学会优化代理指标而未提高真实 TS 搜索性能。

### 4.3 V7.1 — Restricted Policy RL：先优化有限决策

不要一开始就让 SAC 在完整连续动作空间自由探索。先冻结反应坐标集合，把合法动作限制为：

```text
A_t = { Move(α·Δq_SFT), Reduce, Refine, Fallback }
```

其中 `α` 取少量安全缩放候选。该阶段用小动作集合研究：RL 能否学会比 V6 监督控制器更好的步长、停止与回退策略。可优先比较规则决策、离线价值学习与 PPO；后续低维连续动作再考虑 SAC。**GRPO 不必作为强制基线**，其是否适合当前连续化学动作任务需具体证明。

### 4.4 V7.2 — Adaptive Reaction Coordinates：自适应坐标

这是最值得发展成独立方法创新的部分。V6 默认使用反应图规定的固定 driver；V7 才正式回答：

> 一个反应究竟需要多少个有效自由度？应该在哪一步增加、删减或切换反应坐标？

| 策略 | 动作空间 | 研究目的 |
|---|---|---|
| **Fixed-k** | 固定反应图 driver | V6 基线 |
| **Step-RL** | 固定 k，动态步长 | 隔离步长优化收益 |
| **Subspace-RL** | 固定步长策略，动态激活坐标 | 隔离动态维度收益 |
| **Joint-RL** | 动态坐标 + 动态步长与阶段 | 检验联合控制收益 |

这样能把 RL 的计算效率增益**分解为步长控制、坐标控制及两者协同**，而不是只得到一个难以解释的网络。BCB/联烯等可能分步机制/路径分叉的案例可作额外挑战集，但其复杂机制不应成为衡量常规闭壳层反应平均性能的唯一依据。

### 4.5 V7.3 — Final Generalization：最终方法学验证

在冻结测试集上比较四代策略：

| 方法 | 对应贡献 |
|---|---|
| Classic | 传统化学规则 |
| V5 Frozen | 纯离线模仿学习 |
| V6 SFT | 真实量化反馈纠偏 |
| V7 RL | 面向实际计算成本的策略寻优 |

所有模型使用相同电子结构计算设置、反应初始条件与最终验证协议，并对全部失败任务计费。最终需证明：

- V7 是否在相近正确性下减少总 QC 成本；
- 是否扩大可成功处理的反应家族覆盖率；
- 动态坐标控制是否比固定坐标更高效；
- 模型在哪些 OOD 反应中应主动 Fallback；
- **RL 训练额外消耗多少量化算力，部署后需执行多少次任务才能摊销**。

最后一项尤其重要：**节省单次推理成本，不等于已经节省了研发阶段的全部计算成本。**

## 6. 三阶段并行推进与五个冻结接口

**版本的科研验收严格串行，但工程基础设施可并行开发。**

```text
主线 A：V5 离线模型   数据冻结 → 架构对照 → Rollout → 权重冻结
主线 B：V6 真实计算   Classic xTB 接口可提前开发 → 接入 V5 权重 → SFT
主线 C：V7 强化学习   MDP/Reward 先设计 → V6 冻结后正式训练 RL
```

建议现在就冻结五个与具体模型无关的接口：

```text
ReactionSpec
  └── Reaction Graph / Atom Mapping / Driver Coordinates

Observation
  └── XYZ / E / Gradient / History / Budget

ActionProposal
  └── Move / Process / Trust / Δq

StepResult
  └── Accepted / Rejected / QC Calls / Next State

TSValidation
  └── OptTS / Frequency / IRC / Endpoint Identity
```

- **V5** 只调用前三个接口，使用离线回放器；
- **V6** 开始调用 `StepResult`，接入真实量化软件与 `TSValidation`；
- **V7** 完整使用五个接口，在相同执行环境中学习新决策策略。

该接口划分也便于与 ACP3 的 CCCP/ACR 对接：PES2TS 负责路径决策，CCCP 负责统一工作流与结果协议，ACR 负责真实计算资源的执行与管理。

> **治理提示**：五接口一旦冻结即属接口变更，按 `AGENT.md` §7.2 应**另立 ADR**（建议 ADR-0036）记录取舍与版本；本方案只提出接口形状，不代替 ADR。

## 7. 近期实际开发优先级

先把精力集中在以下四项，而不是继续扩大模型种类：

| 优先级 | 任务 | 完成判据 |
|---|---|---|
| **P0 冻结数据集** | 确认独立 Reaction/Family 数量、轨迹重建、原子映射、数据切分、与原 OOF 可比性 | 数据泄漏检查通过、manifest 冻结 |
| **P1 统一训练框架** | 固定 Encoder/Heads/损失定义，完成 MLP、GRU、CfC、SSM 的统一输入输出 | 六模型同接口可训练 |

## 8. 科学贡献定位与论文结构

调整后论文叙事更清楚：

- **V5（算法基础研究）**：神经网络需要什么样的记忆与归纳偏置，才能学习反应路径决策。
- **V6（化学计算方法研究）**：如何把离线学习的路径规律转换为可靠、低成本的物理搜索过程。
- **V7（最可能形成突破性方法学贡献）**：回答——

> **化学反应的拓扑约束能否将高维势能面搜索转化为可学习的低维决策问题，并使机器在真实量子化学反馈下，以更低成本自主选择路径推进策略？**

这里的"自主"指：在给定反应问题及允许的化学操作空间内**自主优化搜索策略**，而不是宣称模型能无条件发现任意未知反应。这一区别也使用户提出的"关键原子主动位移、其余自由度通过量化计算松弛"的核心假设得到严谨的阶段性验证。

## 9. 最终研发决策

1. **V5 主力**完成 `MLP / GRU / CfC / Selective SSM` 轻量化 Benchmark，Transformer 作重要对照，Neural ODE/LTC/Mamba 留扩展；**绝不在 V5 追求量化闭环成功率**。
2. **V6** 使用冻结最佳结构，以 Classic Controller 为安全基线，用真实 xTB 闭环数据训练可靠监督控制器，并建立端到端 TS 搜索效率指标。
3. **V7** 才逐步放开策略自由度：从固定坐标下的步长/停止/回退优化开始，最终进入自适应反应坐标与联合策略学习。

这样不是在 V5/V6/V7 做三个不同的 AI 项目，而是**逐层回答同一个科学问题**：机器究竟应该学习化学反应路径搜索过程中的哪一部分决策，才能在保持量子化学可靠性的前提下，真正减少昂贵计算。

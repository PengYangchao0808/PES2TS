## 1. 架构约束

**ACP 是唯一计算执行后端；任何参考项目都不能成为 PES2TS 的旁路 QC 引擎。** 缺能力时新增/扩展 ACP 能力，PES2TS 只提交明确配方并消费带来源的结果。

| PES2TS 拥有 | ACP 拥有 | 联合冻结 |
|---|---|---|
| 反应图、F/B 范围、driver/guard、方向/调度、路径接受/分支策略、候选排序、目标反应判定 | 二进制/集群、QC 基元、进程/资源/取消、WORK/RESULT、原始解析、manifest、任务/帧展示 | 请求 schema、产品 schema、单位/原子序、能力收据、幂等身份、成本口径 |

纯 NumPy 预测、投影、局部校正更新可留 PES2TS；其中每次 E/g 请求必须经过 ACP，PES2TS 不加载 cccp 或直接启动 ORCA/xTB。若未来把通用局部优化器迁 ACP，则作为独立任务明确迁移，不能两边都实现同一套化学策略。

遵守 ACP 当前仓库规则：新计算基元放 `src/acp/calculations/primitives/`，工作流做薄编排；单步走 CalculationPlanExecutor，多步复用既有执行体系。新增 active workflow 同步 catalog、registry、CLI、scheduler、`job_edit.py::EDIT_ACTIVE_WORKFLOWS`；遵守统一 run_root、任务目录和 scheduler markers。结果写 manifest v2；视图经 `results/frames.py` 的 `TrajectoryFrame`/`TrajectoryAnnotation` 与 VIEW_REGISTRY 投影。能量 viewer 仅保存候选，计算提交通过任务入口，不在 viewer 新开旁路。

## 4. 新增请求/产品合同草案

本节是待版本化冻结的设计字段，不声称这些 CLI 命令或 schema 已存在。既有 `pes2ts_xtb_path_request_v1`、PESsearch、BatchOptimize、irc 合同保持兼容；破坏性扩展使用新版本。

### 4.1 通用身份和幂等

请求至少带：`schema_version`、`request_id`、`reaction_id`、`plan_sha256`、`parent_attempt_id`、`geometry_ref/sha256`、`atom_order_sha256`、完整 method/basis/solvent/charge/multiplicity、operation、显式资源/阶段预算、effective recipe 及其摘要。

内容身份使用 canonical JSON，定义浮点/几何序列化；不把循环自引用的 hash 字段放进自身摘要。缓存键绑定几何、映射、电子态、方法、溶剂、收敛参数、约束/目标、操作、后端语义版本和适用的随机种子/重启材料。原始 XYZ 文件哈希与解析几何哈希分开，禁止随意舍入掩盖不同几何。

- 相同 idempotency key、相同摘要：返回原 receipt/产品，不再次计算；相同 key、不同摘要：明确冲突。
- checkpoint 恢复只从最后已接受帧及对应状态启动；旧缓存错配不能吞掉后继续。
- job/task/execution/attempt/evaluation ID 作用分别为任务、执行尝试与 QC 子调用身份；可变运行身份不进入纯内容哈希。
- 每次重试、方向/guard/方法改变有新的 attempt/plan 版本；ACP 不自主改变 PES2TS 化学配方。
- 请求总预算与已用预算随恢复继承；不能靠换 attempt 清零总预算。

### 4.2 `energy_gradient` 产品（拟定）

| 字段 | 语义 |
|---|---|
| `geometry_sha256`, `atom_order_sha256`, `n_atoms` | 与本次输入/输出几何精确绑定，解析核验元素与坐标 |
| `energy_hartree`, `gradient`, `gradient_unit` | 原始物理 E 和 ∂E/∂X；统一输出 Eh/Bohr 或声明转换，不能把 force 当 gradient |
| `gradient_kind` | `physical_unprojected`；投影/加偏置梯度必须另命名 |
| `method_context`, `scf_status`, `electronic_state` | 实际执行设置与收敛；只有输入参数不算电子态已验证 |
| `source_artifacts`, `parser_version` | engrad/output 文件产品 ID/hash，解析版本 |
| `cost_ref`, `status`, `failure_class` | 计量旁车与 typed 失败，缺失梯度为 null |

原生单位在边界统一转换一次并测试。多坐标约束驻点如需物理梯度，优先回收同几何原生输出；若语义不明确，另起同几何 EnGrad 子请求并计费。不能用优化最后一条日志中无法绑定的梯度充当物理证据。

### 4.3 约束校正 / 梯度交互

约束请求携带 B/A/D 定义、map→index 映射、角度单位/周期性、目标/容差、初猜 hash、固定参考结构、Trust/MaxStep（实际 ORCA 关键字是 Trust）、内部迭代和阶段预算。响应保存初猜/最终几何、每步优化轨迹引用、残差、真实收敛状态和原始输出。

第一版用 ACP CLI 子请求验证语义；每次 QC 调用有独立 receipt，同时属于同一外层 continuation attempt。PES2TS 决定下一 λ、接受、折半或换计划。若逐梯度启动 CLI/排队开销显著，下一步增加 **ACP 管理的会话/子任务通道**：会话复用配置、工作目录和资源，不承诺 ORCA 二进制可常驻；每个 evaluation 仍受预算、身份和取消控制。先测调度开销再优化，不把几百个微小梯度调用各自展示成顶层反应任务。

计划中途输出的 partial manifest/checkpoint 必须与 final completion 区分。终态 failed 不删除已完成子调用和有效前缀；PES2TS 对部分路径逐帧放行，不能把整个失败任务转换为成功。

### 4.4 频率、IRC 与端点

复用 ACP frequency modes / Hessian 产品和 `irc_ts_source_v1` 来源证明，追加几何、方法及溶剂状态核对。拆分 Hessian 初始化、OptTS、最终频率、forward IRC、reverse IRC、两端优化/频率的预算与状态。有效 Hessian 可以复用，但必须绑定相同几何/方法，不能静默复用候选初猜的 Hessian 作为最终频率证据。

ACP 输出模式向量、频率、优化收敛、IRC 收敛原因、原始与优化端点。PES2TS 输出 `target_match` 和化学判定版本。端点最大步数用尽、SCF 故障、任务超时、非目标图、模态无关分别编码，不统一为“TS 不存在”。

## 5. 成本旁车与反重复计数

建议新产品 `calculation_cost_v1`，由 ACP 的 calculations/executor 与解析器生产，storage manifest 注册；不要给原 manifest v2 随意加无版本化解释的必填字段。

每个实际 QC evaluation 记录：`evaluation_id`、父 attempt、stage、method/resource fingerprint、执行起止、energy/gradient/Hessian 事件属性、`cache_hit`、测量来源、完整性、wall_seconds、cpu_seconds、allocated_cores、allocated_core_seconds。计数来源为 engine counter / parser / scheduler / estimate；无法取得的值 null + reason，不把 OptTS iterations 当梯度次数。

数值 Hessian 的外层 Hessian 事件与内部梯度子事件关联；N_gradient 统计实际子调用一次，N_Hessian 统计 Hessian 构造一次，两者不相加解释成“总调用”。有些引擎无法恢复内部计数，显式 lower_bound/unknown。失败和取消保留已发生消耗。

实际 CPU core-hours = 可核验的进程/调度器 CPU seconds 总和 / 3600；分配核时 = 各时间段 allocated cores × wall seconds / 3600，二者分别显示。外层会话时间不能与子进程 CPU 时间重复加总。缓存命中本次 QC 成本为零，但保留来源成本和共享计算关系；基准另报冷启动/分摊成本。

## 6. xTB PATH 与可视化的具体收口

X1′ 中 ACP 工作区已经存在的后端/工作流先审计收口。检查当前实现是否经 calculations 基元；若仍在 workflow 直接执行，则按 ACP 架构规则抽到 primitive，避免再造平行引擎。此后完成 CLI `--path-config`、catalog/registry/scheduler/edit coverage 和 manifest/profile 注册。

配方等价必须覆盖显式 `gfn/uhf`、电荷/多重度、线程环境、超时、seed 支持、path.inp 与额外参数。当前低层 `uhf=0` 仍有按 multiplicity 推导语义，必须在冻结合同中校验一致性或明确拒绝冲突，不能无声覆盖。`extra_args` 禁止重复覆盖冻结关键参数。seed 不受二进制支持时拒绝或显式标记不可控随机性，不能只记录请求值。

保留 ADR-0002 的 RecipeEquivalence/ReplayParity 要求；历史原始轨迹的派生物用钉住依赖版本的环境生成。若 Parquet 序列化版本导致字节差异，报告为证书未过并评估差异，不把“值相同”悄悄替代已冻结的字节证书。两次真实随机计算只做统计对照，不要求原始输出相同。

身份桥默认设计为 CLI `--register` / 绑定指定外层 job（拟新增，名称待合同冻结）：建立或幂等附着运行身份，将 WORK/RESULT 指向实际运行目录；运行时发布状态，终态更新原记录，避免计算结束后新建虚假重复任务。采用 ACP 现有目录规则，job_id 不进入磁盘目录名。崩溃后根据 receipt/manifest 对账，不重复运行已成功 QC。

可视化至少展示：物理能量曲线、accepted/rejected/partial、λ 与帧、driver/guard、候选及排名理由、OptTS/IRC 子任务、错误和成本完整性。统一经 profile 与帧契约；若 rejected 没有结构，只显示事件，不伪造 XYZ。文件级产物可先交付，但 X5′ 通过需要真实 job_id 的 Workbench 查看证据。

## 7. 测试与迁移门

| 门 | 证明内容 | 不能替代什么 |
|---|---|---|
| schema/fixture | 单位、hash、投影、失败、兼容与注册正确 | 不能证明引擎实际可用 |
| 真引擎小例 | PATH、约束、E/g、频率、IRC 的可执行与物理绑定 | 不能证明目标反应通用成功率 |
| strict 回放 | 当前四代表例的结果/失败可复现，缓存身份正确 | 不用放松梯度门换取通过 |
| 验证器校准 | 参考 TS 全链、模式与端点判定正确 | 不计 PES2TS 生成成功 |
| G2.T | 24 条自动终态与账本、≥1 严格生成目标 TS、Workbench 证据 | 不等于 24 条全部成功，不等于泛化评估 |

真实后端 suite 必须明确选择并在缺失能力时失败/阻塞，不以默认被 skip 的测试宣称通过。重点回归：原子重排、Eh/Bohr↔Eh/Å、force 符号、错误几何缓存、开壳层、非收敛残缺产物、单向 IRC、端点同侧、部分路径候选、双向标签交换、改变协议后的旧缓存、重试和重复计费。

迁移顺序：冻结旧快照/回放材料 → ACP 对应能力通过 → PES2TS 接线 → 证书/真实冒烟 → 移除本地计算入口和 cccp 依赖 → 默认 ACP → 文档与真值守卫同步。删除 runner 前必须已有可运行替代；不要求用户为已授权的 ACP 路线再次选择架构。旧大规模产物保持只读。

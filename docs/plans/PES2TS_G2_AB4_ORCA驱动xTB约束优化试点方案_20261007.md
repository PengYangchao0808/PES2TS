## 1. 目标、依据与范围

**保持原生xTB快速主路径，为几何不收敛提供一次有预算的ORCA硬约束优化。** 成功以真实收敛、实际约束残差和原化学门通过衡量，不以正常退出或能量峰衡量。

AB3的395份优化收据中，350次标记几何收敛、45次未收敛；后者分布在7个反应，均未检出SCC失败，记录538个优化周期。这支持先测试几何优化器，不能证明约束刚性是唯一原因。原24例仍是13完整/9部分/2拒绝、validated=0；另2个旁观键窗案例继续按质量拒绝处理。

ORCA使用冗余内坐标、模型Hessian及内部准牛顿更新，并可直接固定键长；当前xTB用谐和势约束。硬约束可能缓解强惩罚势的数值困难，但本试验同时改变优化器和约束语义，收益不单独归因于ORCA。[ORCA优化器与约束](https://www.faccts.de/docs/orca/6.1/manual/contents/structurereactivity/optimizations.html)、[xTB约束势](https://xtb-docs.readthedocs.io/en/latest/xcontrol.html)

首轮仅外部GFN2-xTB、当前气相配方和距离driver。ORCA原生xTB、其他溶剂/电子态设置、角度/二面角和环境冻结另验收，不静默替换。初猜仍由关键原子预测器给出，其他未约束自由度由ORCA/xTB松弛；不是只优化关键原子。

## 2. 计算链及固定配方

`已有接受父帧 → 原关键原子初猜 → ACP → ORCA受约束Opt（外部xTB能量/梯度）→ 同最终几何的裸xTB单点及收据 → PES2TS化学/残差检查 → 接受或typed拒绝`。

ACP新增薄公开适配工作流拟名 `OrcaXtbConstrainedOpt`。复用现有ORCABackend/约束渲染、xTB单点和进程管理；不在PES2TS启动计算程序，也不恢复逐梯度调用的自写BFGS。ACP现有`optimize`能执行通用优化，但其参数/收据是否满足本合同另核验，不能仅靠返回success替代本工作流证据。通用补救矩阵中有Hessian重启/CalcAll，本分支明确不启用这些补救。

| 项目 | 首轮冻结值/语义 |
|---|---|
| 方法 | ORCA外部`XTB2 Opt`，绑定与原生分支同一xTB二进制/参数及有效电子设置；安装版本实读，不假设本机已有能力 |
| 约束 | `%geom Constraints { B i j target C }`；0-based位置、Å；仅driver，guard/monitor仍为事后检查 |
| 优化 | 冗余内坐标、默认模型Hessian/内部BFGS；ORCA最多100周期；原生配对保留maxcycle=500；周期数不是跨引擎等价预算 |
| 排除 | 不自动NumFreq/Calc_Hess/Recalc_Hess/CalcAll、换DFT、SCF补救扫参、内坐标失败后改Cartesian约束或从失败末帧重启 |
| 资源 | 与旧试点相同4线程；逐点冷启动，记录ORCA/外部xTB实际并行与启动开销，避免嵌套超配 |
| 墙钟 | 首轮每引擎每点总预算60秒，覆盖优化/单点/启动回收；ACP向子任务传递剩余deadline，不能把60秒分别给两个阶段 |
| 质量 | 不放宽原距离接受门0.05 Å、旁观键窗或碰撞/身份门；硬约束实现诊断目标残差≤0.001 Å |
| 能量 | 始终用最终几何、同GFN2设置、无约束势的xTB单点作为E_physical；ORCA优化能量单独记录 |

ORCA外部xTB设置和`otool_xtb`映射、核数、精度/电子温度先以有效调用和版本收据核验；不能因关键词均为XTB2就认定方法等价。外部接口支持约束优化，GFN2/ALPB等设置见[ORCA xTB手册](https://www.faccts.de/docs/orca/6.1/manual/contents/modelchemistries/semiempirical.html)。首轮不启用Native-XTB，也不从能量差推断几何梯度等价。

## 3. 请求、收据和最小代码改动

新合同草案为 `pes2ts_orca_xtb_constrained_opt_request_v1` / `pes2ts_orca_xtb_constrained_opt_evidence_v1`。输入绑定几何、元素/原子序/map、charge/multiplicity、driver与单位、方法/实际设置、优化器/硬约束模式、资源/deadline、原始target、plan、父几何和来源尝试hash。父几何hash、父请求hash分开，不沿用旧字段的借名语义。

收据保存真实几何收敛标记、电子收敛/错误、最终原子序/几何、实际约束值、ORCA优化能量、裸xTB单点能量、优化周期/能量/梯度实际调用、优化/单点/总墙钟、程序/输入/日志/产物hash。硬约束分支没有惩罚势能：`E_effective=null + not_applicable_hard_constraint`，不能伪填成优化能量；比较只用E_physical。未知调用计数/CPU核时记null及理由，不把周期当精确梯度次数。

终态区分几何不收敛、SCC/SCF失败、内坐标失败、deadline、能力缺失、身份/原子序错误、无物理能量及化学拒绝。收到ORCA正常退出仍复核几何收敛与实际结构。缓存键包含优化器、硬/软约束、方法/版本和完整请求；失败证据不接受成帧，新旧请求不能串缓存。

| 产品/文件（拟定） | 最小改造 |
|---|---|
| ACP `workflows/orca_xtb_constrained_opt.py`及公开注册/CLI/manifest | 薄工作流；只复用既有QC原语，输出新收据；保留现有工作流 |
| PES2TS `integration/acp/orca_xtb_constraints_adapter.py` | 新请求、公开CLI传输和收据适配；复用既有claim/恢复/几何残差纯工具，必要时小幅提取公共函数，不复制整套接缝 |
| `generation/planning/classic_scan.py` | 在统一批次提取一次公共单步/宏步恢复，增加显式实验备选分派；Classic/残差共用质量和计费，固定网格语义保持 |
| `generation/native_campaign.py`、`native_report.py`和CLI | 显式实验配置与新配方/计费输出；旧模式保持原结果口径 |
| 配套tests/试点报告 | 工作流/身份/失败/恢复fixture及4点真实对照；AB4子任务不重启G3-P1，统一批次新增控制头另按产品归属实施 |

单点实验可先使用新适配器；混合扫描发布新 `pes2ts_native_scan_result_v2` 与trace v2，明确每帧optimizer/constraint_mode/环境版本及分层成本。旧v1和历史报告只读，新产物写新目录；formal schema/validator在实施批次冻结。

## 4. 有限回退规则

实验开关拟定 `native_xtb_with_orca_rescue`，默认关闭。主路径先走原生xTB和原有限缩步；准备因几何不收敛终止时，且能力已冒烟、身份/输入合法、总预算和拒绝配额仍有余量，才触发一次ORCA尝试。

ORCA使用该次失败请求的**原始初猜和相同实际目标**，不使用未接受的失败末帧。只有新结果通过全部检查才成为父帧；接受中点仍保留原目标队列。接受后下一步回原生分支；不让RL增加一个“选优化器”动作。

初始上限：每个原网格target最多1次ORCA、每例最多2次；两引擎共享原每例900秒/120请求预算及拒绝配额。备选请求、失败、裸单点和恢复都计费；预算不足直接typed停止，不能给ORCA重置900秒。SCC失败、化学拒绝、旁观键越界、身份/缓存错误、输入不支持和能力缺失不触发此回退。

残差路径接入时，原网格target的对应物为稳定逻辑action/target ID，内部细分延续父target ID与救援配额，不靠新lambda/attempt编号重置次数。宏步保留原命令、最终实际响应、部分接受/pending目标和所有内部费用；这种学习记录发布新v3结果/trace，AB4固定网格混合v2保持原义。

单轮配方冻结，不因结果临时增加周期、回退次数或精修。新混合环境版本进入未来状态/转移，不能与旧纯原生环境无条件混训；G3编码器和教师任务不变。

## 5. 先4个点，再4条短批路径

以下按历史trace中各反应首个对应尝试选择，先冻结源输入/收据hash，不根据ORCA结果换题。完整选择见[试点点清单](fixtures/g2_ab4_orca_xtb_pilot_selection_v1.json)。

| 反应/原尝试 | 类型 | 原结果 |
|---|---|---|
| RXN_0000017762 / lam0.2-try00 | 失败点1 | 几何未收敛，538周期 |
| RXN_0000100736 / lam0.1-try00 | 失败点2 | 几何未收敛，538周期 |
| RXN_0000194484 / lam0.05-try00 | 失败点3 | 首段几何未收敛，538周期 |
| RXN_0000007104 / lam0.05-try00 | 正常对照 | 几何收敛，21周期 |

1. **离线门**：距离/原子位置/硬约束渲染；同键恢复与冲突；跨workflow收据拒绝；未收敛正常退出、SP失败、deadline及化学拒绝；全部尝试计费；禁昂贵补救；备选关闭时原Classic回归。source身份不全则拒绝，不用optimized.xyz替代原初猜。
2. **能力与方法门**：实读ORCA/xTB版本、hash和调用，正常点冒烟；在同最终几何复核ORCA优化能量与裸xTB单点。首轮能量差诊断门暂定1e-6 Eh；不满足时核对有效精度/电子设置和打印精度，不静默放宽。必要额外单点单列费用，不追加Hessian。
3. **4点成对实验**：两引擎从同一保存的`xtb_input.xyz`出发，用相同目标、线程和60秒总预算；新目录、新request/recipe。比较真实接受率、残差、物理能量、优化调用及含启动/SP的总费用；旧缓存结果仅历史对照，不能拿热缓存墙钟对新冷启动。首轮8次点试验的预算上限480秒，能力冒烟另列。
4. **进入扫描接入的初始门**：正常点通过全部质量/方法门；3个失败点至少2个被ORCA真正接受；身份/全费用/恢复证据完整。任一不满足则收口失败原因，不直接做全24例。此门是小批工程门，不是统计或TS声明。
5. **集成后4例成对短批**：仅上述4个反应，纯原生与显式混合配方各跑一轮；每例预算仍900秒，不使用参考真值。计新增可接受前缀/原网格完成数、全输入费用及备选收益；正常案例在备选不触发时保持同决策。困难案例先报告成本—覆盖取舍，不要求新完整路径比旧提前失败更便宜。

通过后再评估剩余几何失败案例；对7例的适用范围仍如实披露。所有Demo24已暴露开发，试点只能作回归/工程判断，不作独立泛化或RL训练split证明。人工复核/S4、严格TS出口和生产默认仍按原门推进。

## 6. 交付与停止条件

按“ACP单点工作流 → PES2TS适配 → 4点对照 → 有限回退 → 4例短批”顺序交付，每步通过才扩范围。每步保存请求/配方、原始日志、收据、typed终态、费用和新报告；收据齐全但尚未真实执行的能力只记implemented/fixture_passed，真实冒烟通过后才记smoke_passed。

若硬点未改善、方法对不上或成本不可控，保留原生路径并报告原因；本轮不转向完整Hessian/多优化器堆叠。此方案对准一个明确失败机制，属于统一计划中有门的执行增量；不重启G3，不增加RL优化器选择动作。逐坐标残差/动作价值设计由ADR-0017承接，不能因救援门未过阻塞纯原生RL接通。当前交付为方案/ADR/选择清单，尚未实现或运行上述实验。

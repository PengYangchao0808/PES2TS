## 3. 五条边界保证的修订审计

| 保证 | 现实 | 修订结论 |
|---|---|---|
| 白名单输入完整 | 端点、原子序、F/B/O、H 变化、分类等具备；全图/立体权威需补 | 足以支持现有基础实验；新保护/严格身份层需旁车 |
| 活动编辑视图 | 有 edit_kind，没有显式活动视图版本 | 需冻结 F/B active、O archived 的规范适配器与摘要，不让各消费者自行推断 |
| 电子态一致 | 有组分 charge/multiplicity；当前装配仅接受总 Q=0、M=1 范围 | 当前受限范围有门；不能推广为任意多组分总自旋已经确定 |
| 工作方法一致性 | 缺带方法/几何/证据的结论 | G1 交来源与 unknown 合法；G2 origin preparation 经 ACP 产生证明。不得无计算填 true/false |
| 真值无关与可复现 | 映射为 truth_assisted_p1，gate 也使用 IRC 证据；可做版本身份 | **严格端到端 truth-free 不满足**；需分层 provenance，不以删除几个字段清除来源影响 |

不能沿用“2 完全满足、2 部分、1 缺失”这种掩盖不同适用域的总括。静态字段、工作方法证据、来源独立性需要分别判定。

## 4. 真值来源的三层审计

### 4.1 字段隔离不等于来源独立

当前 export 不直接包含 TS XYZ 或 IRC 轨迹，可维持字段级白名单。但 `mapping_provenance="truth_assisted_p1"` 明确说明原子对应关系使用了真值层。

坐标来自 R/P 原始端点，不等于排成这些坐标顺序、派生的 edits/分类都与真值无关。当前 `v2_gate.py` 还基于 IRC 一致性决定 review/excluded；因此队列选择本身也有真值来源。

建议旁车明确四项：`geometry_provenance`、`mapping_provenance`、`cohort_selection_provenance`、`development_exposure`。各项带构建器、输入 hash、版本与证据引用，不能只保留一个笼统 truth_free 布尔。

### 4.2 两条允许但结论不同的评测路线

- **现有开发/辅助映射路线**：保留历史 gate、映射和 split，不覆盖；显示 `truth_assisted_development` 或明确的 `given_truth_assisted_mapping` 条件。可做工程回归和条件化算法对照，不能声称端到端无真值独立泛化。
- **新的独立评测路线**：只用端点和可部署的映射方法构建输入与预筛选规则，在开发调参前冻结反应集合；失败、不确定映射与不可计算样本也留在漏斗。TS/IRC 仅在冻结后用于评价。已给定专家映射的 benchmark 可单列“给定映射”条件，但必须说明来源。

Demo24 已参与真值诊断，整体作为开发回归。仅换反应 ID 或重新划分现有被查看过的集合，不能自动恢复独立性。同一反应的帧、映射副本、对称副本需同组划分，相关反应/家族泛化另报。

## 5. 工作方法证据的正确责任分工

G1 应输出端点原始计算方法/溶剂/电子态/几何来源；不知道时明确 unknown，不猜成 DFT 稳定极小点。G2 在选择工作方法后，调用 ACP 完成 origin preparation。

建议 `endpoint_method_evidence_v1` 至少包含：

| 字段 | 语义 |
|---|---|
| source_geometry_hash / prepared_geometry_hash | 原始与准备后结构分别绑定；新结构不覆盖旧端点 |
| method_context_hash | 方法、版本、参数、电子态、溶剂与收敛设置 |
| stationarity_status | unknown / converged / not_converged / execution_failed |
| minimum_status | unknown / verified / not_minimum；区分梯度收敛与曲率证明 |
| identity_status | target / non_target / ambiguous |
| gradient_ref / frequency_ref | 没算的项为 null + reason |
| acp_receipt_ref / parent | 原始执行与谱/几何证据 |

`working_method_minimum=true` 只有同几何/方法的驻点与极小值证据支持才可派生。单次优化失败不等于 false；优化后重排也需区分方法不兼容、起点构象/装配差、SCF 分支和预算不足。

所有工作方法能力由 ACP 提供。G1 不为每个未来 G2 方法预先做一遍量化计算；现有 183,460 条记录不需要为修合同而全量重算。

## 6. G1→G2 边界 v2 草案

采用新版本边界旁车并绑定原 export hash。现有 `g1_v2_export_v1` 及历史 gate 不原地加语义字段；若未来生产新 export，升级 schema 并保留原产物。

```text
g1_g2_boundary_v2（拟定）
  export_ref + export_sha256 + atom_order_hash + mapping_hash
  active_edit_policy = fully_formed_broken_only_v1
  active_edit_ids / archived_edit_ids + edits_hash
  endpoint_graph_ref/hash + graph_authority + inference_version
  stereo_evidence_ref + specified/unspecified/unknown semantics
  source_method_context + endpoint_method_evidence_ref (nullable)
  provenance {geometry, mapping, cohort_selection, development_exposure}
  electronic_state_scope + assembly_spin_policy
  protection_partition_ref/hash（拟定计划派生物，不是无条件物理真值）
  boundary_status + typed_reasons
```

活动视图由唯一规范适配器根据 F/B/O 语义生成并冻结，其效果等价于显式 scan_active 列；禁止十个下游各写一次推断。纯 O 返回范围拒绝，不因新增图罚项而重新成为 driver/guard。

完整图权威首选由 G1 白名单构建器单独导出 `graph` 所需字段并绑定来源；不把含 irc_evidence 的 edits 整包交给在线 G2。SMILES 重建只作为明确版本的替代权威，记录 SMILES、标准化/芳香规则、显式 H、RDKit 等版本和重建 hash；两者冲突返回 typed conflict，不静默覆盖。

立体记录应包含指定/未指定状态和原子顺序约定。R/S、E/Z 文本受优先级规则与化学环境影响，不能用字符串变化直接判断真实翻转；结合 map 对应的有序局部几何和完整图解释。缺失时返回 unknown，不自动宣称立体一致。

保护分区由活动核心、支持 halo、接口边和明确保护假设派生；输出 `no_spectator_vertices` 与 `no_protected_pairs` 两种不同状态，空集合不制造谱通过记录。

## 8. 审计结论

现有 G1 资产为基础路径开发提供了充足数量的端点、编辑和分类信息；183,460 的规模不是当前主要瓶颈。但它尚不能直接满足新增的保护图/严格立体身份合同，也不能证明所有起点适用于所选工作方法。

更关键的是，当前资产具备字段隔离，**不具备完全独立于真值的映射与队列选择来源**。应保留其开发价值并明确评测条件，另建来源干净的冻结队列验证泛化。

先完成 01–04；05 随图门落地；06 只服务可选对称研究。新 gate 命名和 schema 必须另版本化，禁止将旧 `gate_pass=true` 直接复用为新合同放行结论。

## 0. 摘要

**一句话**：V5 后续阶段分两段走——**先把 V5.5 数据地基冻结（四层数据 + 三头标签 + 无泄漏四测试集），再按「14 架构 × 1 seed 初筛 → 8 架构 × 3 seeds 受控复现 → 消融/压力测试 → 规模与部署冻结」的 122 run 预算推进，最终只冻结 1–2 个架构进入 V6。**

三个关键数字（本文档所有训练安排的基线）：

| 数字 | 值 | 来源 |
|---|---|---|
| 可训练池 | **50,000 条曲线**（2k⊂5k⊂20k⊂50k 嵌套前缀），冻结 dev **589**、confirm **2,000（仅列名、从未建库）** | L3 `split_manifest_v53mp.json`（在库副本 `data/manifests/v53mp_split_50k_ids_v1.json`） |
| 已建库轨迹索引 | **64,195 条曲线 / 128,390 条轨迹（fwd+rev） / 7,342,581 帧 / 14,685,162 条决策样本** | `/pes2ts_data/v53mp_50k_data/idx_v2`（`v53mp_idx_v2`，2026-11-23 复核） |
| 新增 xTB 单点标签 | **120,222 反应 / 240,444 分支 / 2,877,830 个单点**（GFN2-xTB，`train_fit` 池，离线 only；名义上限 2,912,712，`34,486,722` 为 Σ n_points 记账值，非单点数） | `data/manifests/xtb_singlepoints_train_fit_v1.json`（2026-11-23 入库，commit `34f2296`） |

三条纪律（违反任一即停止训练）：

1. **划分单元永远是 reaction group / curve**，不按帧随机拆；normalization 只用训练集统计量；测试集在选型完成前封存。
2. **V5 只做离线 Benchmark**：不用在线 xTB/DFT、不把离线风险代理说成 QC 成功率、不产生物理可靠性结论。
3. **训练作业必须走 WSL 稳定协议**（preflight → `wsl_guarded_run.sh --mem 16G` → 阶段末 `wsl --shutdown`）；当前宿主 commit 余量不足以直接开重活，**M2 之前必须先完成宿主整改**（见 §6.1）。

## 2. 训练数据体系（V5.5 输出定义）

### 2.1 四层结构与计数口径

| 层 | 内容 | 50k 数据集上的计数（`idx_v2`） |
|---|---|---|
| **Reaction** | 反应图、原子映射、成断键、Family ID | 反应组 = 曲线所属 canonical group；`family_labels` 20 类 |
| **Trajectory** | 计算方法、方向（fwd/rev）、参考 TS、采样方式 | 64,195 条曲线 / 128,390 条 intent（每曲线 2 方向） |
| **Frame** | XYZ、能量、反应坐标、路径弧长 | 7,342,581 帧（`q_canonical`/`arc_s`/`node_order` 与 `curve_node_energies` 同长） |

>
> 对外引用任何"20k/50k/100k"数字时，必须注明是反应/轨迹/帧/决策哪一层（v2.1 §2.1 纪律）。

### 2.2 划分与四测试集（V5.5 必须冻结的协议）

继承链（不可改写）：L0 官方 split（train 159,355 / valid 19,904 / test 19,909）→ L1 `pesn_irc_split_v1`（train_fit 121,363 / train_dev 15,161 / train_calibration 15,159 / family_holdout 9,573）→ L3 50k cohort（pool 50,000 嵌套、dev 589、confirm 2,000 封印）→ L4 run 内层（pool 内按曲线 80/20 inner-train/inner-val，每 seed 重算）。

V5 四测试集在 50k 资产上的落地建议（由 V5.5 契约最终冻结）：

| 测试集 | 构造方式 | 规模预算 | 备注 |
|---|---|---|---|
| **ID** | L3 `dev` 589 曲线（一次性） + run 内 inner-val（仅选 checkpoint） | 589 曲线 | dev 不得用于训练；inner-val 不是测试集 |
| **Scaffold-OOD** | 在 pool 内按骨架/取代环境分组留出（需要从反应图派生 scaffold key） | 待定（建议 ~10% pool） | 需要 V5.5 新增派生脚本；当前 50k 划分没有现成 scaffold 标签 |
| **Family-OOD** | 从 20 个 `family_labels` 中留出 3–4 个族（建议含 `other` 与一个 `rearrangement|*`） | 待定（建议 ~3,000–4,000 曲线） | `curve_family.csv` 可直接支持 |
| **Size-OOD** | 按分子规模（原子数/帧数）上四分位留出 | 待定（建议 ~10% pool） | 需 V5.5 统计原子数分布（`irc_node.coords_shape` 可得） |

**纪律**：同一反应的全部构象、正反分支、重采样/扰动轨迹必须同组（Group split）；四测试集互斥；归一化统计量只由训练集计算并冻结（含 SHA256）；测试集在 V5.7 选型完成前封存。

### 2.3 三头标签与 mask（G0 主筛选 / G1 对照）

| Head | 合法监督（V5 内） | idx_v2 字段映射 | mask 规则 |
|---|---|---|---|
| **Move** | 局部切线 `dq/ds` 与指定 `Δs` 的位移；Classic 残差（有 `v_C` 时） | `q_canonical`（按 `node_order`）、`arc_s` → `Δq = q[t+1]−q[t]`、`v = Δq/Δs`；`action_len>0` | `label_status!=ok`、`degenerate_curve=True`、无未来步（末帧）→ mask |
| **Process** | 路径进度 + 参考 TS 邻域（几何区域） | `q`（TS=0）、`ts_row`、`q_mask` → 3 类：pre / near-TS（`|q|≤window`）/ post | 无 `q` 或 `ts_row` 缺失 → mask |
| **Trust** | 离线预测风险代理（大误差/OOD/几何异常） | `|d_key_ts_ep|` 截断到 [0,1]、`degenerate_curve`、`geometry_legal`、`energy_ev_within_window` | 无真值或不适用 → mask；**不得**用 `Trust=1` 补监督 |

- **G0（主筛选）**：只用几何/反应坐标/历史动作/路径间隔，**不使用** `curve_node_energies`。
- **G1（对照）**：在 G0 上增加缓存 QC（能量/梯度或其历史差分）；**不得**在 G1 自主 rollout 中把参考 IRC 的未来梯度赋给模型新构型。
- Classic 残差：`idx_v2` 中无现成 `v_C` 方向，`IdxV2Reader` 走 `classic_dir=None` 分支；V5.7-A 的 Representation 消融需要另行从 `MoveProcessContract`/Classic 控制器派生 `v_C` 标签（V5.5 契约中登记为缺口）。

### 3.8 训练执行协议（必须遵守）

1. **前置检查**：`wsl_stability_check.ps1 -Heavy` exit=0；否则先完成宿主整改（§6.1）。
2. **受限运行**：`wsl_guarded_run.sh --mem 16G --name <stage>-<arch>-s<seed> -- python …`；每 run 留 cgroup 采样证据（`outputs/ops/wsl_stability/cgroup/…/cgroup_summary.json`）。
3. **顺序执行**：同一时间只跑 1 个训练进程；GPU 显存目标 ≤2.5 GB；batch 8 + 梯度累积，OOM 则减半 batch。
4. **checkpoint**：每 epoch 存 `last.pt` + `best.pt`；中断从 last 续跑；不删除既有 run 目录。
5. **记录**：`experiment_registry.csv` 必须含数据集版本/哈希、config_hash、code_hash、seed、参数量、epochs、best_epoch、train_seconds、device、weights_sha256、checkpoint_path。
6. **失败分类**：`failure_taxonomy.csv` 记 `oom / timeout / nan_loss / state_bug / missing_dep / data_missing`；不得伪造指标。
7. **阶段末**：`wsl_reclaim.sh` + `wsl --shutdown`；产出阶段报告并登记台账。

## 6. 风险与应对

### 6.1 B1 宿主内存（最高优先级，阻塞 M3）

- 现状：commit 限额 71.1 GB、余量 10.8 GB、页面文件 8.2 GB @ C:、WSL 空闲页缓存可能再涨。
- 整改（需管理员 + 重启）：页面文件迁 D: 固定 24–32 GB；C: 清盘 ≥30 GB；巡检计划任务；整改后 `wsl_stability_check.ps1 -Heavy` 必须 exit=0。
- 训练侧兜底：`--mem 16G` cgroup、顺序执行、阶段间 `wsl --shutdown`、每 3–4 run 回收一次。

### 6.2 GPU/算力

8 GB GPU 共享桌面占用后仅 ≈3.8 GB 空闲；对策：小批量 + 梯度累积、单进程、`torch.cuda.max_memory_allocated` 记录、必要时 CPU 跑 M10（Neural ODE）等小模型并标注 device。

### 6.3 数据与标签

`v_C` 缺失（Classic 残差需另派生）、Scaffold/Size-OOD 无现成标签、xTB 对齐未完成、confirm 封印不可触碰 —— 全部列入 V5.5 契约缺口清单，未解决项在报告中显式声明，不得用伪标签补齐。

### 6.4 实现简化

M07 xLSTM / M09 LTC / M10 Neural ODE / M12–M14 SSM 均为简化小结构（`CORE_META.simplified=true`），结论只能表述为"该简化实现的收益"，不得外推为原论文规模结论。

### 6.5 进度

按 M2→M3 串行推进；每阶段 No-Go 时先修基础设施再继续，不用"多跑几轮"掩盖问题。

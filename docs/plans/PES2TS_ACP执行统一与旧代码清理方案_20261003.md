## 1. 一句话目标

把 PES2TS 内所有计算化学后端（xTB PATH、ORCA scan/constraints/NEB、continuation）**统一改为经 ACP 执行**，**删除本地引擎代码**，并让 ACP 标准产物/日志/manifest 支撑可视化；191k 旧产物只读不动。

---

## 2. 本次修复在整体开发流程中的定位（重点）

### 2.1 主干定位

```
G0 数据底座 ✅ ── G1 图审计/成键统计 🔶 ── G2 PES generation 🔶（当前）
                                                  │
     G2 子阶段：2.0 端点装配 ✅ · 2.1 方法选择/计划冻结 🔶 · 2.2 执行 🔶 · 2.3 回收+质量 🔶 · 2.4 执行统一 ⬅ 本次 · 2.T 24条 🔶
                                                  │
G2 退出条件：24 条在"统一体系"下跑通 + ≥1 严格验证 TS
```

- **这是 G2.4「执行统一」的实现**，即把 Track A（本地 xTB PATH）与 Track B（ORCA 实验层）收口到**同一个 ACP 执行体系**。
- 它**取代 ADR-0001 的 X1–X4 机制**（本地封装 → ACP 编排），但**保留其执行接缝**（`ExecutionBackend`/`TrajectoryRecord`）。见 ADR-0002。
- 它同时并入 **C 工作流的清理动作**（删本地引擎、归档一次性脚本、移除 cccp 依赖）。

### 2.2 开发序列定位（P0–P8）

| 序 | 阶段 | 与本方案关系 |
|---|---|---|
| P0 | C 收口 | **前置**：迁移（G-R 布局）必须先提交；一次性脚本清理并入本方案 |
| P1 | G1 收口 | 边界合同 + 24 条复核放行；提供 `g1_v2_export`（plan/materials 来源） |
| **P2** | **G2 接缝** | **本方案主体**：原 X0–X2 重定义为 X1′–X3′ |
| P3 | G2 攻坚 | R0–R4（质量）可交错推进；正式 QC 实验依赖对应 ACP 梯度/约束/验证能力 |
| **P4** | **G2 收敛** | **本方案收尾**：X4′–X5′（ORCA/continuation 全迁 + 默认切换） |
| P5 | G2.T | 前置条件：G2.4 完成（统一体系） |
| P6–P8 | G3 | 下游，不受影响 |

### 2.3 里程碑定位

- 本方案是 **M-B「统一生成」判据**（"一个执行体系；等价证书绿"）的实现载体。
- 它是 **M-C「G2 退出」的前置**（P5 的 24 条必须在统一体系下跑）。
- 不影响 **M-A**（收口）、**M-D/M-E**（规模化/排序）。

### 2.4 依赖与阻塞关系

```
G-R 迁移提交(P0) ─▶ 本方案 X1′..X5′ ─▶ G2.T(24条) ─▶ G2 退出
G1→G2 边界合同(P1) ─┘（提供 plan/materials 字段）
R 工作流(P3) ◀── ACP 梯度/约束/验证能力；科学质量与 X 共同阻塞 G2 退出
```

- **阻塞**：无 G1 边界合同 → 无法定 plan/materials 的字段来源；无迁移提交 → 无干净对照基线。
- **被阻塞**：G2 exit 与 M-B 均等本方案。

## 4. 目标架构

```
ExecutionBackend（协议·传输无关·保留）
        ▲
XtbPathACPBackend(method="XTB_PATH")
   ├─ build_path_request(plan, materials)     # 配方归 PES2TS
   └─ ACPTransport.submit(...)                # ACP CLI 子进程
              │
         ACP: run XtbPathSearch --path-config
              │
      RESULT/result_manifest.json(v2) + pes_profile_v2 + trajectory
              │
   PES2TS 解析(xtb_output) + 判定(inspect)  →  g2_path_v1（schema 不变）
              │
       可视化桥：登记为 ACP 任务（job_id）→ Workbench /s2/profile
```

关键原则：**配方 PES2TS 拥有；判定 PES2TS 保留；执行 ACP 承担；AOP 只校验不补默认值。**

## 5. 等价性证书（替代"逐字节一致"）

| 证书 | 做法 | 通过判据 |
|---|---|---|
| **RecipeEquivalence** | 比对"发给 ACP 的 `path.inp`+argv+`--gfn`/`--uhf`/电荷/多重度/线程/超时"与"旧冻结配置生成值" | 逐字节相同 |
| **ReplayParity** | 用历史存档原始轨迹喂新解析+判定管线 | `frames.parquet` 与 `reaction_path.json` 与当年本地产物逐字节相同 |
| 化学分布等价 | N 条对照反应双跑（ACP 新跑 vs 历史） | 通过率/帧数/势垒分布在容差内（验收指标） |

产物：`equivalence_report.json`（随对照子集冻结）。规则：**永不比较两次真实运行的原始输出。**

## 8. 可视化桥（因选择 CLI 而必须单独处理）

- **现状**：CLI 执行不产生 `task_id`、不进 jobs 库 → Workbench `/api/v1/jobs/{id}/s2/profile` 解析不到。
- **方案**：在 CLI 执行后追加"登记为 ACP 任务"。
  - 首选：ACP CLI 增 `--register`/`--job-id`，在 jobs 库落一条记录指向该 WORK/RESULT；
  - 备选：PES2TS 调 ACP `/api/v1/jobs` 的"导入/附着外部运行"接口；
  - 兜底：仅文件级查看（不达 Workbench 目标，需明确接受）。
- **判据**：X5′ 结束时，Workbench 能用真实 `job_id` 渲染一条 xTB PATH 的帧/能量曲线。

## 9. 迁移与安全策略

1. **永不迁移/重跑 191k**；本地 runner 删除后，旧产物 + `xtb_output.py`/`inspect.py` 充当回放 oracle。
2. **对照子集**：从旧产物挑固定子集做 RecipeEquivalence + ReplayParity，产物冻结为 `equivalence_report.json`。
3. **迁移门**：旧本地实现仅作冻结对照/历史回放依据；正式新 QC 走 ACP。对应 ACP 能力与证书通过后再删除 runner，不出现先删入口却没有可运行替代的中间发布。X5′ 默认 ACP。
4. **提交纪律**：先提交 G-R 迁移 → 本方案分阶段小步提交（每阶段门通过后提交）。

## 附录 A：共享请求 schema `pes2ts_xtb_path_request_v1`（冻结）

两侧实现的唯一对齐契约。PES2TS 生成并发送；ACP `XtbPathSearch` workflow 接收并忠实执行，**只校验不补默认值**。

```jsonc
{
  "schema_version": "pes2ts_xtb_path_request_v1",
  "reaction_id": "RXN_0000000001",
  "source": {
    "source_type": "xyz_text_pair",
    "start_xyz": "<map 升序 start.xyz 文本>",
    "end_xyz":   "<map 升序 end.xyz 文本>",
    "charge": 0,
    "multiplicity": 1
  },
  "recipe": {
    "path_inp_text": "$path\n   nrun=1\n   npoint=50\n   anopt=10\n   kpush=0.003\n   kpull=-0.015\n   ppull=0.05\n   alp=0.5\n$end\n",
    "gfn_level": 2,
    "uhf": 0,
    "threads": 4,
    "timeout_seconds": 1800,
    "seed": null,
    "extra_args": []
  },
  "provenance": {
    "plan_sha256": "<str|null>",
    "config_digest": "<str>",
    "request_sha256": "<str>",
    "adapter_version": "pes2ts_xtb_path_request_v1"
  }
}
```

**规则**
- `recipe.path_inp_text` 为**字面 `$path` 文本**，ACP 原样写入 `path.inp`（RecipeEquivalence 的比对对象）。
- ACP 必须**无条件**传 `--gfn <gfn_level>` 与 `--uhf <uhf>`（含 0）；`seed` 非 null 且二进制支持时才传；`extra_args` 原样追加。
- `request_sha256` = `sha256(canonical_json({schema_version, reaction_id, source, recipe}))`（排除 `provenance`，因其含派生值）。ACP 在 RESULT 回显该值。
- **ACP 输出契约**：`RESULT/result_manifest.json`（v2，`workflow="XtbPathSearch"`，`status="completed"`）+ 产品 `pes_profile`（`RESULT/pes_search/pes_profile.json`，schema `pes_profile_v2`）+ 逐帧 `RESULT/pes_search/path_frames/path_frame_%03d.xyz` + 原始轨迹 `RESULT/pes_search/xtbpath.xyz`（供 PES2TS ReplayParity 解析）。
- **失败**：ACP 以非零退出或 `status!="completed"` 表达；PES2TS 映射为 typed 失败，绝不静默部分成功。
- 该 schema 变更需同步 `adapter_version` 并新增 ADR 记录（不得原地改写已冻结计划）。

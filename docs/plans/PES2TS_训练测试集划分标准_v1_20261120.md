## 0. 结论速览

划分不是"一次随机 train/test split"，而是**一条四层继承链 + 一套封存纪律**：

1. **L0 数据集官方划分**（G0，reaction 级，199,168 条：train 159,355 / valid 19,904 / test 19,909，DRFP 泄漏审计 `leak_status="clean"`）是所有下游的父划分，**不可重写**。
2. **L1 预测器父划分**（`pesn_irc_split_v1`：`train_fit` 121,363 / `train_dev` 15,161 / `train_calibration` 15,159 + 整族封存 `family_holdout` 9,573）在**父 train 内、以 canonical reaction group 为单位**再分 80/10/10，并与父 valid/test 一起把评估面封住。
3. **L3 战役层**把 L1 的 `train_fit` 变成**可训练池**（2k ⊂ 5k ⊂ 20k ⊂ 50k 嵌套前缀）、`train_dev` 变成**冻结 dev**（589 曲线）、`train_calibration` 变成 **confirm（仅列名、从不建表、从不读取）**。当前唯一生效的划分文件是 `split_manifest_v53mp.json`（schema `v53mp_split_v1`）。
4. **L4 run 内层**：每个 seed 在 tier 池内**按曲线**做 80/20 inner-train / inner-val；inner-val **只用于选 checkpoint 和校准 `tau_end`**，不是测试集。

**数据来源一句话**：原始数据是**公开的**（Zenodo 记录 18551029，6 个文件 / 12.15 GB / 有 MD5+sha256），任何人可自行下载复现；但**划分产物与训练数据是"本地资产、不入库"**（`outputs/**` 全量 gitignored，`data/` 只入库 `manifests/*.json`）——所以**队友同步的关键不是"传仓库"，而是按 §6.4 的可获得性矩阵决定"重生成 / 传小 manifest / 传大表"**。

### 0.1 60 秒口头同步版

> ① 官方 split（train/valid/test）只是**父划分**，我们只增不改，从不重写。
> ② 训练只用父 train 里再切出来的 `train_fit`，按 sha256 排名扩成 2k/5k/20k/50k **嵌套池**，扩量只能加前缀，不能换池。
> ③ 评估只有一套 **dev（589 曲线，一次性）**；`confirm` 2,000 条**永封、从未启封**；父 valid/test 也从未在预测器侧用过——所以现在**不能**对外说"测试集指标"。
> ④ 一条红线：划分单元永远是 reaction group / curve，**不按帧随机拆**；选模型只用 inner-val，阈值（`tau_end`）只在 inner-val 校准后冻结。
> ⑤ 数据：原始 6 个文件从 Zenodo 下（`g0 fetch` 自动校验 MD5），其余全部由命令重生成；`outputs/` 不入库，要传就传 manifest + SHA，别传整目录。

## 2. 各层定义与冻结规则

### 2.1 L0 数据集官方划分（G0）

- 来源：Reaction-QM（Zenodo 18551029 rev1）作者自带的三份 split CSV；`g0 split` 采纳、`g0 freeze` 定稿。
- 单位是**单条 reaction_id**；`g0 dedup` 另外识别精确重复/逆向对（`duplicate_ledger.json`），`g0 audit` 用 DRFP 做跨 split 近重复审计。
- 记录事实（[split_manifest.json](../../data/manifests/split_manifest.json)）：`leak_status="clean"`、`frozen=true`、`counts.total=199,168`、`covered=199,168`、`n_not_in_split=0`、`n_split_only=673`、审计 `complete=true`、`max_similarity=0.8571`（阈值 0.90）、`n_pairs_over_threshold=0`、`n_cross_split_known_duplicates=0`。
- 纪律：**不重写**。补救只允许 `--remediation {none,exclude-leaky,rebuild}`；发现泄漏而默认不补救即 HALT（退出码 7），审计不完整拒绝冻结（退出码 8），补救未达干净即恢复补救前状态（退出码 9）——见根 README 退出码表。

### 2.2 L1 预测器父划分（`pesn_irc_split_v1`）

生成器：[pes2ts_core/pesn/offline/splits/freeze.py](../../pes2ts_core/pesn/offline/splits/freeze.py)；调用 `python -m pes2ts_core.pesn split --config config/pesn/g3_p1.yaml`（该配置 `seed: 42`、`dev_fraction: 0.10`、`calibration_fraction: 0.10`、`family_holdout_fraction: 0.05`）。

规则（与实现逐条对应）：

1. **只在父 `train` 内选**：`parent_train = {rid | assignment[rid]=="train"}`；三子集全部成员必须属于父 train（否则 `SplitFreezeError`）。
2. **单位是 canonical group**：`build_groups()` 用 `duplicate_groups.json` 与 canonical members 合并正逆反应、映射/对称副本；组内全部成员同进同出。
3. **整族封存 `family_holdout`**：按族（G1 v2 `l0u_undirected_family` 标签，读 `data/interim/g1_v2/classes/<shard>/<rid>.json`）用 `sha256(f"{seed}:{family_id}")` 排序抽 **5%**，整族全部组封存。该抽样在**全库分组**上做，因此 holdout 成员可能落在父 valid/test 里；它同时会被从训练侧候选组中剔除。
4. **冲突隔离**：跨 split 的组不静默移动，进入 `isolated_conflicts`（本次 2 条），并从所有子集剔除 → manifest `known_group_cross_split_conflicts=0`（G3.P.0 硬门）。
5. **开发暴露**：`development_exposure` 记录历史已暴露组（本次 `contamination=true` 但 id 列表为空，即无新增暴露组）。
6. **比例**：dev/calibration 各 10%（对 `eligible_groups` 取整后分配），其余进 `train_fit`；family holdout 5%。
7. **封存面**：父 `valid` / 父 `test` / `family_holdout` 三者不进任何训练子集，等模型与门冻结后由隔离评测器使用。旧 valid/test **不得**移回 train。

派生事实（`split_summary.json`）：`{train_fit: 121,363, train_dev: 15,161, train_calibration: 15,159}`，`family_holdout_reactions=9,573`，`isolated_conflicts=2`。

下游继承：[dual_ts_split.py](../../pes2ts_core/pesn/offline/splits/dual_ts_split.py) 把 v1 成员原样继承为任务角色，**不重新随机**：

| v1 子集 | 继承角色 | v1 前缀选择 |
|---|---|---|
| `train_fit` | `fit` | `direct_fit50` / `direct_fit500` / `direct_fit2000` / `direct_sac_fit12` |
| `train_dev` | `monitor` | `direct_monitor8` |
| `train_calibration` | `test` | `direct_dev8` |

> ⚠️ **命名陷阱（同步时最容易说错的两条）**
> 1. v1 里叫 `direct_dev8` 的 8 条曲线，角色是 **`test`**，存放在 `train_calibration` 子集里。不要按字面把 "dev8" 当开发集。
> 2. `train_calibration` 的继承角色是 `test`；到 V5.3-MP 之后改称 **`confirm`**。因此 **`train_calibration` = `confirm` = 最终确认集**，三者是同一个东西的三代叫法。

### 2.3 L2 V5 冲刺 5 折（仅在 fit50 上，历史）

- 生成器：[v5_fold.py](../../pes2ts_core/pesn/offline/splits/v5_fold.py)，`main --write` 才落盘；schema `pesn_v5_split_v1`，`seed=20261018`。
- 做法：fit50 的 50 个 direct-fit 组先按 `duplicate_groups` + lineage 绑定做 union-find 合并（组件不可跨折），再按 (family, size bucket) 分层、以 `sha256(f"{seed}:{root}")` 排序做「最小折优先」分 5 折。
- 封存：**fold 3/4 = confirm 封存**，fold 0–2 = dev 侧；manifest 断言 `components_single_fold / folds_pairwise_disjoint / group_fold_unique / confirm_sealed / ood_sealed`。
- 规模（V5.3-MP 计划 §3 记录的当时口径）：50 曲线 / 6,017 节点 / 12,034 样本，dev 30 / sealed 20。
- 状态：**只对旧 fit50 有效**。50K 数据不使用这套 5 折，**两者不可混用**（见 §2.4 fold 表）。

### 2.4 L3 战役 cohort 与 50K `split_manifest_v53mp.json`（当前生效）

**第一步：冻结 cohort**（[r3_v53mp_freeze_cohort.py](../../scripts/agent_ops/data_gate/r3_v53mp_freeze_cohort.py)）

- 输入：S0-A 的 `eligible_reactions.parquet`（带 `subset` 列，取值即 L1 三子集）+ 父 split 的 sha256 钉死。
- 排序：`sha256("v53mp:cohort:20261021" + ":" + canonical_group)` 升序，**逐组**排序 → 扩池是**严格前缀扩展**。
- 三类名单：`pool_candidates`（来自 `train_fit`；20k 建库取 26,000 = 1.3× 余量，50k 建库取 65,000）、`dev`（来自 `train_dev`，目标 600）、`confirm`（来自 `train_calibration`，列 2,000，**只列名**）。

**第二步：池冻结 + 写 split manifest**（[r3_v53mp_finalize.py](../../scripts/agent_ops/data_gate/r3_v53mp_finalize.py)）

- `subsets.pool` = frozen pool 的**嵌套前缀** tier：`2k ⊂ 5k ⊂ 20k ⊂ 50k`；tier 只在池够大时才写出（20k 建库只有前三档，50k 建库四档齐全）。
- `subsets.dev` = **跨 tier 共享的同一套 dev 曲线**（50k tier 直接复用冻结 dev 与 dev pack，使 2k→5k→20k→50k 的差异可归因）。
- `subsets.confirm` = id 列表，`rules` 明写「仅列名，从未读取或建库」。
- `curve_folds`：**已建曲线的 fold = 该曲线在名单中的位置 `% 3`（0/1/2）；confirm 记为 fold 4**。
- `counts`：`pool_qualified / pool_20k（= 冻结池，两个名字同值）/ pool_overflow_unqualified_or_margin / dev / confirm_listed_never_built`。
- 冻结块：`frozen: true`、`seed_key`、`parents`（cohort / g3p1_split / s0a 三者 sha256）。

**当前生效参数**（[pes2ts_v543_dual_decoder_50k.yaml](../../config/campaigns/pes2ts_v543_dual_decoder_50k.yaml) `data:` 块；V5.4.1/V5.4.2 同源）：

```yaml
data:
  tables_dir: /pes2ts_data/v53mp_50k_data
  split_manifest: /pes2ts_data/v53mp_50k_data/split_manifest_v53mp.json
  pool: 50000
  dev: 589
  confirm: 2000
  confirm_policy: sealed_never_read
```

**fold 语义必须分清（两层不同）**：

| | V5 冲刺 fit50（L2） | 50K 战役（L3） |
|---|---|---|
| fold 0–2 | dev 侧 | 所有**已建库**曲线（pool 与 dev 都在内） |
| fold 3 | confirm 封存 | **未被使用**（保留位） |
| fold 4 | confirm 封存 | confirm（未建库，仅占位） |
| 隔离靠什么 | fold 3/4 | **`subsets` 名单**（pool/dev/confirm 三张 id 表），**不是 fold** |

两条推论：

1. 50K 数据里 **dev 曲线同样是 fold 0–2**，与 pool 曲线同折；dev 不进训练靠「它不在 `subsets.pool` 里」。
2. `CONFIRM_FOLDS_V53MP = {3, 4}` 是**防御性并集**（对两代数据都成立）；50K 数据上 fold 3 无使用者。看到 fold 3 不是数据错误，也别以为 fold 0–2 就"可以随便训"。

### 2.5 L4 run 内层切分（inner-train / inner-val）

- 唯一实现：`v53mp_pool_split(samples, pool_curve_ids=<tier>, seed=<run seed>, inner_val_fraction=0.2)`。
- 做法：tier 池内**按曲线 id 字符串排序**后以 `np.random.RandomState(seed ^ 0x5EED53)` 洗牌，取前 20% 曲线作 inner-val；**曲线级互斥**，不按帧切。
- 三重 typed refusal：池为空（`POOL_EMPTY`）、池内曲线 <2（`SPLIT_CURVES`）、池内出现 confirm fold（`CONFIRM_POSITIONS`）。
- 用途边界：inner-val **只**用于 checkpoint 选择（`inner_val_loss`）与 `tau_end` 校准（按目标 precision 取最小阈值，冻结进 checkpoint）；`train_q_mean`、endpoint `pos_weight` 等统计量**只从 inner-train** 估计（`derived_from_dev=false`）；inner-val 指标**不进**科学结论表。
- 样本上限：V5.4.3 配置 `inner_val_max_samples: 8192`。

## 4. 硬规则清单（做 / 不做）

**必须（Do）**

1. 拆分单元一律是 **canonical reaction group / curve**，组（曲线）内全部帧、全部 intent 方向同分区；**禁止帧级随机拆分**。
2. 扩池只能**嵌套前缀**（2k ⊂ 5k ⊂ 20k ⊂ 50k，同一 rank 序列），一次冻结后不换池；报告必须写明用的是哪个 tier。
3. 选模型/调参/校准阈值**只能**用 inner-train + inner-val；报告必须声明 `tau` 来源是 `checkpoint_best.pt#tau_end_calibration`。
4. 评估必须先冻结再读取：先写 freeze/绑 SHA，再读 dev；每次 dev 访问向 dev 账本追加一行（`audits/dev_access_ledger.jsonl`、repo 根 `audit/dev_rollout_access_ledger.jsonl`）。
5. 报告必须带**分母证据**：positions / move-eligible / curves 三个计数 + `positions_sha256` + `curves_sha256`，与冻结值**逐位相等**（不等即 `DEV_DENOMINATOR_MISMATCH`，判失败而非降级重跑）。
6. 依赖真值的读取必须走审计访问器（R1）；划分本身只用元数据与 L1 成员表，**不读** TS/IRC 真值。
7. 数据交换只走"**manifest + SHA**"（小）或"**显式索取的大表 + sidecar 校验**"，不手工改大文件、不 `git add -f`（[outputs/README.md](../../outputs/README.md) 明令）。

**禁止（Don't）**

1. 禁止重排既有划分（`不重新随机拆组`，ADR-0023 / dual_ts_split 规则 a–e）。
2. 禁止用 dev / confirm / family_holdout / 父 valid/test 做早停、选参、调阈值、换 seed、选候选（R6）。
3. 禁止把 confirm 建进六表、做特征、算 dev pack，或以任何 split 名不等于 `dev` 的方式请求评估（`CONFIRM_ACCESS_REFUSED` / `CONFIRM_POSITIONS`）。
4. 禁止把 fit 内部 dev 的筛选结论当外部泛化或部署证据。
5. 禁止改写历史冻结件：改划分只能新增版本 + schema + 父 hash 绑定，旧产物保持原身份。

## 5. 四种"测试集"的区别（最容易被问错的地方）

| 名称 | 层 | 规模 | 是否已使用 | 能回答什么问题 | 不能回答什么 |
|---|---|---|---|---|---|
| **父 valid / 父 test** | L0 | 19,904 / 19,909 reaction | **否**（预测器侧从未用于训练或评估） | 未来"作者口径外部测试" | 现在不能说"已通过官方 test" |
| **family_holdout（排族）** | L1 | 9,573 reaction（整族） | **否**（仅封存；尚无冻结评测协议，见 §8-5） | 族外推（unseen family）泛化 | IID 环境下的性能 |
| **confirm** | L3 | 2,000 id（fold 4） | **否，永封** | 最终一次性确认（须单独授权） | 任何当前结论 |
| **dev** | L3 | **589 曲线**（135,926 positions） | **是**（一次性纪律：V5.4.1 记 WP1 + WP7、V5.4.3 记 T7，逐条见 dev 账本） | 候选/冠军的冻结评估与复现 | 二次调参、再选一个候选 |
| **inner-val** | L4 | 20% 池曲线/seed（cap 8,192 样本） | 是（选 checkpoint、校准 tau） | 选模型是否收敛 | 不作为科学结果上报 |

> **pack 身份提醒**：同一 589 曲线在不同特征视图下会得到不同的 dev pack SHA（V5.3-MP 证书 `4d84b611…`；V5.4.x 冻结视图 `4f6c1e95…`）。**分母口径按 campaign 绑定**，跨 campaign 比指标前先确认 pack 一致（V5.4.3 报告 §6 已记该冲突）。

手工下载后请把文件放到 `data/raw/reaction_qm/` 并自行核对 §6.1 表的 MD5；缺 manifest 或哈希不符时下游命令会以退出码 3（校验不符 / 上游产物缺失）拒绝，不会静默继续。

### 6.2 下载与校验语义

```bash
conda run -n pes2ts python bin/pes2ts g0 fetch
conda run -n pes2ts python bin/pes2ts g0 fetch --force   # 强制重下
```

行为要点（据根 README 与 `pes2ts_core/g0/fetch.py` 契约）：

- 1 MiB 分块流式写 `<name>.part-<pid>`，**MD5 校验通过后**才 `os.replace` 落盘 → 中断/损坏永不产生可用文件、也不留 `.part` 残留。
- 本地 MD5 已匹配则跳过 → 重跑下载 0 字节（幂等）。
- 只有**六件全部核验通过**才写 `source_manifest.json`；任一 MD5 不符 → **退出码 3**，不留 manifest。

> 队友只需 `g0 fetch` 一条命令即可完成"下载 + 校验 + 登记"，无需 ACP、无需 GPU、无需真值权限。

### 6.3 派生落位与真值隔离（下载之后数据去哪）

```
data/raw/reaction_qm/            ← 4 个 CSV（reaction_info + train/valid/test）留在原地
data/ground_truth/sources/       ← 2 个 HDF5 被 g0 quarantine 物理搬入（真值隔离）
data/ground_truth/ts.parquet     ← 提取出的 TS 几何（仅经审计访问器可读）
data/ground_truth/irc_index.parquet ← IRC 序号（形状型，不含帧）
data/interim/**                  ← inventory / fingerprints / 分类 / g1_v2 文档（hundreds of MB，本地）
data/manifests/**                ← 小 manifest（唯一入库面）
```

- `g0 quarantine` 把两个真值 HDF5 **搬迁**（不是复制）出 raw 树，并提取 `ts.parquet` 与 `irc_index.parquet`；约 9.3 GB 的 IRC 帧**永不复制**。
- 真值只允许经 `pes2ts_core.g0.truth.truth_reader`（`allow_truth=True` + 每次写 `truth_access_log.jsonl`）读取；静态 AST 守卫覆盖 `pes2ts_core/` 与 `bin/`。
- 后果：**任何一次未登记的 out-of-band 读取都不被日志观察到**——因此"传数据"本身就是一次需要纪律的动作（见 §6.5）。

### 6.7 从零复现顺序（新人 onboarding）

**A. 数据底座（G0 → G1，只需 CPU）**

1. `python bin/pes2ts g0 fetch` —— 下载 6 件并校验（§6.2）。
2. `python bin/pes2ts g0 inventory` —— 反应信息 join HDF5 R/P 物种 → `inventory.parquet`。
3. `python bin/pes2ts g0 quarantine` —— 提取 TS/IRC 索引并把 2 个 HDF5 搬入 `data/ground_truth/sources/`（**此后 raw 树不再能重跑 inventory**，见根 README 的 `run-all --force` 警告）。
4. `python bin/pes2ts g0 dedup` → `g0 audit`（DRFP 泄漏审计）→ `g0 split`（采纳官方划分）→ `g0 freeze`（按泄漏决策定稿）→ `g0 cohorts`（试跑/分层 cohort）。
   - 等价一键：`python bin/pes2ts g0 run-all`（幂等；`--skip-fetch` 只核验不下载）。
5. G1（生成 L1 排族所需的族标签与图先验）：`python bin/pes2ts g1 --help` 起，按其子命令建 `data/interim/g1_v2/**`（**L1 freeze 依赖 `g1_v2/classes/` 里的 `l0u_undirected_family`**）。

**B. 划分（L0 已定 → L1 → L3）**

6. L1：`python -m pes2ts_core.pesn split --config config/pesn/g3_p1.yaml`
   → `outputs/pesn/g3_p1/splits/pesn_irc_split.json` + `split_summary.json`
   → **立刻核对** `subset_sizes = {train_fit: 121363, train_dev: 15161, train_calibration: 15159}`、`family_holdout 9573`、`冲突隔离 2`（不符即说明 G1/父 split 版本不同，**不要继续**）。
7. L3 第一步 S0-A（元数据资格，**不读原始真值**）：`scripts/agent_ops/data_gate/r3_v53mp_s0a_qualify.py` → `outputs/pesn/v53mp/s0a/{metadata_qualification.json, eligible_reactions.parquet}`。
8. L3 第二步 cohort：`scripts/agent_ops/data_gate/r3_v53mp_freeze_cohort.py`（50k 用 `--pool-candidate-target 65000`）→ `outputs/pesn/v53mp/cohort/v53mp_cohort_v1.json`。
9. L3 第三步建库（S0-B，**授权真值提取，逐次记账**）：`scripts/agent_ops/data_gate/r3_v53mp_build_tables_h5.py all`。
10. L3 第四步 finalize（池冻结 + tier + fold + 报告 + S0 门）：

    ```bash
    python3 scripts/agent_ops/data_gate/r3_v53mp_finalize.py \
        --data <六表目录> \
        --cohort outputs/pesn/v53mp/cohort/v53mp_cohort_v1.json \
        --s0a outputs/pesn/v53mp/s0a
    ```

    → `<六表目录>/split_manifest_v53mp.json`（20k 建库时 `<六表目录>` 为 `outputs/pesn/v53mp/data`；50k 建库另加 `--pool-target 50000`）。
11. L3 第五步特征/索引/证书：`r3_v53mp_build_dev_pack.py`（dev pack）、`r3_v53mp_build_idx_v2.py`（惰性索引）、`r3_v53mp_build_geometry_pack.py`（几何分片）；再用 `r3_v53mp_dev_pack_certificate.py`、`r3_v53mp_startup_certificate.py`、`r3_v53mp_loader_v2_certificate.py`、`validate_r3_tables.py` 出证。
12. 进训练前检查：`split_manifest_v53mp.json` 的 `subsets.confirm` 与六表**零交集**（confirm 从未建库），`config` 里 `confirm_policy: sealed_never_read`、`allow_confirm_access: false`。

> 全部脚本的**参数以各自 `--help` 为准**（本表只给角色与已验证的 finalize 用法）；每一步的产物都要落 `*.sha256sidecar.json` 或 manifest，否则不可审计。

## 8. 已知缺口与待对齐项（同步时逐条确认）

1. **本文件不是规范。** 仓库没有"划分标准"的规范位：规则分散在 G3-P1 计划 §2.4、ADR-0023/0026、MoveProcessContract、各战役方案与代码里。要成为强制标准须按 AGENT.md §7.2 出 ADR 并在宪法登记。
2. **划分真身几乎都不入库。** `outputs/**` 整体 gitignored（[outputs/README.md](../../outputs/README.md)），所以 L1 `pesn_irc_split.json`、L3 cohort、`split_manifest_v53mp.json`、sidecar 全是**本地资产**；队友只能"重生成 + 对数字"或"向持有者索取"。这是当前同步的最大摩擦点，建议为这三件指定一个**内部制品库 / Release 资产**位。
3. **split manifest 文件名三代并存**：G0 的 `split_manifest.json`、30h 计划的 `split_manifest_r3.json`（`r3_table_schema.py` 已记录该文档不一致并优先取 r3 名）、实际使用的 `split_manifest_v53mp.json`。建议下一版预注册给一张"别名 → schema → 生效范围"表并钉死。
4. **fold 语义两代不同**（§2.4 表）：5 折时代 fold 3/4 = 封存；50K 时代只有 fold 4 = confirm，fold 3 空置，隔离靠 `subsets` 名单。跨代看数据必须换读法。
5. **父 valid/test 与 family_holdout 的最终评估协议未冻结**：谁在什么时候评、报什么指标、分母怎么钉，目前只有"封存"这一条。这是当前最大的**口径**缺口。
6. **计数口径常见误解（已澄清）**：`121,363 + 15,161 + 15,159 = 151,683` 是**父 train 的子集**；`159,355 − 151,683 = 7,672` 是父 train 中落在 `family_holdout`（5% 抽样在**全库分组**上做，跨三份 split）、`development_exposure`、以及 2 条冲突隔离组里的组，**不是**缺失数据（该 7,672 为算术推断，构成未逐项登记）。`family_holdout 9,573` **不是**父 train 的 5%，不能与三子集相加当 161,256 的总训练面。
7. **dev 600 → 589 的 11 条差额没有逐条原因登记**：cohort 的 dev 目标是 600，实际进入 dev 并建库的是 589（`curve_quality` 未覆盖的 dev 候选被静默滤掉）。建议 `finalize` 的 counts 补 `dev_candidates / dev_built / dev_dropped` 三栏。
8. **50K 六表无发布渠道、体积未登记**：数据本体在 WSL `/pes2ts_data/v53mp_50k_data/`，本仓既无副本也**没有总量记录**（应补 `du -sh` 实测）。跨机同步必须按 §6.5 清单走，且对方要有同等磁盘余量（≥10 GiB 余量约定）。
9. **dev pack 双身份**：`4d84b611…`（V5.3-MP 证书）与 `4f6c1e95…`（V5.4.x 冻结视图）并存。跨 campaign 比较前必须声明用哪一个。

## 10. 不能声称的结论

- 不能说"已有可用的独立测试集跑出最终指标"：父 valid/test 未在预测器侧使用，confirm 从未启封，dev 是一次性评估集且已用掉（按 campaign 各一次，逐条见 dev 账本）。
- 不能把 dev 指标当泛化/部署证据；dev 与训练同源（同一 L1 父 train 内切分），只覆盖"同分布内泛化"。
- 不能把 `family_holdout` 的封存当"已通过族外推评估"——它目前只是把 9,573 条反应封起来，尚无冻结评测协议（§8-5）。
- 不能把 §9 的数字跨层混用：199,217 / 199,168 / 151,683 / 50,000 曲线 / 589 dev 曲线是**五个不同口径**。
- 不能用 inner-val 数字替代 dev 数字上报；也不能用 A seed 的 inner-val 解释 B seed 的 checkpoint。
- 不能说"仓库里有完整数据"：入库的只有小 manifest；原始 12.15 GB 与 50K 六表都是**本地资产**。
- 不能声称 §6.7 的复现链"已整体跑通验证"：本文只记录**既有实现与既有产物**的对应关系，未在本轮重跑任何一步。

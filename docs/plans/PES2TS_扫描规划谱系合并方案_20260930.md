## 1. 冲突定性

同一工作流（G1 规划 → 静态验证 → 冻结 → 执行）存在三份"面"：

| 面 | 内容 | 代表物 |
| --- | --- | --- |
| A · 旧谱系（2026-09-27/28） | 逐反应冻结候选树 + 关卡纪律 | `g1_scan_plan_v1`、`g1 v2-scan-plan/verify/freeze`、`data/interim/g1_v2/scan_plans/`、`orca_capabilities_v1.json`、G1-0…G1-7 |
| B · 新设计（2026-09-30） | 图论选择器 + 提案/计划分离 | `generation/planning/`（原 `scan_strategy/`）、`StrategyProposal`、`ExecutablePlan v2`/`GenerationPlanV2`、P0–P3 |
| C · 实现现实 | 已落地的边界与产物 | v2 gate 到 `export_contracts_v1`（183,460）；`planning.py` 最小规划器；ACP 适配器单距离限制（恰 2 原子、等间隔、3–101 点、≤4 坐标） |

三面归一的必要性：CLI、产物路径、schema 任一维度出现两套名字，都会让下游（G2 / ACP / worker 会话 / 后续规划）被迫理解并行机制。

## 2. 合并原则

1. **单一面纪律**：CLI / 产物 / schema 各只有一个名字族；
2. **版本语义**：新行为用新 schema 名；旧名登记被取代，不复用；
3. **只增不改**：`planning.py`、`adapter.py` 现行为逐字节不变，新能力走新模块/新函数；
4. **门控纪律沿用**：每一级都有 verify/freeze；`gate_pass=false` 时不得暴露看似可用的导出；
5. **谱系可追**：被取代关系写入仓库文档，不依赖会话记忆。

## 3. 裁决一：单面并轨（命名与接口映射，规划时必须原样固化）

| 领域 | 保留（旧约定） | 采用（新设计，g1_ 家族前缀） | 被取代登记 | 说明 |
| --- | --- | --- | --- | --- |
| CLI | `g1 v2-scan-plan` / `v2-scan-verify` / `v2-scan-freeze` | — | — | 不发明 `scan_strategy` 前缀命令 |
| 产物树 | `scan_plans/<shard>/<rid>.json`、`scan_inputs/`、`g1_v2_scan_plan_summary.parquet`、`data/manifests/g1_v2_scan_plan_manifest.json` | 新增 `scan_proposals/<shard>/<rid>.json` | — | 提案与冻结计划分树，同根 `data/interim/g1_v2/` |
| Schema | — | `g1_strategy_proposal_v1`（提案，允许 needs_review 输入，`execution_eligible=false`）；`g1_generation_plan_v2`（冻结执行计划；判别联合 `ScanCandidateV2 \| PathCandidateV1`） | `g1_scan_plan_v1` → `superseded_by g1_generation_plan_v2` | 兼容层从 `g1_generation_plan_v2` 导出旧单 B ScanPlan |
| 能力注册 | `orca_capabilities_v1.json` 文件名 | 注册表域（`effective_capability` 交集、`probe_receipts` 等） | — | 名称与内容分层合并 |
| 选边逻辑 | 混合选边 v1 的分析文档保留为证据 | 五规则降级为 `LOCAL_CONNECTIVITY` / `CONNECTIVITY_EXCHANGE` 的默认锚点策略，记录于 `rule_trace` | 独立"混合规则规划器" | 不再存在第二套选择机制 |
| 规划器代码 | `planning.py` 逐字节冻结 | `pes2ts_core/generation/planning/`（原 `pes2ts_core/scan_strategy/`；+ `g1/endpoint_graph.py`、`g1/reaction_edit_graph.py`） | `planning.py → planning/` 包迁移 = **deferred**，非本计划目标（G-R 迁移后已落位 `generation/planning/`） | 名称冲突按设计 §13.1 注释处理 |
| 规划人群 | — | **v2 `scan_ready`（183,460）** | — | v1 `g2_eligible`（191,148）维持 xTB-G2 现状，属独立决策 |
| 全图来源 | — | 由白名单输入（端点组件 + mapped reaction SMILES）在 `generation/planning/`（原 `scan_strategy/`）内重建 R/P 完整键图 | 不扩展冻结的 v2 export；不读内部 edits 结构 | 保持"导出=冻结、算法=上层"分层 |
| 真值防火墙 | `FORBIDDEN_TRUTH_KEYS` / 导出黑名单 | 新 schema 纳入同类测试 | — | 提案层允许 `endpoint_hypothesis` 元数据，零 TS/IRC 几何/能量 |

**被否决备选**：① 两套并存——第三规划面风险；② 并入 `g1_scan_plan_v1` 名——版本语义违规且提案层无位置。
**可逆细节**：schema 命名可在计划评审时微调（如 `g1_generation_plan_v2` 与 `g1_scan_plan_v2` 之争）；不可逆的是"单一前缀 + 版本递增 + 被取代登记"纪律。

## 4. 裁决二：验收口径

- **计划完成门槛 = 离线自动化**：fake ACP 子进程（沿用 `_fake_acp(tmp_path)` 模式）+ 合成 fixture。P0 门（Demo24 逐条对照）、P1 门（单 B 无损通过现有 ACP）离线达成。
- **真实冒烟 = 分阶段显式 gated 门槛**：
  - pytest marker：新增 `acp`（需 `PES2TS_ACP_ROOT` + ACP python）、`orca`（需 `PES2TS_ORCA_EXECUTABLE`）；`xtb` 已存在；
  - **never-skip 语义**（沿用 `tests/test_g2_xtb_smoke.py` 先例）：显式调用且环境缺失时响亮失败，绝不静默跳过；默认套件继续排除；
  - **阶段认证语义**：P0/P1 离线门通过即"落地"；P2 的 ORCA 冒烟与 P3 的 NEB 冒烟为显式 gated task——环境未就绪记 `blocked`（附确切需求清单），不阻塞代码与计划落地，但对应 stage 的认证状态保持未完成；"未冒烟不得产出 ready 计划"红线不变。
- **需要项目方提供的环境资源**（可先记 pending）：ACP 根目录（`.../ACP_V1_20260811`）、ACP 环境 python、ORCA 安装（版本入能力注册表）。

## 5. 统一阶段阶梯（G1-0…7 ↔ P0…P3）

| 统一级 | 组成 | 验收门 |
| --- | --- | --- |
| **L0 前置** | G1-0 上游安全放行（已实现：`export_sanitize.py` + `v2-sanitize-exports` + `export_contracts_v1`）→ 只做闭合验证：重跑 v2-verify + gate、记录摘要 | `verify.problems=0`、`gate_pass=true`、导出无 IRC 派生字段 |
| **L1 = P0** | EndpointGraphBundle + 归一化 + 三层图（ΔG / 上下文 / 事件耦合）+ 特征（并入 G1-2） | Demo24 逐条证据对照；每编辑恰一事件归属或明确共享；零真值字段 |
| **L2 = P1** | 单坐标选择器 + 双方向 + 全编辑监测 + 旧单 B 兼容导出 + 能力注册 baseline + verify/freeze CLI 骨架（并入 G1-3 部分 / G1-4 单 / G1-5 单 B） | 单 B 无损通过现有 ACP（离线）；错误输入有原因；拒绝合同 |
| **L3 = P2** | COUPLED/SCHEDULED + 多坐标编译与逐帧全驱动回收 + 能力注册全量 + 目标质量层（并入 G1-3/4/5 全量） | 每 driver 每帧可追踪；未支持能力显式拒绝；gated ORCA 冒烟 |
| **L4 = P3** | Path/NEB 协议 + 分段新版计划 + 四个结果层级 + 试点锁版（含 G1-7；verify/freeze 纪律贯穿 L1–L4） | NEB/Scan 分开计成本；24 条逐例闭环（依赖人工复核）；200–1000 分层试点 |

## 6. 放行条件（三项修正）

1. 计划必须固化 §3 命名映射表为"接口承诺"节；
2. 计划必须包含"谱系登记"任务：旧方案文档头部已加并轨注记（本方案落地时同步完成），防止未来会话复活第三面；
3. 计划必须写入 §4 的 gated 约定（marker / env / never-skip / blocked 语义）。

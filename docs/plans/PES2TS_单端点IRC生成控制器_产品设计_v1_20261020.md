## 0. 一页结论

用户的想法是对的：

> 既然 A–TS–B 是一条完整、可逆的曲线，模型应当能够从任意一端出发，生长出整条曲线，并在过程中确定 TS 和另一端。

但“直接学习整条曲线”不能理解成“输入 A，输出一整条曲线”。IRC 不是 A 的静态函数，而是**当前势能面（PES）上的最小能量路径**。正确产品形态是：

\[
\boxed{
\text{单端点 IRC 生成控制器}
=
\text{局部生长策略}
+
\text{物理松弛}
+
\text{停止判据}
+
\text{端点/TS 验证}
}
\]

模型负责**提议下一步方向、步长、是否停止、可能的产品图**；物理后端负责**梯度/能量/约束松弛**；验证器负责**TS/IRC/端点身份**。

产品必须支持三种模式：

| 模式 | 输入 | 输出 | 难度 |
|---|---|---|---|
| **Known-B Growth** | A + 目标 B 图 | A→TS→B 路径、TS | 中 |
| **TS-only Growth** | A + 反应中心约束 | A→TS 路径、TS 候选 | 中 |
| **Unknown-B Discovery** | 仅 A | Top-k 产品候选、路径、置信度 | 高 |

**不要承诺唯一产物。** 同一 A 可能有多个竞争通道、构象、立体选择性；产品应返回**排序后的候选集 + 置信度 + 验证状态**，而不是强行给一个 B。

## 1. 问题定义

### 1.1 输入

必需：

```text
X_A          起点三维结构
G_A          起点合法拓扑（元素、键级、电荷、多重度）
method       理论层级/方法（xTB/DFT）
budget       最大 QC 调用数/步数/墙钟
```

可选：

```text
G_B          目标产物图（Known-B）
reaction_center / K  反应中心约束
target_TS    已知 TS 候选（仅验证模式）
```

禁止作为在线输入：

```text
历史 IRC 帧、未来帧、参考 TS 坐标、教师标签、IRC progress
```

### 1.2 输出

```json
{
  "path_id": "...",
  "mode": "known_b",
  "start": {"xyz": "...", "graph": "..."},
  "nodes": [
    {"xyz": "...", "graph": "...", "energy": 0.0, "grad_norm": 0.0,
     "arc_length": 0.0, "step": 0.05, "accepted": true}
  ],
  "ts": {"xyz": "...", "verified": true, "imag_freq": -123.4},
  "end": {"xyz": "...", "graph": "...", "matched_target": true},
  "stop_reason": "ts_verified | target_matched | budget | stagnation | low_confidence",
  "confidence": 0.0,
  "cost": {"qc_calls": 0, "wall_time_s": 0.0},
  "verification": {"irc_connected": true, "endpoint_identity": true}
}
```

### 1.3 成功定义

分三层，不能混：

1. **生长成功**：路径连续、每步物理松弛、无几何/拓扑非法；
2. **TS 成功**：一阶鞍点、一个虚频、虚频模式指向反应方向；
3. **IRC 成功**：从 TS 双向下降连接 A 与 B（Known-B）或连接到合法极小点（Unknown-B）。

产品报告必须分别给出三层状态，不能把“生长到高能点”称为 TS。

## 2. 为什么不是“输入 A，输出整条曲线”

### 2.1 IRC 由 PES 定义，不由 A 唯一决定

IRC 是质量加权坐标中的最小能量路径。给定 A，路径取决于：

- 方法/泛函/基组；
- 电荷/多重度；
- 溶剂/环境；
- 竞争通道；
- TS 构象。

一个静态 seq2seq 模型输出整条曲线，很容易生成**不在当前 PES 上的几何**。必须让物理后端在环内松弛和验证。

### 2.2 曲线长度、节点数、分叉数可变

不同反应的 IRC 弧长、帧数、中间体数量差异很大。固定长度输出会：

- 对短路径过参数化；
- 对长路径截断；
- 无法表示分叉/多路径；
- 无法表示“未知产物”的不确定性。

### 2.3 误差会累积

单步预测的误差会在长 rollout 中累积。闭环控制器可以在每一步用能量/梯度/几何约束纠正，静态曲线模型不能。

### 2.4 Unknown-B 是组合问题

从 A 确定 B，需要决定：

- 哪些键断/成；
- 键级变化；
- 质子/电荷转移；
- 环化/开环；
- 立体化学。

这不是一个连续回归能可靠解决的；需要**图编辑提议 + 排序 + 物理验证**。

### 2.5 正确分解

```text
静态整曲线模型：A -> (X_1,...,X_n)        # 容易幻觉
闭环控制器：    A -> policy -> physics -> accept/rollback -> stop -> verify
```

模型是**提议者**，物理是**裁判**。

## 3. 产品形态

### 3.1 三种模式

#### Mode 1：Known-B Growth

用户给出 A 和目标 B 图。控制器从 A 出发，生长到 TS，再到 B。

用途：

- 已知反应的 IRC 生成；
- 反应机理验证；
- TS 搜索初始化；
- 训练/评估的主模式。

#### Mode 2：TS-only Growth

用户给出 A 和反应中心约束（哪些键可能变化），不要求 B。控制器生长到 TS 候选并停止。

用途：

- 只知道反应物、不知道产物；
- TS  поиск；
- 机理解释。

#### Mode 3：Unknown-B Discovery

用户只给 A。控制器：

1. 提议可能的键编辑/产物图；
2. 对每个候选生长；
3. 验证/排序；
4. 返回 Top-k 路径与端点。

用途：

- 产物预测；
- 新反应发现；
- 多通道探索。

**这是最高风险模式，必须最后做。**

### 3.2 CLI/API 草案

```bash
# Known-B
pes2ts grow \
  --start A.xyz --topology A.json \
  --target B.json \
  --method xtb --max-steps 40 --budget 200 \
  --out path.json

# TS-only
pes2ts grow \
  --start A.xyz --topology A.json \
  --reaction-center K.json \
  --stop-at ts \
  --method xtb --out ts_path.json

# Unknown-B
pes2ts discover \
  --start A.xyz --topology A.json \
  --top-k 5 --method xtb --budget 500 \
  --out candidates.json

# Verify
pes2ts verify \
  --path path.json --method xtb \
  --out verify.json
```

### 3.3 产品边界

- 不承诺唯一产物；
- 不承诺低能路径一定是最低能垒路径；
- 不把 proxy 能量/代理模型结果称为 IRC；
- 所有成功必须经过独立验证；
- 失败/未验证/预算耗尽必须显式返回，不能静默过滤。

## 4. 系统架构

```text
                    ┌─────────────────────┐
                    │  State Encoder      │
                    │  SE(3)-equivariant  │
                    │  geometry + graph   │
                    └─────────┬───────────┘
                              │
              ┌───────────────┼────────────────┐
              │               │                │
      ┌───────▼──────┐ ┌──────▼───────┐ ┌──────▼────────┐
      │ Growth Policy│ │  Stop Head   │ │ Endpoint Head │
      │ direction/   │ │ Move/No-Move │ │ graph edits   │
      │ step size    │ │ TS candidate │ │ (Unknown-B)   │
      └───────┬──────┘ └──────┬───────┘ └──────┬────────┘
              │               │                │
              └───────────────┼────────────────┘
                              │ proposal
                    ┌─────────▼───────────┐
                    │  Trust Region /     │
                    │  Validity Guard     │
                    └─────────┬───────────┘
                              │
                    ┌─────────▼───────────┐
                    │  Physics Backend    │
                    │  xTB/DFT gradient   │
                    │  constrained relax  │
                    └─────────┬───────────┘
                              │ accepted node
                    ┌─────────▼───────────┐
                    │  Path Memory        │
                    │  nodes/tangent/     │
                    │  energy/force/budget│
                    └─────────┬───────────┘
                              │
                    ┌─────────▼───────────┐
                    │  Stop / Endpoint    │
                    │  Check              │
                    └─────────┬───────────┘
                              │
                    ┌─────────▼───────────┐
                    │  Verifier           │
                    │  TS opt + IRC       │
                    │  endpoint identity  │
                    └─────────────────────┘
```

### 4.1 State Encoder

输入：

- 当前几何 \(X_t\)；
- 当前拓扑 \(G_t\)；
- 起点图 \(G_A\)；
- 可选目标图 \(G_B\)；
- 路径记忆：前 2–3 个节点、切线、弧长、能量、梯度、预算；
- 反应中心 mask。

输出：

- 节点嵌入；
- 边嵌入；
- 图级 summary；
- 切线/路径上下文。

要求：

- SE(3) 等变；
- 对 A/B 命名交换不变（Known-B 模式下 A/B 是对称的）；
- 不读未来/参考 TS。

### 4.2 Growth Policy

输出：

- 方向（低维内坐标或 key-atom Cartesian）；
- 步长；
- 可选：局部信任域缩放；
- 可选：多个候选方向/模式。

第一版建议：

```text
动作 = 反应中心低维内坐标增量（键长/角/二面角）
     或 key-atom Cartesian 位移 + step size
```

不要第一版就输出全原子坐标。

### 4.3 Stop Head

输出：

- Move / No-Move；
- stop_score；
- TS candidate score；
- 可选：距离 TS 的 proxy。

监督：

- 接近 TS 窗口的帧；
- 真实 TS 邻域；
- 终点极小点（Known-B）；
- 失败/预算耗尽（非停止）。

**No-Move 是“曲线停止位置选择”，不是普通不确定性拒绝。**

### 4.4 Endpoint Head（Unknown-B）

输出：

- 键编辑候选（断/成/键级变化）；
- 候选产物图；
- 每个候选的置信度；
- 电荷/质子转移候选。

训练：

- 从 IRC 端点对提取图编辑；
- 多产物/多通道标签；
- 不强迫唯一 B。

### 4.5 Physics Backend

职责：

- 当前节点能量/梯度；
- 约束松弛（固定推进方向/切向）；
- 信赖域；
- 几何合法性；
- 失败回滚。

模型只提议，物理决定是否接受。

### 4.6 Path Memory

保存：

```text
nodes, graphs, energies, gradients,
tangents, arc_length, step_sizes,
accepted/rejected, budget, visited_hashes
```

用途：

- 切线更新；
- 避免循环；
- 停止/回滚；
- 训练时的历史观测；
- 评估路径质量。

### 4.7 Verifier

职责：

- TS 优化；
- Hessian/虚频；
- 双向 IRC；
- 端点图同构/RMSD；
- 方法/电荷/多重度一致性。

**没有 Verifier，不允许称成功。**

## 5. 控制器状态机

```text
INIT
  -> ENCODE
  -> PROPOSE (direction, step, stop?)
  -> VALIDATE (trust region, geometry, graph)
  -> RELAX (physics)
  -> CHECK (energy/force/accept)
  -> ACCEPT / ROLLBACK
  -> UPDATE MEMORY
  -> STOP? (stop head / target match / budget / stagnation)
  -> VERIFY (TS/IRC/endpoint)
  -> OUTPUT
```

### 5.1 每步伪代码

```python
state = encode(X_t, G_t, G_A, G_B, memory)
proposal = policy(state)
if stop_head(state).stop:
    return stop_and_verify()
proposal = trust_region_clip(proposal)
X_prop, G_prop = apply(proposal)
if not valid(X_prop, G_prop):
    rollback(); shrink_step(); continue

X_relaxed, E, g = physics.relax(X_prop, G_prop, tangent)
if not accept(E, g, X_relaxed):
    rollback(); shrink_step(); continue

memory.add(X_relaxed, E, g)
if target_matched(G_relaxed, G_B) or ts_candidate(E, g):
    return verify()
if budget_exhausted() or stagnated():
    return fail("budget"/"stagnation")
```

### 5.2 回滚与信赖域

- 最大步长按方法/体系预注册；
- 失败时缩小步长，不重置 episode；
- 连续失败 N 次 → stop with reason；
- 不允许无限重试；
- 所有失败计入成本。

### 5.3 循环检测

- 图哈希/几何哈希；
- 弧长停滞；
- 能量/梯度震荡；
- 重复访问节点；
- 触发回滚或停止。

## 6. 动作空间

### 6.1 Known-B / TS-only

第一版建议：

```text
反应中心低维内坐标：
  键长变化、键角、二面角
或 key-atom Cartesian 位移 + step size
```

优点：

- 维度低；
- 物理可解释；
- 易于约束；
- 与 V5/R3 的 key-atom 输出兼容。

### 6.2 Unknown-B

需要两级动作：

```text
高层：图编辑（断键/成键/键级/质子转移）
低层：几何生长（方向/步长）
```

高层用离散候选 + 排序；低层用连续策略。

### 6.3 不要第一版做全原子坐标

全原子输出：

- 维度高；
- 容易生成非物理几何；
- 难以约束；
- 数据效率低。

## 7. 训练路线

### 7.1 Phase 0：R3 局部策略

- 端点对称特征；
- 单步位移；
- 无 stop；
- 目标：H1/H2/H3。

R3 是控制器的**局部动作先验**，不是完整产品。

### 7.2 Phase 1：Known-B 单步 + Stop

- V5.2 合同；
- Move/No-Move；
- Known-B；
- 仍不 rollout 整条路径。

### 7.3 Phase 2：Known-B 单端生长

- 路径记忆；
- 多步 rollout；
- 物理松弛；
- 停止/端点验证；
- 训练：behavior cloning + scheduled sampling + path-level loss。

### 7.4 Phase 3：Unknown-B Discovery

- Endpoint Head；
- 图编辑候选；
- Top-k 排序；
- 多路径验证；
- 需要更多反应数据。

### 7.5 Phase 4：物理修正 / RL

- V6 xTB 修正；
- V7 cost-aware RL；
- 奖励：严格成功、路径质量、QC 成本、停止正确性。

### 7.6 训练目标

#### Behavior Cloning

```text
L_bc = L_step + λ_stop L_stop + λ_endpoint L_endpoint
```

- `L_step`：下一步位移/内坐标；
- `L_stop`：Move/No-Move；
- `L_endpoint`：图编辑候选（Unknown-B）。

#### Path-level

```text
L_path = L_endpoint_match
       + λ_ts L_ts
       + λ_energy L_barrier
       + λ_smooth L_smooth
       + λ_cost L_cost
```

#### RL

```text
r_t = β * success
    - λ_c * QC_cost
    + η * progress
    - λ_l * loop/stagnation
    - λ_f * invalid
```

只在 BC/物理闭环稳定后启用。

## 8. 数据合同

### 8.1 路径级样本

```text
path_id, canonical_irc_id, method, charge, multiplicity,
start_endpoint, end_endpoint,
nodes[], energies[], gradients[], graphs[],
ts_index, ts_verified, irc_verified,
source, data_quality_status
```

### 8.2 方向规范化

- 所有路径统一为“起点 → TS → 终点”；
- 从 B 端出发的训练样本反向；
- A/B 交换增强；
- 不把 TS 同时作为两个相反“向外动作”的普通 MOVE 样本。

### 8.3 Split

- 按 canonical IRC / near-dup component 分折；
- 不按帧分折；
- 同一路径的所有节点、两个方向、所有 d0 在同一折；
- 训练/评估端点身份隔离；
- 失败/替代路径单独标记。

### 8.4 数据量

- Known-B / TS-only：50 反应可做 pilot；
- Unknown-B：50 反应远远不够，需要扩展；
- 需要失败路径、竞争通道、不同方法；
- 扩展前必须过 S1 数据质量门。

## 11. 风险

| 风险 | 处理 |
|---|---|
| 模型幻觉路径 | 物理松弛 + 验证器，禁止直接接受 |
| 多产物歧义 | Top-k + 置信度，不承诺唯一 |
| 误差累积 | 闭环 + 回滚 + 信赖域 |
| 数据不足 | 先 Known-B/TS-only，后 Unknown-B |
| 停止标签稀少 | 预注册 stop 窗口，软标签 |
| QC 成本高 | 预算、缓存、代理模型分层 |
| 方法迁移 | 单列方法层级，不混 PES |
| 评估泄漏 | canonical IRC/path-level split |
| 过度承诺 | 三层成功分开报告 |

## 12. 产品验收

最小可用产品（MVP）：

- Known-B；
- 单端生长；
- TS 验证；
- 路径/成本/停止原因输出；
- 失败显式返回。

MVP 不包含：

- Unknown-B；
- 多产物发现；
- RL；
- 全自动机理解释。

MVP 成功标准：

```text
在预注册 Known-B 测试集上，
端点到端点成功率、TS 验证率、IRC 连接率
均显著优于线性插值/随机生长基线，
且 QC 成本可接受。
```

---

## 13. 一句话

**不要把“整条曲线”当成一个静态输出；把它做成“单端生长策略 + 物理松弛 + 停止/端点验证”的闭环控制器。** A/B 对称意味着控制器不应依赖 branch；从任一端出发都应得到同一条路径（反向等价）。Unknown-B 是更高阶的发现模式，必须晚于 Known-B 和 Stop Head。

## 1. 新方向的核心判断

**PES-G 与 PES-R 可以收敛为一个共享价值学习核心的两种使用方式：内部用于选择动作、保留候选和决定何时交接；外部用于比较已有候选。**

这认可“搜索本身具有排序属性”的判断。对内部生成，不再把“走完路径 → 调用独立学习排序器”当作必须的目标架构。对外部路径或候选池，保留显式排序入口，复用同一价值核心。

但不把生成动作、搜索价值和候选精修价值强行定义成同一个无条件标量。建议将用户所说的“距离 TS”操作化为：

> 在给定目标反应、计算方法、精修协议和剩余预算下，当前结构或下一动作对获得严格目标 TS 的预期价值。

项目的拟议表述为：**PES2TS 通过共享的目标条件价值模型，在真实 QM 反馈下选择几何推进、识别可精修候选并决定交接时机；同一模型也为外部候选提供排序。**

PES-C 保留为规则控制和数据生成基线；PES-G 是闭环搜索模式；PES-R 是外部候选评价模式及独立评测接口。G/R 名称可以继续兼容历史使用，不要求建立两套独立模型、标签体系或产品。

## 2. “距离 TS”需要澄清的三层含义

| 含义 | 能否直接承担统一核心 | 主要限制 |
|---|---|---|
| 到某个参考 TS 的几何 RMSD/内坐标距离 | 不建议作为主目标 | 在线不知道参考 TS；同反应可能有多个有效 TS；几何近不保证可精修性 |
| 到目标精修成功域的接近程度 | 可作为任务化解释 | 成功域依赖 preparation、OptTS、验证方法和预算，并非普适固定几何集合 |
| 获得严格目标 TS 的成功概率、剩余计算成本与决策价值 | 建议作为主定义 | 需要可信标签、成本记录、条件化与校准，不能由一个预测步长直接得到 |

初期输出建议是成功概率 p、预期成本 C、适用域/不确定性及组合效用 U；不急于把它们压成“几 Å 的 TS 距离”。

若论文中采用“学习距离”，可以定义为明确条件下的代价或价值变换，但注明：不一定对称、不保证三角不等式，也未必沿路径单调下降。目标应表示成满足 H 的一组可验证结果，不能默认为某一参考 TS 坐标。

例如，结构 A 与某个参考 TS 几何很近，却具有错误的氢伙伴；结构 B 几何较远，但冻结精修器能够稳定将其收敛到正确 TS。此时候选价值应允许 B 高于 A。这是概念示例，不是本项目实测结果。

另一个关键区别是“现在精修”和“继续搜索”：一个结构可能适合继续推进，但现在交给 OptTS 容易回到极小值；另一个结构可能没有多少继续探索价值，却已是很好的精修初猜。共享模型需要区分这两个任务条件。

因此，以下量不直接等价：

- actor 输出的动作概率；
- 预测步长的大小或位移范数；
- 当前状态继续搜索后的长期价值；
- 当前几何立即精修的成功概率。

纯模仿策略只输出 Δq 时，并没有自动得到可信的绝对候选分数；要实现用户设想，需要显式训练价值/交接估计，或使用有清晰语义的动作价值模型。

## 3. 一个核心、两种入口

### 3.1 内部：价值引导的闭环生成

~~~mermaid
flowchart TD
  H[目标反应、端点映射与允许事件] --> S[当前接受结构、QM反馈、历史、预算]
  S --> V[共享价值核心]
  V --> A[合法动作选择：下一坐标目标]
  A --> O[ACP → ORCA完整约束优化]
  O --> Q[公共质量与化学验收]
  Q -->|接受：更新结构与观测| S
  Q -->|拒绝：几何不变，更新历史和成本| S
  Q -->|合格真实帧| M[在线候选保留与去重]
  M --> V
  V -->|交接决策| P[SeedProposal：当前帧或已保留帧]
  P --> F[ACP严格精修与验证]
  F --> L[隔离标签与评测]
~~~

模型每步参与三项决策：下一动作、本帧是否值得保留、当前是否值得交接。接受/拒绝仍由公共规则及物理证据决定，模型评分不越权。

在线候选档案保存少量高价值且有差异的已接受帧，避免最后一帧越过有利区域后丢掉较好的历史初猜。所有原始帧和尝试仍按现有全量留数原则归档；“少量”只约束在线决策档案。

这一档案是搜索状态的一部分，使用同一价值核心，不再是生成结束后启动另一套 PES-R。若最终证明当前帧交接已足够，可进一步简化档案；不在没有证据时假设最后一步总是最优。

交接时生成既有数据链中的 PathBundle/SeedProposal，可来自有效前缀；无需等 λ=1。达到计划目标、交接精修、无候选终止和严格验证成功分别记录。

### 3.2 外部：已有路径/候选的显式排序

~~~mermaid
flowchart TD
  A[外部扫描、NT2、RMSD-PP、NEB或候选几何] --> B[身份、方法、单位和质量适配]
  B --> C[观测编码：同一特征定义与缺失掩码]
  C --> V[共享价值核心：现在精修的价值]
  V --> R[排序、去重与预算内候选选择]
  R --> P[SeedProposal]
  P --> F[同一ACP精修与严格验证]
~~~

外部模式没有 PES2TS 搜索时保存的动作、历史和在线分数，因而需要显式评价已有点。这个入口继续称 PES-R 即可，其核心是共享价值函数的批量调用，而不是另造一个与 PES-G 无关的学习目标。

共享权重不代表直接跨方法可用。外部方法来源、能量/梯度、是否带偏置、是否约束驻点、历史缺失及分布差异都要进入适配和评测。需要时使用同一核心的来源校准或缺失兼容版本，版本差异显式记录。

### 3.3 “任意势能面”的可支持输入范围

| 用户输入 | 可交付能力 |
|---|---|
| 同一反应的几何候选/轨迹，含元素、映射、电子态、方法和目标 R/P/H | 资格检查后评价与排序，必要时经 ACP 补物理特征 |
| 只有几何，无能量/梯度/历史 | 使用经训练验证的缺失兼容模式，或补算并计费 |
| 低维 PES 网格，且每个点可映射回完整结构 | 先提取有限候选，再评价；不需要遍历无限连续 PES |
| 只有能量曲线图片/无结构绑定的数值 | 只能做曲线候选分析，不能直接输出可提交的严格 TS 初猜 |
| 有结构但没有目标反应定义 | 可另定义通用候选任务；不能报告“目标 TS 成功概率” |
| 不同反应或方法的候选混在一起 | 各自条件化和校准；不按原始总能量或未经校准的分数直接全局排序 |

当前首版仍以已放行 F/B 和电子态范围为准。外部入口不因为叫“任意 PES”就承诺所有元素、反应、电子态或多步机理。

## 4. 统一模型的数学语义

本节给出设计形式，不宣称当前已实现 Bellman 求解或最优性保证。

令 z 是结构及可用观测，H 是目标事件条件，ρ 是冻结的 preparation/OptTS/频率/IRC/端点协议，b 是剩余预算。对外部候选和内部真实帧共用：

\[
p_\theta(z,H,\rho,b)=
P(\text{直接交给协议 }\rho\text{ 后，在 }b\text{ 内得到严格目标 TS}),
\]

\[
C_\theta(z,H,\rho,b)=
\mathbb E[\text{该次精修与验证实际消耗，含失败和超时}],
\qquad
U_\theta=p_\theta-\eta C_\theta/C_{\rm ref}.
\]

这里的成功域属于具体协议；换 DFT 方法、准备层约束或预算，评分条件也改变。成本用冻结的标量预算单位定义效用，报告仍保留梯度数、核时、墙钟等向量，不能把 xTB 与 DFT 的一次梯度当成同价。

C 估计此刻之后的追加成本；已经发生的生成费用留在总账本并影响剩余预算，不在每个候选评分中重复扣除。用于比较的候选还要保留各自原方法/电子态身份，不能因共用评分器而混成同一物理状态。

内部完整搜索状态 s 包括当前 z、历史、事件状态、剩余资源以及候选档案 M。定义两类动作：

1. continue(a)：施加合法内坐标目标，执行一次真实受约束优化并验收；
2. handoff(i)：结束本次生成，将已合格候选 i 交给冻结精修协议。

于是候选排序可写成动作价值的一个切片：

\[
Q_\theta(s,M,\mathrm{handoff}(i),b)=U_\theta(z_i,H,\rho,b).
\]

继续推进的价值则包含一步计算代价及后续机会：

\[
Q^\pi(s,M,\mathrm{continue}(a),b)
=\mathbb E[-\eta c_a/C_{\rm ref}
+V^\pi(s',M',b-c_a)].
\]

拒绝也产生消耗和新历史，所以不能把拒绝视为零成本自循环。V 的估计依赖后续策略 π 及预算；如要写最优 V*，还需对允许动作取最优并具备相应求解证据，当前不作这种声明。

由此可以实现**同一评价核心驱动搜索和排序**，但 Q_continue 与 Q_handoff 的含义明确区分。学习实现可以采用共享编码器和动作条件评分，也可以采用共享编码器上的少量输出头；这些都是一个算法体系内的实现选择。

策略优先选择有价值的合法继续动作；当交接某个已保留候选的价值优于继续搜索，或预算达到预定交接条件时，输出该候选。首版用经过 train 校准且冻结的门限和最低证据要求近似比较，不把未校准 Q 的大小直接当作可靠停止依据。

外部排序只调用 handoff 分支；内部在线候选比较也调用同一分支。因此可以复用同一组权重、特征合同和标签，而不必建立独立后处理模型。

若一次允许多个精修尝试，初期在交接前冻结候选顺序、协议和预算，交给现有验证执行链；不要让验证失败结果回流当前生成策略。学习“验证后再重新导航”属于未来单独架构议题，会触及现有真值反馈边界。

## 5. 模型与反馈的实现路线

### 5.1 共享表征

首版采用事件级局部几何、实际内坐标与目标余量、角色/相位、相对能量、有效广义力、非驱动自由度响应、优化成本及历史拒绝。包含方法、电子态、来源类型与特征缺失掩码。

完整约束松弛后，自由梯度和约束残差通常已很小，不能只靠这两项区分候选或动作。也不把到产物的距离当成到 TS 的距离：越过 TS 向产物移动时，前者可继续下降。

外部候选缺历史时使用训练过的观测模式；不填虚假零值。内部历史编码用于继续动作，handoff 评价主要使用当前结构及可用局部上下文，这有利于外部复用。

### 5.2 价值如何产生下一步

仅有 U(X) 并不自动给出下一动作。需要在已冻结合法动作目录上建立联系：

- 开发教师阶段：对同一父状态试验有限合法动作，经真实 ORCA 松弛后，获得下一状态、资格和成本，构建动作价值或偏好标签。
- 部署阶段：模型在提交计算前预测动作价值或由蒸馏策略提出一个动作；选中的动作再经真实 ORCA 执行。
- 观察到真实结果后更新状态与在线候选评价，不用预测结果冒充实际优化帧。

首版不要求每步在线执行 K 次 QM 才选择一个动作，否则成本可能高于规则方法。有限 K 动作搜索可以作为明确计费的教师或独立在线方法基线。预测几何和价值均不能绕过帧验收。

如果用模型分数对坐标求梯度，它只是一种候选动作生成启发；分数梯度不是物理势能力，也不直接作为 ORCA 的替代优化器。本轮不建议优先走这条复杂路线。

### 5.3 在线候选与交接

每个合格接受帧保存 handoff 评分、模型/特征/协议版本、打分预算和几何 hash。档案使用同一核心维护价值和多样性，保留拒绝原因及替换记录。

同一候选在不同剩余预算下的价值可以不同。最终交接时以共同的剩余精修预算重新评价少量档案候选，或使用明确可比的固定预算评分；不能直接比较不同时间、不同预算下保存的分数。

这里的再评价是共享模型的一次轻量决策，不是重新扫描整个路径并引入另一套排序算法。是否值得维持档案大小 K、是否需要额外重评，均用消融决定。

不确定性可用于选择保守动作、回退规则或拒绝自动交接；普通模型方差不自动是可靠置信区间。模型校准和适用域检查属于评测任务。

## 6. 数据：一份状态—动作—精修证据体系

拟统一保存以下记录，但观测和标签物理隔离：

~~~text
ReactionCondition：端点、映射、H、方法与来源
ObservedState：真实接受结构、QM观测、历史、预算、观测可用性
ActionTransition：提议/执行动作、父子绑定、优化结果、验收与成本
CandidateValueEstimate：handoff预测、模型/协议/预算条件、适用域
HandoffDecision：继续/交接/放弃、档案选择、决策证据
RefinementOutcome：准备层和严格验证阶段结果、label_state、全量成本
~~~

以上为合同草案，正式名称/版本登记后才成为接口；不直接改现有 TrajectoryRecord、PathBundle、SeedProposal、ValidationResult 的字段语义。

### 6.1 训练目标

| 目标 | 数据来源 | 能声明什么 |
|---|---|---|
| handoff 成功概率与成本 | 隔离 train 候选的冻结精修/验证结果 | 当前帧在指定协议和预算下的精修价值 |
| 动作可行性、成本和局部响应 | 全部真实优化尝试及拒绝 | 下一动作执行难度，不等于严格 TS 成功 |
| 继续动作价值/偏好 | 有限教师动作与后续 rollout/隔离标签 | 特定教师覆盖和策略下的长期价值估计 |
| policy 蒸馏 | 合法动作及教师偏好 | 减少部署在线枚举，不保证教师全局最优 |
| 距离或进度辅助任务 | 有明确来源的 train 数据 | 辅助表征，不替代主成功/成本目标 |

不建议把“到轨迹被选中帧的帧数”当 TS 距离；采样密度、步长、方向和成功与否都会改变它。成功轨迹上的较早状态也不必具有较差的立即精修价值。不能强制所有真实路径的 handoff 分数逐步单调升高。

### 6.2 标签质量先于统一模型

沿用审核报告指出的优先问题：RMSD 端点匹配不足以完成身份判定，preparation 尚需完整接线，验证失败不能统一写成 verified_non_target。

任务结果“指定预算内未得到严格目标 TS”与化学标签“已验证非目标反应”是不同量。已执行到预算终点的尝试可提供操作性失败观测；未执行候选不构成负例；超时/删失和执行故障保留其原因，不冒充严格化学阴性。

为减轻旧选点策略带来的标签偏差，train 内按预定方案抽样验证不同价值区间、不同事件位置、成功/失败路径中的合格帧，并记录选择机制。不能只对高分候选做验证，再用这些标签证明模型可靠。

模型访问的新状态会偏离 Classic 数据；后续仅在 train 范围迭代采集，再冻结模型评测。family holdout、逆反应/邻帧/映射副本隔离和来源审计继续适用；静态与在线模式使用同一分裂版本。

## 7. 后续阶段的拟议重组

**开发主线建议改为：Classic 物理闭环 → 统一价值学习 → 价值引导生成与交接 → 外部候选适配扩展。**

这不意味着丢掉当前 Rank 的工作。固定候选池上的学习是共享价值核心最容易验证的入口，仍可先做；变化在于它不再作为与生成器独立发展的终点产品。

| 主干 | 建议任务 | 主要交付 | 出口证据 |
|---|---|---|---|
| G0/G1 | 保持数据、身份、映射和分裂基础 | 来源完整的反应条件与白名单 | 不因新模型放宽真值与适用范围 |
| G2 | PES-C、ORCA 原生约束优化、严格验证、在线规则候选档案 | 可回放 Classic 闭环；状态/动作/成本和真实标签 | 维持 24 可审计终态及 ≥1 非参考严格目标 TS 的既有出口 |
| G3.0 | 冻结 1000 输入漏斗与标签抽样 | 统一训练记录和失败/删失账本 | 帧数、标签数、成功输入数分列 |
| G3.1–3.2（拟调整） | 统一价值核心第一代，先学 handoff 价值并作静态评测 | 可校准 p/C、共享特征；PES-R 是该模型的静态使用方式 | 同候选池、同验证预算下优于强规则；适用域明确 |
| G4.0（拟调整） | 规则自适应与有限动作教师；建立 continue/handoff 关系 | 合法动作转移和成本数据；有限搜索证据 | 反馈确有价值，教师覆盖与成本完整 |
| G4.1（拟调整） | 共享价值驱动动作、在线候选保留与交接 | 冻结 PES-G；内部不强制独立后排序 | 固定验证器下，family holdout 的全流程收益 |
| G4.2（拟调整） | 联合优化与外部来源扩展 | 内部生成和外部候选两个入口 | 共享/独立模型对照，来源留出、负迁移检查及总成本证据 |

上表是针对阶段文件的修订提案，不在本次改写其现行出口。无需新增 G5 或另一套阶段编号。外部适配器可在共享模型静态评测期间开始最小开发，其广泛泛化验收后置；不能为了做外部产品阻塞内部生成研究。

PES-G 论文主线可以从第一代就围绕“价值引导的反应生成”组织；开发时先验证静态 handoff 分数，并不要求论文仍按两个独立算法叙述。

## 9. 模块与数据链迁移

本轮不迁移受保护目录、不新增执行后端。正式实施建议优先复用：

| 现有落点 | 后续职责建议 |
|---|---|
| generation/planning/continuation.py | 外层物理状态推进；调用统一策略和价值接口 |
| generation/planning/candidate_selection.py | Classic 规则基线及候选来源绑定；未来兼容在线候选记录 |
| generation/planning/gradient_evidence.py | 真实反馈编码，逐步解除仅依赖 λ 的斜率假设 |
| ranking/ | 外部输入适配、批量 handoff 评价和独立基准入口；不删除兼容 API |
| integration/acp/ | 单帧约束优化、preparation 与严格验证执行 |
| integration/validation.py、generation/campaign.py | 严格证据解释、原因分型和统一终态/成本 |
| evaluation/ 与既有数据飞轮 | 统一标签、分裂、静态/在线/外部评测 |

共享模型只有一份实现、配置、训练产物和特征定义，G/R 两入口通过同一公共接口调用。其实际目录在实施前按受保护布局登记；不分别在 generation/ 和 ranking/ 复制模型代码，也不为本次概念整理提前迁移目录。

原数据链仍可保持：

~~~text
ExecutionBackend → TrajectoryRecord → PathBundle → SeedProposal → ValidationResult
~~~

变化是 SeedProposal 可由搜索中的 handoff 决策产生，而非必由独立后处理排序器产生。来源可记录为 rule_posthoc、online_handoff 或 external_value_ranking；新语义通过新版本/绑定旁车登记。

拟新增的对象包括 ValueEstimate、HandoffDecision、ExternalCandidateSet；名称仅为草案。每个评分绑定目标条件、候选几何、观测可用性、模型/特征/校准版本、QC/精修协议、预算及来源。

## 10. 如何证明统一路线优于原分离路线

共享模型不等于所有任务自动相容。动作预测、长期价值和立即精修价值可能产生负迁移；推荐保留独立模型作为对照，按证据选择共享程度。

| 实验 | 固定条件 | 回答的问题 |
|---|---|---|
| 固定候选池：规则 vs 统一 handoff 价值 | 相同候选、方法、验证预算 | 价值是否能识别真正可精修候选？ |
| 规则生成 vs 学习生成 | 冻结 handoff 评价/交接门及验证器 | 下一步策略是否有效？ |
| 最后帧 vs 在线档案交接 | 同一已记录轨迹与同一评分版本 | 搜索是否仍需要保留历史候选？ |
| 内生交接 vs 独立后排序 | 在线对照冻结协议与总预算；另做离线同轨迹诊断 | 取消独立后排序是否损失覆盖或降低全流程成本？ |
| 共享核心 vs 分离 G/R 模型 | 尽量匹配数据、容量、调参和训练/QC预算 | 统一是否真的增益，是否出现负迁移？ |
| 去掉 QM 响应/历史/目标事件 | 其他条件不变 | 模型是否依赖有意义的闭环信息？ |
| 外部来源留出 | 冻结模型和输入适用域 | 自生成路径上学到的价值能否迁移？ |
| 整族留出与端到端评测 | 无真值预筛、同总预算和严格目标判据 | 是否具备科学泛化和实际效率？ |

主指标为全部冻结输入上的严格目标 TS 覆盖—总成本关系。另报固定候选池 Top-k、概率校准、误交接/漏交接、无效继续步数、外部拒绝率和成本预测误差。不能用模型分数上升、预测步长变小或候选自评分证明成功。

若在线提前交接改变了未来轨迹，不能把它与原来走完整路径的结果直接当同轨迹比较；区分离线重放诊断与实际在线策略实验。

取消后排序通常只能省去有限的推理/特征处理开销；主要潜在收益应来自减少无效 QM 推进、提前交接、减少失败精修。训练、教师枚举、特征补算和全部失败都计入，不能用“少一个模块”推算数量级加速。

初期实验冻结统一模型再比较 policy；后续才作共同训练/版本升级。共享权重若改变，同时影响生成和交接评分，应报告联合变更，不把收益全部归因给某一端。

## 11. 创新性与相关工作的更新

统一价值用于搜索与候选比较，在一般机器学习中已有基础，不能把“把 ranking 合并到 policy”本身作为首次创新。

MetricRL 已研究用度量学习近似目标条件价值并学习策略，其理论设定包含确定转移、可逆动作等条件。本项目的局部优化可能合并分支、产生拒绝和依赖历史，因此不能直接套用其度量或最优性结论。[MetricRL 作者论文](https://arxiv.org/abs/2402.10820)

TTGS 说明已有目标条件价值可支持搜索，同时讨论长期价值估计误差；它是一般目标导航的相关先例，不是化学 TS 证据。[TTGS 作者论文](https://arxiv.org/abs/2510.07257)

2026 年 SACTS 预印本已使用内坐标和量子梯度/曲率反馈作学习型 TS 搜索。PES2TS 的潜在差异需落到事件条件动作、完整约束松弛响应、统一的继续/交接价值、严格验证成本，以及外部候选复用等具体设计上。[SACTS 作者预印本](https://arxiv.org/abs/2607.10854)

建议凝练为以下可证伪研究主张：

> 一个目标反应条件下的价值核心，能够同时支持真实 QM 松弛反馈中的几何导航与已有结构的精修优先级判断，并通过在线交接在独立反应族上改善严格目标 TS 的覆盖—成本关系。

支撑它的关键证据是共享优于/不劣独立模型、反馈有用、外部迁移成立、全流程有收益。多输出头、价值函数、成本正则或模型名称本身均不足以证明强创新。

## 12. 规范影响、发布与下一份交付

本提案保持 R1–R6 的方向：真实 QC、严格物理标签、全量成本、合法动作和数据隔离。需要修订的是现有 G/R 组织和接口，不通过设计文档静默覆盖开发宪法。

| 文档/条款 | 拟修订内容 |
|---|---|
| 开发宪法 §1.3、§2.4 | G/R 作为共享核心的在线/静态模式，内部不固定 G→独立R 串行 |
| 开发宪法 §6–§7 | 区分 continue/handoff 条件价值；不再要求两个独立学习器 |
| 开发宪法 §6.3 | 目标成功域、有限 Oracle 证据及全输入分母，与前次审核建议合并处理 |
| 开发宪法 §9.5–§9.6 | 统一观测/标签和 ValueEstimate/HandoffDecision 的版本化登记 |
| 开发宪法 §10.2–§10.3 | 从独立 Rank→Gen 产品路线调整为价值先行、控制后接；里程碑按相应证据更新 |
| 开发宪法 §11.1 | 保留静态/生成独立诊断，并新增共享与交接的联合评测 |
| 阶段定义/完整开发流/Classic→Rank→Gen | G3 为共享价值基础，G4 为价值引导导航；G0–G4 编号和未完成状态保留 |
| AGENT.md、索引和修订台账 | 正式修订时同步投影与生效范围 |
| ADR-0006 与原生优化方案 | 保留控制/优化分离；后续正式调整其独立后排序假设 |

本次交付为本方案、Proposed ADR-0007、索引/台账及相关旧方案的后续指针。未启动计算、未删除 ranking 模块、未改生产默认、未重标历史产物；能力状态不升级。

下一份实施交付建议是：**G2 验证标签修补 + 原生约束优化接缝 + 规则版在线候选/交接记录**。这既解决当前科学证据缺口，也让后续统一价值模型从第一批数据开始拥有一致的状态、动作和精修标签。

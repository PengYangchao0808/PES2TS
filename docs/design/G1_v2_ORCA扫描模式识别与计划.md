# G1 v2：ORCA 扫描模式识别与逐反应计划

> 设计版本：2026-09-27。基于 ORCA 6.1/6.1.1 官方手册和当前 G1 v2 数据快照。本文是新的 G1→G2 责任合同：**G1 识别、参数化、验证并冻结每条反应的全部候选扫描计划；G2 只按计划运行、解析结果并按预先冻结的判据决定是否执行下一候选。** “全部候选”指能力注册表允许、输入可构造、预算内且有明确触发条件的有限计划，不意味着穷举连续势能面或预先保证每一种方法成功。

全量一维路径目标与 xTB/二维成本决策另见 [G1 v2：一维优先、xTB 与二维扫描的成本策略](G1_v2_一维优先与xTB二维成本策略.md)。

当前首选路由是**方向无关的成键锚点扫描**：键合锚点可为原始 R 或 P，从锚点拉伸及向锚点拉近均可作为预先规划的候选。选边采用 [多成键与少成键方向的混合规则](G1_v2_多成键与少成键方向对比.md)；[多成键锚点方案](G1_v2_方向无关成键锚点与双向扫描策略.md)保留为基线。早期[固定 P 侧方案](G1_v2_产物成键逆向扫描优先策略.md)仅作对照；下文七个静态候选族仍用于覆盖与失败统计。

## 1. ORCA 实际提供的计算模式

首先分清 **ORCA 原生计算原语**与 **PES2TS 的反应类别**。ORCA 没有“取代扫描”“开环扫描”等现成关键词；这些是我们从映射图和端点几何识别后，翻译成 ORCA 输入的项目级模板。

| ORCA 6.1 模式 | 原生控制量/输入 | 能做什么 | 在本项目的角色 |
| --- | --- | --- | --- |
| 松弛一维表面扫描 | `%geom Scan B i j` / `A i j k` / `D i j k l` | 每个设定点固定一个键长、键角或二面角，优化其余自由度 | 有独立、可定义局部坐标时生成 1D 路径 |
| 组合松弛扫描，网格 | 2 或 3 个 `Scan` 坐标，默认嵌套 | 得到 2D/3D 网格；若每维 10 点，3D 有 1000 次约束优化 | 仅限小规模研究/消融，不能作为全量默认 |
| 同步组合扫描 | 2 或 3 个坐标 + `Simul_Scan true` | 多个坐标按同一步号同时变化，成本接近一条路径；**不是**完整 2D/3D 曲面 | 协同成断键、H 转移双键长等路径候选 |
| `ScanTS` | 单个局部 `Scan` 后接 TS 优化 | 从扫描高能点及邻点启动 TS 寻优 | 仅局部单键或单角模式的后续验证候选；不能套在协同反应上 |
| 双端 NEB | `NEB`、`NEB-CI` 等，R/P 两端几何；`NEB-IDPP` 用于初始路径估计 | NEB/CI 优化图像链、估计最小能量路径；IDPP 本身不是已计算的 PES | 多编辑、非局部、无法选稳定 B/A/D 坐标时的主要双端模式 |
| 双端 NEB + TS | `NEB-TS`、`FAST-NEB-TS`、`LOOSE-NEB-TS`、`TIGHT-NEB-TS`、`ZOOM-NEB-TS` 等 | 路径搜索后继续 TS 优化 | 单列为更高成本的 TS 验证分支，不与纯路径有效率混报 |
| 多 XYZ 单点序列 | 多帧 `xyzfile` | 对**已经存在**的帧逐帧算能量/性质 | 路径补能量；不是路径搜索 |
| 参数化坐标/法向模式扫描 | `%coords` 参数范围；`NMScan` 需要 Hessian | 特殊几何参数或振动模式方向的采样 | 研发/特殊子集；当前 R/P+编辑记录不能自动给出可靠 Hessian 模式 |

松弛扫描的 B/A/D、最多三个坐标、网格与同步扫描的区别均见 [ORCA 6.1 Surface Scans](https://www.faccts.de/docs/orca/6.1/manual/contents/structurereactivity/optimizations_scans.html)。`ScanTS` 的官方适用范围是局部模式，见 [ORCA Transition State Searches](https://www.faccts.de/docs/orca/6.1/manual/contents/structurereactivity/optimizations_TS.html)。NEB 系列关键词与双端输入见 [ORCA Nudged Elastic Band Method](https://www.faccts.de/docs/orca/6.1/manual/contents/structurereactivity/neb.html)。[ORCA Semiempirical Methods](https://www.faccts.de/docs/orca/6.1/manual/contents/modelchemistries/semiempirical.html)明确列出通过 xTB 接口使用 GFN2-xTB 执行松弛扫描和 NEB；6.1 另提供原生 GFN2-xTB，实际组合仍需在目标安装上做最小输入兼容测试。**实际 ORCA 安装版本必须在执行前探测并与计划的能力版本匹配**；本机 PATH 目前没有检测到 `orca` 命令，因此这里未声称已验证输入可执行。

直接 `%geom Scan` 支持的原生坐标是 B/A/D。常用的 H 转移差值 `d(D,H)-d(A,H)` **不能直接写成单个原生 B/A/D Scan 坐标**；可用两个 B 坐标同步变化，或采用 NEB。多 XYZ、`ScanTS`、NEB-TS 的“扫描/路径/TS”产物必须分别标识。AIMD metadynamics 是自由能探索方法，不纳入这批固定 R/P 的默认扫描路线。

## 2. 当前反应在 G1 中的第一层归组

数据源为 `g1_v2_summary.parquet` 与每条 `g1_v2/edits/<shard>/<rid>.json`。仅统计审计状态 `clean` 的 183,460 条；`issues` 7,688 条进入复核，`excluded` 8,069 条保持排除。最终 G2 集合以 `v2-gate` 产出的 `g2_scan_ready.json` 为准。以下互斥归组按从上到下的**优先顺序**判定，属于静态候选族，不是已经确定可运行的 ORCA 模式。

| G1 初步候选族 | 判定要点 | 条数 | 候选 ORCA 模式 |
| --- | --- | ---: | --- |
| H₂ / H–H 特殊事件 | `hydrogen_partner_changes` 含 `to_hh` / `from_hh` / `hh_release` / `hh_form_free` / `hh_swap` | 6,538 | 几何验证后尝试 2–3 B 同步扫描；双端 NEB 备选 |
| 芳香/共轭区域耦合 | 有 `aromatic_regions`，且未被前项选中 | 4,986 | 寻找 ≤3 个独立几何驱动坐标；无法合理降维时用双端 NEB |
| H 转移 + 重原子变化 | 有 `transfer`，且另有重原子形成/断裂/键级变化 | 80,676 | 经几何验证的 2–3 B 同步扫描；双端 NEB 备选 |
| 仅 H 伙伴转移 | 有 `transfer`，没有重原子编辑 | 315 | 供体–H 与受体–H 两个 B 同步扫描；NEB 备选 |
| 单个重原子成/断键 | 无前述事件，恰有一个重原子 `formed`/`broken`，无重原子键级变化 | 180 | 1D B 候选；符合局部模式时才考虑 `ScanTS` |
| 两至三个重原子成/断键 | 无前述事件，2–3 个重原子 `formed`/`broken`，无重原子键级变化 | 3,510 | 2–3 B 同步扫描候选；NEB 基线 |
| 其余耦合编辑 | 剩余全部，包括成断键与键级变化网络 | 87,255 | 先检查能否选出 ≤3 个主驱动坐标；否则双端 NEB |
| **合计** | 互斥、全覆盖 `clean` 快照 | **183,460** | 逐条继续做几何可行性判定 |

归组规则以 `edits[].elements` 排除含 H 的键，再数重原子形成/断裂及键级变化；H 事件从专用 `hydrogen_partner_changes` 读，芳香区域从 `aromatic_regions` 读。**不能用 L0 的 F/B/O/H 数字直接替代这些逐条结构检查。** 当前 `clean` 集合有定向 L0 615 类、L0u 400 类，而上表只有七个**扫描规划候选族**；两套标签应并存，不相互覆盖。

上表是可复现的**初步归组**。没有逐条几何质检、端点装配、坐标退化检查、计算预算和 ORCA 输入解析验证，因此不能把 180 条直接叫作“已可 ScanTS”，也不能把 80,676 条直接叫作“已可二维扫描”。一条记录可在其主候选族之下拥有多个有序执行方案。

## 3. G1 对每条反应要完整生成什么

G1 增加一个 `scan-plan` 子阶段，位置在 `v2-gate` 完成之后、G2 启动之前。它从冻结的 `g2_scan_ready.json` 和对应白名单导出读取数据；不重新判断 G1 的 `scan_ready/needs_review/excluded`。每条反应最终恰有一份 `scan_plan_v1`，其状态为 `ready`、`input_rejected` 或 `manual_review`。

### 3.1 结构与几何特征提取

1. 核对 map 升序、R/P 原子数及元素逐位一致、总电荷和多重度、坐标有限值、ORCA/xTB 元素覆盖。建立 `map → ORCA 0 基原子下标`，并保留反查表。
2. 把成键、断键、键级变化、H 伙伴改变、芳香区域汇成**编辑耦合图**：共享原子、同一 H 转移、同一芳香区域、同一环变化与同一反应中心的事件有耦合边。每个连通块只是候选协同模式，不把编辑数当作扫描维数。
3. 按不变骨架对齐 R/P；对多组分给出**确定性有限集合**的端点摆放方案。每个方案记录旋转、平移、种子、接近的反应中心原子对和碰撞检查。不能用 TS/IRC 几何反推摆放。
4. 从合格的端点几何求各候选 B/A/D 的起止值，检查零长度、共线导致的角/二面角退化、周期开角、原子是否重复、扫描距离是否跨越无法接受的碰撞。起止值来自端点；步数和界限来自版本化全局策略，经试点冻结。

### 3.2 反应级候选生成规则

| 项目级反应模式 | G1 要生成的有序候选 | 必须满足的附加条件 |
| --- | --- | --- |
| 单局部成键/断键、简单环合/开环 | `B_1D` 正向、反向；`NEB` | B 两端距离可定义，单键变化能代表主要反应模式；`ScanTS` 只在局部性检查通过后作为后续候选 |
| 两键同步形成/断裂、取代、消除 | `B_SIMUL_2/3` 优先验证；`NEB`、必要时 `NEB-CI` 备选 | 不超过 3 个可解释且非退化的 B 坐标；同步步数相同；对已知异步类型冻结少量早/晚时间表；全部目标编辑逐项检查 |
| H 迁移或夺取 | 供体–H、受体–H 两个 B 同步；`NEB` | 两个伙伴唯一且端点几何一致；伴随重原子变化时把其作为第三个 B，或直接走 NEB |
| 芳香重排、密集键级变化、环协同、H₂ 特殊反应 | 先尝试识别 ≤3 个独立几何驱动坐标；无法验证时以 `NEB` 为主 | 不按单个键级变化或整环键的数量制造高维网格；H₂ 需显式核对 H–H 与原伙伴键 |
| 构象主导的局部变化 | `A_1D` 或 `D_1D`；`NEB` | 必须证明同一结构骨架、候选角/二面角有足够端点差异且不退化；不能仅因 L0 相同推导 |
| 多组分结合/解离 | 对每个合格装配生成 `NEB`；若单一结合距离明确，附加 `B_1D`/同步 B | 两侧碎片能放在统一坐标框架；R/P 排列、电荷和空间碰撞均检查 |
| 无可构造原生坐标、端点不可信或方法能力不足 | `manual_review` / `input_rejected`；保存所有拒绝原因 | 不生成无效 ORCA 作业，也不把记录移出原始分母 |

`NEB` 的前提不是“有 R/P 文件”这么简单：两端必须有相同原子顺序和可比的整体排布。对多组分的远距离解离，G1 应给出有限终点距离与取向，标明人为端点装配，避免把无穷分离端点混作确定势垒。若编辑耦合块彼此独立，G1 可以输出**候选分段**，但必须明确中间体仅为待验证假设；G2 不能把两个独立峰自动解释为同一基元反应。

### 3.3 冻结的计划格式

建议 `data/interim/g1_v2/scan_plans/<shard>/<rid>.json`，另有 `data/manifests/g1_v2_scan_plan_manifest.json` 与 `g1_v2_scan_plan_summary.parquet`。每个计划至少包括：

```json
{
  "schema_version": "g1_scan_plan_v1",
  "reaction_id": "RXN_...",
  "status": "ready",
  "source_sha256": {"g2_export": "...", "gate": "...", "policy": "..."},
  "taxonomy": {"l0_id": "...", "l0u_id": "...", "l1_id": "...", "planning_family": "..."},
  "atom_order": "map ascending",
  "map_to_orca_index": [{"map": 1, "index0": 0}],
  "endpoint_assemblies": [{"id": "a0", "r_xyz_sha256": "...", "p_xyz_sha256": "...", "checks": {}}],
  "candidates": [{
    "id": "a0-neb-01", "rank": 1, "engine": "orca", "mode": "NEB",
    "assembly_id": "a0", "direction": "R_to_P",
    "coordinates": [], "orca_input_sha256": "...",
    "budget": {"max_wall_seconds": 0, "max_core_hours": 0},
    "run_if": "first_attempt", "pass_if": "path_valid_v1"
  }],
  "reject_reasons": []
}
```

这里的 `0` 只是 schema 示意占位，实际预算必须为正、由冻结策略赋值。`coordinates` 逐项记录 `B/A/D`、map 原子号、ORCA 原子下标、端点值、采样列表、单位和方向；同步扫描还需记录共同步号及 `Simul_Scan`，网格扫描记录维数与预估作业量。每个候选还需固定 ORCA 版本、Hamiltonian（首轮建议 GFN2-xTB）、环境/溶剂、总电荷/多重度、资源、计算方法、超时及是否允许反向。G1 **写出完整 `.inp` 与 R/P `.xyz`，并做语法/索引/输入范围静态检查**；G2 不再自由挑选坐标、增减步数或更改预算。

`run_if` 只能引用前一作业的机器可判定状态，例如 `path_incomplete`、`wrong_endpoint`、`scf_failed` 或 `budget_exhausted`。G1 提前列出候选及触发树；G2 仅求值条件并运行，不临时设计新的扫描。修改策略须生成新版计划与新的哈希，不能暗改原计划。

## 4. 实施顺序与验收

| 步骤 | 工作 | 可验收产物 |
| --- | --- | --- |
| G1-S0 能力注册 | 固定 ORCA 6.1.x 支持的 B/A/D、同步/网格、ScanTS、NEB 关键词和组合限制；记录目标机实际版本 | `orca_capabilities_v1.json`、最小输入模板及版本检查 |
| G1-S1 反应归组 | 对全部 `scan_ready` 逐条计算编辑耦合图、H 类型、芳香/环、多组分标签；保留 L0/L0u/L1 | 每条都有可解释的 `planning_family`；总数与 gate 一致 |
| G1-S2 坐标/端点生成 | 端点对齐和多组分装配；B/A/D 可行性；ORCA 0 基索引；候选起止值与方向 | 每条 `ready` 的 R/P XYZ、每个 Scan 候选的坐标都可重算 |
| G1-S3 候选编排 | 由版本化规则生成主方法、备选、触发条件、固定预算与 `.inp` | `scan_plan_v1`、输入 SHA256、候选数和预估成本 |
| G1-S4 独立验证 | 不调用生成函数重算 map/原子索引/坐标范围；解析输入；检查所有候选都无 truth 字段；覆盖拒绝状态 | 零静默缺项、零无效索引、全量账目闭合 |
| G1-S5 冻结关卡 | 写计划 manifest/summary、按 L0/规划族/组分数统计覆盖与拒绝；与 v2 gate 哈希绑定 | 仅冻结 `ready` 计划供 G2 消费 |
| G2-E1 执行 | 按冻结候选和触发树运行 ORCA，保存原始日志、逐帧 XYZ/能量、终止码与资源消耗 | 可重放的 `path_manifest`；无现场改输入 |
| G2-E2 结果核验 | 按 G1 冻结的几何、能量、拓扑判据给 `valid_path`/失败码 | 每条反应与每个候选都有终态；按类报告实际成功率 |

试点顺序：先用 100–200 条覆盖七个规划族的合同集验证输入和状态机；再用约 1,000 条分层集合估计路径有效率、反向/多装配/NEB 的增益与成本。所有阈值和候选优先序只用训练/验证集调整，锁定后再跑测试集。二维网格、三维网格、`ScanTS`、NEB-TS 均须单列成本和严格验证结果，不能混入基础路径生成的成功率。

## 5. 必须保持的边界

- G1 规划**可以使用**真值辅助的原子映射和编辑元数据，但编制扫描输入**不可使用** DFT TS/IRC 坐标、能量、路径帧或由其拟合的扫描区间。计划与生成器均要有白名单/静态检查。
- 路径高能点、`ScanTS` 收敛或 NEB-TS 输出都不自动等于目标 TS；后续仍需频率和双向 IRC 对目标 R/P 做独立核验。
- G1 需要完整列出**有限且受预算约束**的候选及回退树；G2 不负责新策略识别，但必须保留执行状态、质量判定及异常报告。计算失败返回 G1 的下一版本改进，不在 G2 中静默修补。
- 当前七族数字是依据已完成 v2 编辑树作的静态分析，**还没有完成 G1-S2 至 G1-S5 的逐条几何计划生成**；因此没有任何一族被宣称为 100% 可运行或 100% 可找到目标路径。

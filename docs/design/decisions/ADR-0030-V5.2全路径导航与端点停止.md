## 1. 背景

V5.2（PES2TS_30H 战役）以 **TS 邻域**为 Stop 正例训练，终局 G3 = FAIL(E-NO-GAIN)。战役后审计表明这不是"Stop 难学"或"网络容量不足"，而是**任务定义层面的错误**：Stop 标签定义的是"靠近 TS"，而 PES2TS 的研究目标是完整反应路径导航——Stop 应发生在**目标端点**，TS 是必须穿越的途经点。

关键审计事实（全部实测，详见审计报告）：

1. **终点正例被系统性排除**：V5.2 训练入口 `scripts/campaigns/r3_v52_run.py:158-160` 只加载 `label_statuses=("ok",)`；200 个端点行中 92 个"到达目标端点"的行是 `terminal`，从未进入 Stop 训练；90 个"从端点出发"的行是 `ok` 且 stop=0（Move）。
2. **旧 Stop 正例全部在 TS 附近**：标签来自 `d_key_TS ≤ 0.04 Å`，共 405 行 / 196 个独立 (curve,node) 正例，每曲线中位数 6 个；200 个端点行中仅 2 个因 TS 窗口偶然为正。
3. **`terminal` 语义混用**：`teacher_manifest.json` 定义 terminal = "path exhausted below d0"（Move 教师无未来 contact），**不是反应终点**；1123 个 terminal 行距最近端点中位 6 节点、最大 47 节点，恰是 Endpoint Stop 最需要的区域。
4. **Move 教师是全路径的、正确的**：45.7%（4414/9655）ok 行的 Move 目标指向远离 TS——穿越 TS 后本应继续走向另一端点；此前"Move/Stop 教师冲突"的解释不成立于全路径任务。
5. **"q 不可学习"结论降级为 exploratory**：战役后线性探针池化了 TS 两侧/双 intent（符号相消：全量 corr −0.147 vs approach 侧（朝 TS 接近的 intent 起始侧子集）−0.793、曲线内 −0.932），且使用了 48 条曲线（dev folds 0–2 仅 30 条，疑触 sealed folds 3/4）。
6. **20 步 rollout 预算不足**：关键原子弧长中位 1.74 Å → 在 d0=0.08 Å 下估算步数中位 22，71% 曲线需要 >20 步；V5.3 的"弧长饱和 62%"部分是预算限制。
7. **provenance 缺口**：本地 HEAD 94b7da9 领先 origin/master 4918442 达 65 个提交；run records 无 `git_sha`；`key_atom_teacher.py` docstring 仍写 "TS-terminal"（R3 builder 实际传入完整曲线），易再次引发语义混用。

## 2. 决策

### 2.1 任务：Reaction-Intent-Guided Full-Path Navigation

- **Forward**：R → TS → P；**Reverse**：P → TS → R。
- **Move**：沿指定 intent 继续推进完整 IRC；**允许且必须跨越 TS**。
- **No-Move / Endpoint Stop**：当前关键原子几何进入**目标端点**邻域；选中坐标 = 当前 \(X_t\)。
- **TS**：完整路径的途经点与诊断/验证事件，**不触发 No-Move**。
- **Progress q**：有向进度辅助量；q=0 只表示 TS 位置，不表示停止。
- 输入合同不变：当前单帧几何 + 合法有向反应图/约束；历史轨迹只用于外部执行器验证，不回灌 V5 模型。
- **Model Stop ≠ Verified Reaction Path**：端点到达判断不等于已验证 TS/IRC 连通性。

### 2.2 Move：保留 R3 Full-Traversal 教师

- 全部 `ok` Move 行、两个 intent、全部节点；
- 不按 approach-side 过滤（已撤回方案）；不在 TS 附近裁剪/屏蔽；
- 仅保留 R3 已有合法性 mask（no_future_contact / gauge / conflict）；
- Move 质量（R3 0.910/0.9735）是独立工作流；V5.2-R 只保证**不退化**（RMSE/zero 退化 ≤2%，硬门）。

### 2.3 Endpoint Stop 标签

- \(d_{\rm end}(X,H)=\operatorname{RMSD}_K(X, X_{\text{target endpoint}}(H))\)；forward 目标端点 = canonical 路径末端 B(P)，reverse = 起点 A(R)；
- 主候选窗口 **w_pos=0.10 Å / w_neg=0.30 Å**；D1 可比较 0.08/0.10/0.12/0.15，但 T1 前必须按预注册标准冻结，禁止按 AUPRC 事后挑窗；
- 实测（12034 行）：0.10/0.30 → 正例 1781（14.8%）、Mask 1854、每曲线正例 min/med/max = 9/32/90；起点误正例 0；TS 误正例 2/100；
- 2 个 TS/端点几何退化样本（RXN_0000001174 TS d_end=0.066；RXN_0000001675 TS d_end=0.019）单独 flag/mask，并按含/排两种口径报告；
- **Stop eligibility 完全独立于 Move eligibility**：`terminal` 行必须进入 Stop 数据；
- 同一几何在端点的 intent 条件对照是核心监督：\((X_P,H_{R\to P})\to\) Stop，\((X_P,H_{P\to R})\to\) Move；
- TS 默认负例；禁止用 `d_key_TS` 或 q 阈值定义 Stop。

### 2.4 Progress：q 保留 + 全路径 directed ordering

- q 分段归一化：A=−1 / TS=0 / B=+1；reverse 取 −q（现行 `progress_q_from_arcs_v52` 定义不变）；
- Pairwise ordering 允许跨 TS 构对，不限制同侧；
- q 回归仅为可选辅助损失，不作为 Stop 触发条件、不作为唯一验收门槛；
- 不建立 q→Stop 的依赖路径。

### 2.5 评估

主指标：起点误停止率、TS 附近误停止率、TS 跨越完成率、目标端点到达率、首次 Stop 的 \(d_{\rm end}\)、Move 非退化（≤2%）、全路径/跨 TS ordering。Rollout 预算长度感知：

\[
B=\max\left(40,\ \left\lceil 1.5\cdot L_{\rm key}/0.08\right\rceil\right)
\]

统计单位 = 反应簇 bootstrap + 3 seeds；dev folds 0–2 only；folds 3/4 继续封存。

### 2.6 文档单一真相与一致性门

- 规范性任务定义只允许存在于：宪法（v2.8 增量）+ `PES2TS_FullPathNavigationContract_v1` + 本 ADR；其他文档只能引用，不得重新定义 Move/Stop/TS/q；
- `scripts/agent_ops/docs_consistency.py --strict` 为 CI/训练前强制门；
- 任何语义变更必须：新 ADR + 新合同版本 + docs gate 通过；禁止静默修改。

## 3. 备选方案

| 方案 | 结论 | 理由 |
|---|---|---|
| 修复 TS 邻域 Stop（调窗/调权/扩容） | 拒绝 | 任务定义错误，不是标签噪声或容量问题 |
| approach-side filter / TS-directed Move | **拒绝（正式撤回）** | 把全路径任务错改成 TS 汇聚任务 |
| 继续用 d_key_TS 训练 Stop | 拒绝 | Stop 的对象是目标端点，不是 TS |
| 以 20 步 rollout 判定 full-path 失败 | 拒绝 | 71% 曲线预算不足 |
| Full-Traversal Move + Endpoint Stop + directed q | **采用** | 与 PES2TS 研究目标一致，接口不变 |

## 4. 后果

- 新标签 schema `pes2ts_fullpath_nav_labels_v1`：`move_status` / `stop_status` / `q_status` 三域分离；`endpoint_stop_label`、`target_endpoint`、`d_end_angstrom` 为新字段；旧 `ts_stop_legacy` 仅作 ablation；
- 旧 V5.2 符号（`TSStopHeadV3`、`ts_stop_loss_v52`、`stop_label_from_distance_v52`）保留用于加载旧 checkpoint，标注 `LEGACY_TS_STOP`，不再用于新训练；
- V5.2 已执行结果保留为**旧任务（TS-stop）的有效负证据**，不作为 Endpoint Stop 的基线或反例；
- V5.2-R 阶段：D0（标签/provenance 审计）→ D1（冻结 R3 编码器，独立 Endpoint Head + directed ordering）→ T1（联合训练）→ R（全路径 rollout，长度感知预算）；
- 所有 V5.2-R run 必须记录 `code_commit`、`data_manifest_sha256`、`teacher_manifest_sha256`、`split_sha256`、`label_schema`、`label_spec_sha256`、`config_sha256`；
- verified TS 仍只由 OptTS + 频率 + 双向 IRC + 端点身份确认；模型输出最多称 `TS_candidate` / `endpoint_reached`。

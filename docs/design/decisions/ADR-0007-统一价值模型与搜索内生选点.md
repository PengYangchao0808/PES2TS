## 背景

用户提出：PES-G 的预测推进本身包含对不同点接近 TS 程度的比较，内部搜索未必需要额外 ranking；外部输入的已有路径或候选仍需要显式排序。

现有方案将 generation 和 ranking 分别组织为学习轨道。该划分有利于隔离评测，但不意味着应永久使用两套独立价值模型。

完整方向、数学定义和任务见[统一价值模型与搜索排序一体化发展方案](../../plans/PES2TS_统一价值模型与搜索排序一体化发展方案_v1_20261004.md)。

## 拟议决策

1. 以共享目标条件价值核心统一 PES-G/PES-R 的观测、训练证据和模型实现；G/R 保留为闭环搜索与外部候选评价的使用模式。
2. “距离 TS”优先解释为指定协议与预算下的成功概率、剩余成本及决策价值，不定义为到已知参考 TS 的在线几何距离。
3. 区分继续动作价值与立即交接价值；外部候选排序是 handoff 动作价值的批量评价，不能直接拿 actor 概率、步长或长期搜索价值替代。
4. 内部采用边搜索边评价、维护有限合格候选档案和显式交接，不强制路径完成后再启动独立学习排序器。既有规则后排序保留为基线/兼容模式。
5. 外部路径先检查目标、原子/方法身份、帧资格及特征可用性，再复用同一价值核心；跨来源校准和缺失模式单独验证。
6. 保留 ACP/ORCA 数值执行、公共物理验收和完整严格验证；模型预测不能替代物理标签，严格验证结果不反馈当前在线生成。
7. 开发建议为 Classic 闭环 → 共享价值的静态验证 → 价值引导生成/交接 → 外部来源扩展；不新增阶段编号，不跳过 G2 出口。

## 备选与取舍

| 选择 | 取舍 |
|---|---|
| 独立 G/R 模型与固定串行管线 | 容易分开训练评测，但目标与特征可能重复，在线交接不自然 |
| 单一无条件“几何距离”标量 | 接口简单，但混淆未知/多解 TS、搜索机会与立即精修价值 |
| 共享核心、条件化动作/交接价值（建议） | 统一数据与决策；需校准、缺失处理、负迁移和预算语义验证 |

## 验收与回滚

先修复严格验证、准备层来源链和标签归并，再完成真实优化状态/动作记录。共享模型先在相同候选池验证 handoff 价值，再进入在线生成。

比较共享与独立模型、内生交接与独立后排序、最后帧与在线档案；固定 QC/验证协议和总预算，保留反应族/外部来源留出。主要结果为全输入严格 TS 覆盖—总成本，不能只报告自评分。

若共享产生负迁移，可保留共享编码及分任务输出/校准，或显式退回独立模型基线；不为了维持“一模型”名义降低性能或物理验收。native/legacy 和各模型版本保持独立身份及可回放历史。

## 1. 背景与问题

1. **V5.4.2 已执行完毕并交接**：V5.4.2 结论为 `no_backbone_winner`，A0 留任；三个 seed 完整且逐 seed H2 无 breach 的候选集为空。该结论**不得写成「A0 胜出」**，也不得与 V541 E0 比较。V5.4.3 承接 V5.4.2 报告 §9 的交接，把 A0 从「可训练联合模型」拆成「一次性 Coarse Encoder + 参数自由 Geometric Latent Bridge + 两条独立残差 Decoder + 外层 Controller」。
2. **问题从「换 Backbone」收敛为「换 Decoder」**：V5.4.3 的中心问题是「同一份冻结的分子空间表征（A0 的 `z`、最后一层 `h`、`edge_msg`、`u0`、`q0/e0`），采用何种 Decoder 结构，能在不损害化学语义与推理成本的前提下，最准确地产生下一步关键原子位移和当前反应状态？」V5.4.3 不回答「哪个 Backbone 更好」——A0 是固定 Encoder，不参加冠军竞争。这比继续堆 Backbone 更可归因，也为 V5.4.4/V6 留下稳定接口。
3. **用户提案 v2.0 的五个基本原则全部保留**：Encoder 只跑一次、两 Track 独立训练、所有 Decoder 残差预测、先确定性 Benchmark 再条件生成、不改科学接口。方案在其上做三类增强——**可冻结**（把 `DecoderContextV1` 从字段清单升级为带单位、对称性、构造算法、禁读清单、审计与缓存身份的完整数据合同）、**可归因**（把「≤40K」升级为「同 Track 参数匹配 ±5%」，把「固定覆盖率方向」升级为独立定义，把「q 很高」升级为「q MAE + ordering + 有效点数」）、**可执行**（把 WP0–WP9 展开为带前置、放行证据、失败动作与运行矩阵的工作包）。
4. **提案需 8 处工程/科学修正后才能冻结**：其中 4 处是硬错误风险——`q0_raw` 当前没有公开出口；`pair_index/pair_edit` 是监督字段不能作为 Bridge 输入；V542 的 `fixed_coverage_direction` 实际就是 sign 的重复叶子；PROCESS 的 `frame_mask` 不能沿用 MOVE 的 `label_status=="ok"`，否则 terminal 行会被误删。其余 4 处是设计缺口——Bridge 缺 key-key 邻接与 token 布局；8 通道基底的「覆盖率」单独使用会虚高；`q_corr` 在当前每曲线点数下接近退化；V542 实际 MOVE 损失没有 `λ_strong/λ_dead`。修订后的字段与流程见 §2–§5。
5. **本 ADR 是 V5.4.3 的唯一治理锚点**：最重要的交付物不是某一个 Decoder 权重，而是 **`DecoderContextV1` + Decoder Registry + 可复现的两 Track 训练/评估合同**。有了它们，V5.4.4 可以替换离线 IRC Teacher，V6 可以加入物理校正，而不需要推翻 V5.4.3 的模型组织方式。
6. **冻结不等于免门**：D1–D8 签认只冻结设计语义；正式 run 启动仍须 H0（合法性）、H1（资源）、单路 smoke、同环境 profile、预算签认、runplan SHA 冻结全部通过；`confirm`/`sealed` 恒 false、新增 QC 恒 0、单路、无 swap。

## 2. 决策

### 2.1 架构冻结：五个独立组件与唯一数据流

| 组件 | 职责 | 是否读原始 XYZ | 训练状态 | 参数量 |
|---|---|---|---|---|
| `CoarseEncoder` | A0 EGNN + D0 + P0；产生 `z`、`h`、`edge_msg`、`u0`、`q0_raw`、`e0` | 是（仅此一处） | **冻结** | 57,619 |
| `LatentBridge` | 从 Encoder 输出与 forward 拓扑构造 `DecoderContextV1` | 只在构造时读一次 `pos` 的差值 | **固定、参数自由** | 0 trainable |
| `MoveRefiner` | `δu` | 否 | 独立训练 | ≤36K 目标 |
| `ProcessRefiner` | `δq_raw`、`δe` | 否 | 独立训练 | ≤36K 目标 |
| `ReactionController` | 化学核验 + MOVE/No-Move | 可读当前合法输入做核验 | 非本阶段学习目标 | 0 |

唯一前向流程：单帧 `forward_view`（当前 XYZ + 合法有向拓扑 + 约束）→ `CoarseEncoder`（只调用一次：`StarEGNNV3 → z[G,64], h[N,48], edge_msg[E,48]`；`DirectMoveDecoder → u0[K,3]`；`ReactionProcessHeadV53MP → q0_raw[G], e0[G]`）→ `LatentBridge`（参数自由；产出 `DecoderContextV1`，不含 `pos`、不含监督）→ 分叉 `MoveRefiner`（`δu[K,3]`）与 `ProcessRefiner`（`δq_raw[G], δe[G]`）→ 合并 `u = u0 + δu`；`q = tanh(q0_raw + δq)`；`e = e0 + δe`，`p_end = σ(e)` → `ReactionController`（外层，不在训练前向内；`move_flag` / `selected_coords` 仅依据校准端点 + 化学状态）。

**输出语义（冻结）**：

- `u = u0 + δu`，单位 Å；行序严格等于 `key_index`；非关键原子零位移。
- `q = tanh(q0_raw + δq)`；`order_score IS q`（保持 V542 外部合同）。
- `e = e0 + δe`；`p_end = σ(e)`；训练时只用 logit，**禁止双重 sigmoid**。
- 外部 forward 仍只返回五键 `{u, z, q, endpoint_logit, order_score}`；诊断量（`u0`、`δu`、`q0_raw`、`δq`）通过独立 `forward_debug` 返回，不进入外部合同。
- **单 Track Benchmark 时，未参与当前 Track 的 Refiner 固定为零残差（M0/P0）**，避免另一 Track 的随机初始化污染当前指标；只有 T7 集成才同时启用两个冠军。
- `No-Move` 只能由「校准后的端点概率 + 目标化学状态一致」触发；`q` 阈值、接近 TS、路径长度均**不得**触发 No-Move；TS 行必须继续 MOVE。

### 2.2 五条冻结边界

1. **Encoder 只运行一次**：每次当前构型恰好一次 `CoarseEncoder.forward`；Flow/Diffusion 的 NFE 循环不得重新调用 Encoder。
2. **两条 Track 独立**：MOVE 训练不更新 PROCESS Refiner，PROCESS 训练不更新 MOVE Refiner；两者都不更新 Encoder/D0/P0。
3. **所有 Refiner 残差预测**：最后一层零初始化；初始模型必须逐元素还原 V542 A0。
4. **先确定性、后生成**：M4/M5 只在 S1 诊断显示明确剩余瓶颈时激活；不得因「模型流行」直接进入正式矩阵。
5. **科学接口不变**：单帧输入、合法有向拓扑、TS 可穿越、No-Move 语义不变（MoveProcessContract v1）。

### 2.3 零残差初始化（逐候选冻结）

| 模块 | 零初始化位置 | 初始输出 |
|---|---|---|
| M1 | 最后一层 `Linear(·,8)` 的 weight/bias | 8 个系数 = 0 → `δu = 0` |
| M2 | 最后一个 scalar→vector 的输出投影 + 外层 gate | `δu = 0` |
| M3 | 输出 head 最后一层 | `δu = 0` |
| M4 | 速度输出最后一层 + 外层零 gate | `δu = 0`（不依赖噪声） |
| M5 | 去噪输出最后一层 + 外层零 gate | `δu = 0` |
| P1–P5 | 最后一层 `Linear(·,2)` 的 weight/bias | `δq = 0`、`δe = 0` |

**注意**：仅把 Flow 内部参数初始化为零，不能保证随机采样输出为零；必须在最外层加零初始化残差门控。测试必须验证「随便采样多少次，初始 `δu` 恒为 0」。

### 2.4 Controller 语义（非学习，冻结）

```python
def move_flag(p_end, tau_end, chemical_state_ok, is_ts):
    if is_ts:
        return True                    # TS 永远继续 MOVE
    if p_end >= tau_end and chemical_state_ok:
        return False                   # 唯一合法的 No-Move
    return True                        # q 不参与
```

`tau_end` 只在 inner-val 上校准一次，目标 precision 0.9；**dev 不重校准**。`chemical_state_ok` 由外层合法端点/键级核验给出，**不由模型 `q` 给出**。该函数不在 `V543Model.forward` 内；训练前向不产生 `move_flag`。

## 3. 数据合同：`DecoderContextV1`

### 3.1 六条设计原则

1. **只读、类型化、不可变**：`@dataclass(frozen=True, slots=True)`；Decoder 只能拿到 context，拿不到 `batch`、`pos` 或任何监督键。
2. **单位与对称性显式**：每个字段写清 dtype、shape、单位、旋转/平移/置换行为。
3. **参数自由**：Bridge 不引入可训练参数；固定投影矩阵以 `persistent=False` buffer 存放，不进入 optimizer。
4. **构造一次**：每个当前构型只构造一次；Flow/Diffusion 的 NFE 循环复用同一 context。
5. **可缓存**：缓存键覆盖 Encoder/Bridge/输入/精度/代码身份；缓存内容只有 context，没有标签。
6. **可审计**：任何字段都能追溯到 forward-view 键或 Encoder 输出；禁止字段在运行时不可达。

### 3.3 两个只读视图（强制 Track 独立）

`DecoderContextV1` 只在 `V543Model` 内部持有；两个 Refiner 拿到的是互不重叠的只读视图：

- `MoveContextV1`：`graph_s[G,64]`、`key_s[K,48]`、`key_v[K,8,3]`、`u0[K,3]`（Å）、`key_edge_index[2,Ek]`、`key_edge_attr[Ek,8]`、`key_graph[K]`、`key_ptr[G+1]`。
- `ProcessContextV1`：`graph_s[G,64]`、`key_s[K,48]`、`pair_s[P,48]`、`intent_pair_index[2,P]`、`key_graph[K]`、`pair_graph[P]`、`key_ptr[G+1]`、`pair_ptr[G+1]`、`token_index[T]`、`token_type[T]`、`token_graph[T]`、`token_ptr[G+1]`、`q0_raw[G]`、`endpoint0_logit[G]`。

**硬约束**：`MoveContextV1` **不含** `q0_raw`、`endpoint0_logit`、`pair_s`、`token_*`（MOVE 不能读 PROCESS 状态）；`ProcessContextV1` **不含** `u0`、`key_v`、`key_edge_*`（PROCESS 不能读 MOVE 初猜或 MOVE 的向量基底）；两个视图都不含 `pos`、监督键、绝对坐标、历史帧。`V543Model.forward` 只把对应视图传给对应 Refiner；测试 `test_v543_track_view_isolation` 必须断言视图互斥。

**为什么强制互斥**：如果 MOVE 能读 `q0_raw`，它可能学会「用 PROCESS 的进度作弊」；如果 PROCESS 能读 `u0`，它可能从 MOVE 的位移反推进度。V543 要回答的是「两条独立专家各自能从同一份 Encoder 表征中学到什么」，不是「两个头互相泄题能到多高」。

### 3.4 `key_v` 的 8 个通道（参数自由、确定性）

记 `x = pos`，`a_ref = 0.08`，`unit_e = (x[src_e] - x[dst_e]) / (||…|| + 0.1)`（与 D0 完全相同的单位向量约定）。对每个 key 原子 `k`：

| 通道 | 定义 | 说明 |
|---|---|---|
| 0 | `u0[k] / a_ref` | 继承 MOVE 初猜；除以 `a_ref` 使其无量纲 |
| 1 | `Σ_{e: dst=k, ΔB_e<0} abs(ΔB_e) · unit_e / Σabs(ΔB_e)` | 断键方向 |
| 2 | `Σ_{e: dst=k, ΔB_e>0} abs(ΔB_e) · unit_e / Σabs(ΔB_e)` | 成键方向 |
| 3 | `Σ_{e: dst=k, ΔB_e=0, covalent} unit_e / count` | 不变共价边方向 |
| 4 | `Σ_{e: dst=k, spatial} κ(d_e) · unit_e / Σκ`，`κ(d)=exp(-((d-3.0)/1.0)^2)` | 空间邻近方向 |
| 5 | `Σ_{p: k∈pair, changed K-pair} sign(ΔB_p) · (x[other]-x[k])/(‖…‖+0.1) / count` | 关键对方向 |
| 6 | `Σ_{e: dst=k} (d_e/4.0) · unit_e / Σ(d_e/4.0)` | 距离加权全边均值 |
| 7 | `(mean_{j∈K, j≠k} x[j] - x[k]) / (‖…‖+0.1)` | 指向关键原子质心的方向 |

**规则**：任一分母为 0 时该通道置零向量，**不得产生 NaN**；所有通道只依赖 `pos` 的差值、`ΔB`、`is_changed`、`is_covalent`、`is_spatial`、`key_index`，不依赖绝对坐标；通道 0 与 `u0` 线性相关，在 S0-C 中必须同时报告「含通道 0」与「去掉通道 0」的覆盖率，避免用 `u0` 自证；8 个通道的目标不是「一定表达真实动作」，而是给 Decoder 一个可解释、等变、低成本的向量读出基底，是否足够由 S0-B/S0-C 判定。

### 3.5 `pair_s` 的 48 维布局（参数自由）

对每个 changed K-pair `(i,j)`（`i<j` 为 key-slot 规范序）：

| 维度 | 内容 |
|---|---|
| 0–5 | `b_src`, `b_tgt`, `ΔB`, `abs(ΔB)`, `is_changed`, `is_covalent` |
| 6–7 | `is_aromatic`, `is_spatial` |
| 8–19 | `RBF12(d_ij)`（复用 `gaussian_rbf_v3` 的 12 个中心） |
| 20–22 | `d_ij`, `1/(d_ij+1)`, `ΔZ/10` |
| 23 | `abs(ΔZ)/10` |
| 24–27 | 端点 i 的 `(breaking, forming, spectator, is_key)` |
| 28–31 | 端点 j 的同一组角色 |
| 32–39 | 图级广播：`signed_intent`, `‖cv_delta‖`, `cv_delta[0:6]` |
| 40–47 | `W_fixed @ (key_s[i] - key_s[j])`；`W_fixed` 为固定的 `8×48` ±1/√48 矩阵（`persistent=False`，无训练参数） |

**说明**：40–47 是固定的 Johnson–Lindenstrauss 式 sketch，只提供低维标量上下文；它不是可训练层，也不改变 `key_s` 的语义。若 WP2 审计认为它引入不必要的耦合，可替换为 8 个固定索引的 `key_s` 差值；两种实现都必须参数自由，并在 Bridge 规格中冻结。

### 3.6 key-key 邻接与 token 布局

**key 图边集**（去重、无向、双向存储）：(1) 每个 changed K-pair 加一条双向边；(2) 每个 key 原子到最近的最多 4 个 key 原子（距离 < 6.0 Å）加边，排除自身与已存在边；(3) 不做稠密 `K²` 全连接；`Ek ≤ 2·(P + 4K)`。

**`key_edge_attr` 8 维**：`d`、`RBF(d;2,3,4,5)`（4 维）、`|ΔB|`、`is_changed`、`edge_type`（0=covalent/changed，1=spatial）。

**token 布局**：每图 token 连续排列为 `[graph_token, key_tokens…, pair_tokens…]`；`token_index` 对 graph token 填 `-1`，对 key/pair 填对应行号；`token_type` 区分三类。这样 P2/P3/P4 可以共享同一套 token 定义，不需要各自私建索引。

### 3.7 禁止输入与运行时审计

**Bridge 不得读取**：`pos` 以外的任何几何量（且 `pos` 只用于差值）；`pair_index`、`pair_edit`、`y_teacher`、`q_true`、`endpoint` 标签、`frame_weight`、`d0`；参考 TS/端点 XYZ、未来帧、IRC 历史、能量/梯度；`split_family`、`branch_id`、`curve_id`、`sample_id`；任何 `SUPERVISION_KEYS_V3` 成员。

**运行时审计**：

```python
def assert_no_supervision(ctx: DecoderContextV1) -> None:
    for name in SUPERVISION_KEYS_V3:
        assert not hasattr(ctx, name)
    for forbidden in ("pos", "xyz", "pair_edit", "y_teacher", "q_true"):
        assert not hasattr(ctx, forbidden)
```

- `DecoderContextV1` 的 `__slots__` 只含 §3.2 字段；`__getattr__` 不得回退到 batch。
- 测试 `test_v543_decoder_no_xyz`：给 Decoder 传一个「只有 context」的假对象，任何 `ctx.pos` 访问必须 `AttributeError`。
- 测试 `test_v543_no_supervision_leak`：在 batch 中注入哨兵值（如 `pair_edit=12345`、`y_teacher=999`），构造 context 后所有字段与哨兵无关。

**pair 集合来源审计（只读、离线）**：在 10,000 个采样帧上，比较 Bridge 从 forward edges 重构的 pair 集合与监督 `pair_index` 的集合/计数/端点；期望集合完全一致（二者都来自同一 intent 的 changed pairs），若不一致说明 forward 视图缺信息或重构规则错，必须阻断。审计代码只读监督字段用于**比对**，不进入 context、不进入模型；审计报告单独存放，SHA 进 run identity。

### 3.8 缓存记录与 Packet 边界

**缓存内容**：只有 `DecoderContextV1` 的 tensor 字段 + schema/identity；**不含** `y_teacher`、`q_true`、`endpoint`、`frame_weight`、`sample_id`、`curve_id`。

**缓存键**：

```text
encoder_ckpt_sha256
| bridge_spec_sha256
| input_feature_sha256
| source_frame_identity   # curve_id + node_index + intent_id + d0 的 canonical hash
| precision_version
| code_fingerprint
```

**规则**：缓存只在 `frozen_encoder` 模式有效；`joint_finetune` 必须实时构建、保留 autograd，禁止读 detached 缓存。缓存构建必须在 split 之后；只允许 inner-train + inner-val 曲线；**dev/confirm 永不入缓存**。缓存按曲线分片（建议 256 curves/片），按需加载，RAM LRU 1–2 GB；磁盘上限 30 GB；命中率目标 ≥80%。身份不匹配、文件 SHA 不匹配、schema 版本不匹配 → 拒绝命中并重建，**不得静默复用**。缓存统计（hit/miss/build time/disk bytes）写入 run records；缓存本身不参与科学选择。

### 3.9 A0 迁移与零残差 parity

**必须证明的等式**（三 seed、≥8 个真实 inner-val batch、CPU 逐位、GPU ≤1e-6）：

```text
u0_V543            == u_V542
z_V543             == z_V542
q0_V543            == q_V542
tanh(q0_raw_V543)  == q0_V543
endpoint0_V543     == endpoint_logit_V542
零残差 V543(u,q,e) == V542(u,q,e)
order_score is q
```

**实现要点**：`CoarseEncoder` 复用 `A0LegacyBackbone`（含 `message_mlp[-1]` hook、共享 `w_v`、strict load），**不修改 V542 文件**；增加 `norm_h[-1]` 的 forward hook 捕获最后一层 `h`，hook 必须在 `finally` 中移除并断言恰好触发一次；`q0_raw` 用 `progress_head.fc2` 的 forward hook 捕获，`q` 仍由 `process_head(z)` 产生，两者逐元素验证；`u0` 由 `DirectMoveDecoder` 用与 V542 完全相同的五个张量计算，不得重排 `edge_index` 或改变 `key_index` 行序；所有 hook 不得 detach；frozen 模式可在 `torch.no_grad()` 中运行，但 zero-residual parity 必须在同一 dtype/device 下比较。

### 4.4 单步训练数据流（每 update）

1. `curve_batch_positions_v541` 按 `(seed, update, salt)` 抽 8 curves × 4 frames，得到 32 个 position。
2. `_batch_from_positions` 从 dataset/LRU 取特征并 collate；`forward_view_v3(batch)` 去掉全部监督键。
3. `CoarseEncoder.forward(forward_view)` **恰好一次**，得到 `z/h/edge_msg/u0/q0_raw/e0`。
4. `LatentBridge.build_context(packet, forward_view)` 得到 `DecoderContextV1`；frozen 模式可走缓存，miss 时实时构建。
5. 当前 Track 的 Refiner 读 context，输出 `δu` 或 `(δq,δe)`；组装 `u/q/e`。
6. **独立标签通道**：从 `labels_v52`、`endpoint_labels`、`batch["pair_index"]/["pair_edit"]/["y_teacher"]/["frame_weight"]` 取监督；这些键**永不进入 context**。
7. 按 Track 计算损失 → backward → clip → step；记录 loss 分项、有效样本数、grad finite、Encoder call count。

**为什么把标签通道单独写**：V543 的核心风险不是模型结构，而是「Bridge 看起来参数自由，实际上把监督偷偷带进来」。把 context 构造与标签读取写成两条互不引用的代码路径，是比单元测试更可靠的结构性隔离。

### 4.5 损失（D5 已签认：原样复用 V542 系数）

**MOVE Track（原样复用 V542，不含 strong/dead）**：

```text
L_M = L_atom + 0.5 * L_pair + 0.02 * L_cos
```

复用 `key_atom_loss_v53mp` / `key_atom_loss_v3` 的现有函数与 mask；`lambda_strong = lambda_dead = 0`（V542 实际配方）；只用 `label_status == "ok"` 的帧（`_frame_mask_for`）；`pair_index`/`pair_edit` 只作为损失输入，不进入模型；**不重新实现不同版本的损失**。

**PROCESS Track（原样复用 V542 系数）**：

```text
L_P = 0.5 * L_ranking + 0.5 * L_q + 0.012385049119773344 * L_endpoint
```

直接调用 `ranking_loss_v53mp`、`progress_loss_v52`、`endpoint_loss_v53mp`，不调用 MOVE 损失；**PROCESS 的 frame mask 不能沿用 `_frame_mask_for`**：必须使用 endpoint 标签表的有效 mask（`process_frame_mask`，覆盖 `ok/terminal/masked/conflict`），terminal 行只要 endpoint 标签有效就进入训练；q 用 `q_mask`；endpoint 用 `endpoint_mask`；`endpoint_pos_weight` 从 inner-train 估计一次；`order_pairs` 用与 V542 相同的 `sample_order_pairs` 与 RNG 协议；两条 Track 的 loss 数值**不可直接比较**；若某 batch 在当前 Track 无任何有效监督（全 mask），跳过该 update 并记 `skipped_no_grad`——不得反复重采样直到有标签，也不得伪造零标签。

**规则**：恢复只从 `checkpoint_last.pt`，且 identity 逐键 + digest 匹配；不匹配 = `invalid_run`，不得静默新建；恢复必须带回 model/optimizer/step/RNG/sampler counters/schedule；`test_v543_exact_resume` 必须证明连续 100 updates 与「50 + kill + resume 50」的权重、loss、records 逐位一致（CPU）。

### 4.8 S0 → S1 → S2 三阶段

**S0（迁移验收与冻结表征，进入 S1 前阻断门）**：

- **S0-A 零残差 parity**：`V543_M0_S17` ← `V542_A0_S17`、`V543_M0_S29` ← `V542_A0_S29`、`V543_M0_S43` ← `V542_A0_S43`；必须复现 `u0`/`z`/`q`/`endpoint_logit` 与 V542 对应 seed 逐元素一致（CPU bitwise；GPU ≤1e-6）、`tanh(q0_raw) == q`、零残差 M0/P0 全模型输出与 V542 一致、`order_score is q`、Encoder forward 每次当前构型恰好 1 次、hook 恰好 1 次、3 seeds × ≥8 个真实 inner-val batch。**失败处理**：阻断所有训练；按缺陷类别修复（代码/数据/初始化/hook），bump 对应 identity 层，重跑 S0-A；**不得用「近似相等」放行**。
- **S0-B Latent Sufficiency Probe（信息充分性）**：冻结 Encoder，只训练很小的线性/MLP 诊断头。B1 = `graph_s` only → `q`/`endpoint`；B2 = `graph_s + key_s + key_v` → `δu = y - u0`；B3 = `key_s + key_v`（无 graph_s）→ `δu`；B4 = `graph_s + key_s`（无 key_v）→ `δu`。Probe 只在 inner-train 上训练，从 inner-train 再切 curve-level probe-val 选 epoch，inner-val 只在最后评估一次；结果只用于「是否继续/是否需要 Adapter」的诊断，**不进入冠军选择**。报告残差 MAE、R²、按 stratum/反应类型分层，并与 M0 的 `||y-u0||` 基线比较。**Go 条件**：B2 的残差 MAE 明显低于 B1/B4（例如相对 B4 改善 ≥10%），说明 `key_v` 有增量信息；否则先改 Bridge，**不加深 Decoder**。
- **S0-C Vector Basis Coverage（基底能力）**：对真实教师残差 `r = y - u0`，逐 key 原子计算 `rank(key_v[k])`、最小/最大奇异值、条件数、投影残差 `||r_perp|| / ||r||`（含通道 0 / 去掉通道 0 两版）、教师系数幅度分布、留一通道后的覆盖率变化，并按 Start / Pre-TS / Post-TS / Endpoint 与 breaking/forming/both 分层。**解释纪律**：8 个任意 3D 向量几乎必然张成 R3，所以「覆盖率≈100%」不是好消息也不是坏消息，真正要看的是**条件数**、**系数是否可预测**、**留一通道是否敏感**；若条件数 >100 或投影残差中位数 >0.5，Bridge 需要重新设计，**不得靠加深 Decoder 掩盖**。
- **S0 出口**：S0-A 全过；S0-B 给出「Bridge 是否有信息」的结论；S0-C 给出「基底是否可用」的结论；三者写入 `encoder_bridge_parity` 报告；任一失败则 WP2 回炉，**不进入 S1**。

**S1（Decoder-only 训练）**：按 §4.3 日程与 §4.5 损失训练当前 Track 的 Refiner；两条 Track 独立训练、独立 checkpoint、独立冠军。

**S2（条件 Adapter / 联合微调，不进入主排名）**：只有 S1 证明「冻结表征不足」时才启动——MOVE 私有向量 Adapter；PROCESS 私有 token Adapter；部分解冻 Encoder（最后 1 层或 norm）；全联合微调（最后手段）。**纪律**：单独登记为 `V543-S2`，独立 run identity、独立预算、独立报告；不与 S1 的固定 Encoder 排名混在一起；可训练 Bridge 必须明确算 Encoder 还是 Decoder 预算，并重新做参数匹配；**S2 的收益不能回溯改写 S1 的冠军**。

### 5.2 独立 fixed-coverage direction 的正式定义（D2 已签认）

对每个含 ≥1 个 changed K-pair 的帧：

```text
dd_y[l] = Δd_l(y) = ||x_i + y_i - (x_j + y_j)|| - ||x_i - x_j||
dd_u[l] = Δd_l(u) = ||x_i + u_i - (x_j + u_j)|| - ||x_i - x_j||
k = min(3, n_pairs)
T_k = 教师 |dd_y| 最大的 k 个 pair（ties 按 pair 索引）
P_k = 预测 |dd_u| 最大的 k 个 pair
fixed_coverage_direction@3 = mean_{l∈T_k} [ sign(dd_u[l]) == sign(dd_y[l]) AND |dd_u[l]| ≥ 0.005 Å ]
topk_overlap@3 = |P_k ∩ T_k| / k
```

**聚合**：帧均值 → 曲线均值 → seed 均值；曲线级 cluster bootstrap；按 Start/Pre-TS/Post-TS/Endpoint 与 breaking/forming/both 分层报告。**为什么独立**：旧 `sign_accuracy` 的分母是「所有教师显著对」，新指标的分母是「教师最关键的 top-3 对」；两者可以背离——模型可能把大量容易对做对，却漏掉最关键对。H2/H3 用新指标，旧指标只作历史对照。

### 5.3 H0–H3 门

**H0 合法性与等价性（任一失败 = `invalid_run`）**：schema/forward-view 白名单；无监督泄漏（哨兵测试）；E(3)（平移不变、旋转/反射等变、原子置换等变、边置换等变）；reverse intent 合同；非关键原子零位移；typed-invalid 输入拒绝；restore/resume；有限梯度、有限 loss；Encoder 每次 forward 恰好 1 次；零残差 parity。

**H1 资源（失败 = `resource_failure` / `budget_censored`）**：单路、无 swap、无 OOM；host ≤12 GB；VRAM 不超线；core-time ratio ≤2.0（分母 = 同环境 M0/P0）；p95 latency ≤2× A0；参数在预算带内。

**H2 逐 seed 非劣（失败 = `scientific_failure`，结果保留）**：

| MOVE（对照同 seed V543 M0） | 允许退化 |
|---|---:|
| `rmse_zero` | ≤2.0% 相对 |
| `sign_accuracy` | ≤0.01 绝对 |
| `dead_fraction` | ≤0.01 绝对增加 |
| `fixed_coverage.direction_at_3` | ≤2.0% 相对 |

| PROCESS（对照同 seed V543 P0） | 允许退化 |
|---|---:|
| `endpoint.auprc` | ≤0.01 绝对 |
| `endpoint.recall_at_fpr_0p05` | ≤0.02 绝对 |
| `q.mae_curve_median` | ≤5.0% 相对 |
| `ordering.pairwise_accuracy_full` | ≤0.02 绝对 |
| `endpoint.ece` | ≤0.02 绝对增加 |

**规则**：每个正式 seed 都必须无 H2 breach；任一 seed breach → 该候选 `scientific_failure`，不得用另一 Track 的收益豁免。**零基线规则**：任何相对阈值（RMSE/zero、fixed-coverage direction、q MAE）在对照基线为 0 或接近 0 时退化为绝对阈值：退化 ≤0.01（比例类）或 ≤0.005 Å（距离类）；该规则已在 WP0 写死，不得事后选择「相对更有利」的解释。

**H3 效应量与统计（对照同 seed V543 M0/P0）**：

MOVE 路线（括号逻辑）：

```text
(rmse_pass AND direction_non_inferior)
OR
(direction_pass AND rmse_non_inferior)

rmse_pass:                    rmse_zero 相对改善 ≥3.0%
direction_pass:               fixed_coverage.direction_at_3 相对改善 ≥3.0%
                              AND 绝对提升 ≥0.01
rmse_non_inferior:            rmse_zero 退化 ≤2.0%
direction_non_inferior:       fixed_coverage.direction_at_3 退化 ≤2.0%
```

PROCESS 路线（括号逻辑）：

```text
(auprc_pass AND q_non_inferior AND recall_non_inferior AND calibration_non_inferior AND ordering_non_inferior)
OR
(q_pass AND auprc_non_inferior AND recall_non_inferior AND calibration_non_inferior)

auprc_pass:                   endpoint.auprc 绝对提升 ≥0.02
q_pass:                       q.mae_curve_median 相对改善 ≥5.0%
                              AND ordering 非劣（退化 ≤0.02）
auprc_non_inferior:           AUPRC 下降 ≤0.01
q_non_inferior:               q MAE 相对退化 ≤5.0%
recall_non_inferior:          recall_at_fpr_0p05 下降 ≤0.02
calibration_non_inferior:     ECE 增加 ≤0.02
ordering_non_inferior:        pairwise_accuracy_full 下降 ≤0.02
```

**统计显著性**：三 seed 中 ≥2 个同向；每个 seed 无 H2 breach；三 seed seed-averaged curve-level paired bootstrap 10,000 draws，95% CI 下界 >0；one-sided p = `(1 + #{seed-averaged paired improvement ≤ 0}) / 10001`；MOVE 两个 exit 各 α=0.025，各自对 eligible candidates 做 Holm；PROCESS 单一 family（2 endpoints × eligible candidates）α=0.025，Holm；报告未校正与校正后结果。

**效应量 margin（用于 tie-break，不替代显著性）**：

```text
move_rmse:        relative_improvement / 0.03
move_direction:   min(relative_improvement / 0.03, absolute_improvement / 0.01)
process_auprc:    delta_auprc / 0.02
process_q:        relative_q_mae_improvement / 0.05
```

### 5.4 统计合同（冻结）

| 项 | 冻结值 |
|---|---|
| bootstrap unit | curve（reaction cluster） |
| pairing | 同 cluster、同 frame set；候选与基线共享 resample indices |
| draws | 10,000 |
| CI | percentile 95%（2.5/97.5） |
| p 值 | one-sided improvement paired cluster bootstrap |
| seed aggregation | 每 draw 先 seed-average，再比较 |
| 缺失 cluster | 两边同时丢弃；报告丢弃数；不插补 |
| frame-level bootstrap | 禁止 |
| 多重比较 | Holm；family 定义见 §5.3 |
| 阈值冻结 | WP0 签认后不得按 seed17/dev 结果修改 |

**q 有效性规则（D3 已签认）**：报告 `n_eval_curves`、`median_points_per_curve`、`frac_curves_ge3`、`frac_curves_ge5`；若 `frac_curves_ge3 < 0.70`，`q.corr_curve_median` 只作诊断、不进入结论，q MAE 与 ordering 仍是主指标；**禁止**用「两点 Pearson=±1」的曲线支持「q 很好」。

### 5.5 基线、dev 与 confirm（D8 已签认）

- **基线**：S0 在 V543 evaluator 下重算 M0/P0 的 per-seed inner-val 文档；SHA 冻结；H2/H3 只用这份基线，**不用 V542 归档数字**。

- **confirm**：**永封存**；`confirm_read=false`；任何读取都是 `invalid_run`。
- **tau**：只在 inner-val 校准一次（target precision 0.9）；dev 不重校准。
- **新 QC**：**0 次**。

2. **strict 加载不可绕过**：V543 必须复用 `pes2ts_core/pesn/models/v542/loader.py::load_a0_strict`（显式映射 + `strict=True` + 逐键 `torch.equal`），**不得另写 `strict=False` 加载器**。A0 checkpoint 的 `model` state dict 有 45 个键 = 37 个 backbone 键 + 2 个 `move_decoder.w_v`（与 `backbone.w_v` 同一 tensor 的 dual-write）+ 6 个 `process_head` 键。
3. **任务语义不变**：MoveProcessContract v1 的单帧输入、合法有向拓扑、TS 可穿越、No-Move 只表示目标端点完成——全部不变；ADR-0031/0032/0033 的合同与冻结阈值不被本 ADR 改写。
4. **外部接口继承 V542**：forward 外部 5 键 `{u, z, q, endpoint_logit, order_score}`、`order_score IS q`、`a_ref=0.08` 非学习常量、`DirectMoveDecoder` 只读 5 个张量——全部沿用。
5. **Encoder 不参加竞争**：A0 是固定 Encoder，不是候选；V5.4.3 不产生 Backbone 冠军，也不与 V541 E0 比较。
6. **registry 是唯一机器可读源**：新增战役必须登记进 `config/registry/g_v_map.yaml`；旧 `V5.4`/`V5.4.1`/`V5.4.2` 条目不动。

## 8. 适用条件与不能声称的结论

**适用条件**：冻结 A0（V542 A0×3 checkpoint）作为唯一 Encoder；`DecoderContextV1` schema/构造/禁读边界不变；两条 Track 独立训练、独立 checkpoint、独立冠军；剂量固定 37,900 flat + 400 warmup；参数带 36K ±5%（单候选硬上限 40,000、整模硬上限 150,000）；H2/H3 用 V543 evaluator 重算的同 seed M0/P0 基线。

**不能声称**：

- 不能声称「A0 最优」或「A0 胜出」——A0 只是固定 Encoder，不参加冠军竞争。
- 不能声称 Flow/Diffusion 必然优于回归——M4/M5 默认关闭，条件激活且单独登记 T8。
- 不能声称单步指标提升等于路径导航成功——闭环收益只在 T7 rollout 上判定，且须 BMP 集成门通过。
- 不能声称「q 高等于 PROCESS 好」——`q_corr` 仅为诊断，`frac_curves_ge3 < 0.70` 时不进入结论。
- 不能声称「8 通道基底覆盖率≈100% 就说明 Bridge 足够」——覆盖率只是必要条件。
- 不能把无物理松弛 rollout 的失败全部归因于 Decoder。
- 不能声称生产级 No-Move、verified-TS、在线部署或任何科学收益；`confirm` 未读、QC=0、dev 仅 T7 一次。

**负结果措辞**：无候选通过 H3、或只有单 seed 证据、或收益被成本抵消时，保留 M0/P0，按冻结措辞记录 `no_decoder_winner`（或 Track 级留任），**不得用「趋势好」「接近显著」替代**。

## 9. 风险、回退与 S2 条件

### 9.1 风险登记（R1–R10，冻结）

| # | 风险 | 触发信号 | 影响 | 缓解 | 回退 |
|---|---|---|---|---|---|
| R1 | Bridge 信息不足 | S0-B probe 明显低于 M0；S0-C 条件数差 | Decoder 再深也无用 | 先改 Bridge；必要时 S2 Adapter | 回炉 WP2，不进入 WP4 |
| R2 | 监督泄漏 | 哨兵测试失败；pair 审计不一致 | 结论无效 | 运行时白名单 + 离线审计 + 代码评审 | `invalid_run`，修复重跑 |
| R3 | A0 parity 漂移 | `u0/q/e0` 不逐位一致 | 基线不可比 | 复用 V542 adapter/loader；hook 计数；CPU 逐位 | 阻断所有训练 |
| R4 | PROCESS 指标虚高 | q_corr≈1 但 q MAE 不降；有效点 <3 | 错误晋级 | q MAE/ordering/有效点数同报 | q_corr 只作诊断 |
| R5 | 缓存膨胀/损坏 | 磁盘 >30 GB；命中率 <50%；SHA 不匹配 | 训练中断/结果污染 | LRU、分片、身份校验、live fallback | 关闭缓存，live encoder |
| R6 | seed43 MOVE 不稳定 | 前两 seed 好、seed43 H2 breach | 冠军无效 | 三 seed 必需；H2 逐 seed | `scientific_failure`，保留 M0 |
| R7 | 算力超支 | 单 run >2.5 h；OOM/swap | 预算/日历 | 熔断、恢复、单路 | `resource_failure`/`budget_censored` |
| R8 | 选择过拟合 | 7 候选 × 2 seed 的噪声 | 假冠军 | top2 预注册、Holm、三 seed、dev 一次性 | 无合格则留任 |
| R9 | rollout 失败 | 单步好但闭环差 | 不能宣称路径成功 | 四组合、物理松弛分开、V6 物理反馈 | 只声明单步改进 |
| R10 | 治理漂移 | docs gate 失败；SHA 不一致 | 不可复现 | WP0 冻结；append-only；SHA 记录 | 停止并审计 |

### 9.2 回退路径

- **S0 失败** → 阻断全部训练，按缺陷类别（代码/数据/初始化/hook）修复并 bump 对应 identity 层，重跑 S0-A；不得「近似相等」放行。
- **S1 证明冻结表征不足**（S0-B/S0-C 或 S1 系统性瓶颈）→ 启动 S2（私有 Adapter / 部分解冻 / 联合微调），单独登记 `V543-S2`、独立预算与报告；S2 收益不得回溯改写 S1 冠军。
- **成本或资源越界** → `gate_skipped_cost_ratio_exceeds_2` / `resource_failure` / `budget_censored`，科学结果保留但不晋级；禁止减帧/减层/减 updates 等事后绕行。
- **无合格候选** → M0/P0 留任，按冻结措辞记录；不补替补、不换 seed、不降阈值。
- **治理不一致**（docs gate 失败、SHA 不一致、registry 与 config 漂移）→ 停止并审计，修复后方可继续。

### 9.3 未决事项

- **估算参数量的回填**：M1–M5、P1–P5、P4-C 的参数量是设计起点（含 `约` 值），构造时必须按 `sum(p.numel())` 调整宽度使精确值落入 34,200–37,800 并回填 registry；估算值不得作为实现前 exact 断言。
- **pair_s 40–47 维的两实现方案**：固定 `W_fixed` sketch 与「8 个固定索引的 `key_s` 差值」二者取其一，必须在 Bridge 规格中冻结（影响 `bridge_spec_sha256`）。
- **预算与 runplan PIN**：budget 数值、同环境 profile、runplan SHA 在 WP7 前不产生；生成后须签认并同步 run identity，**不得**以默认值或占位值替代。
- **config/validator/registry 条目**由并行 lane 落地；本 ADR 只冻结语义，落地一致性由 docs gate 与 validator typed rejection 机器核验。

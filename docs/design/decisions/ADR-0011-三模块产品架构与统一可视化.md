# ADR-0011：三模块产品架构与统一可视化

> 状态：Accepted（用户要求的产品架构与开发方向；统一代码模块、接口schema、UI和真实能力另验收）
> 层级：G1/G2整合，G3/G4策略扩展；工作流C/R/X
> 取代关系：细化ADR-0010的宿主产品视图，承接ADR-0002的ACP执行与展示边界；不取代既有阶段、接口或历史验收
> 上游依赖：[开发宪法](../../PES2TS_开发宪法_v1.md)、[ADR-0010](ADR-0010-PES-N反应状态价值与STOP-MOVE统一决策.md)
> 下游消费者：[三模块产品架构设计](../PES2TS_三模块与可视化产品架构_v1_20261005.md)、PES-N计划、模块整合、ACP展示及产品验收
> 当前版本：v1 @ 2026-10-05

## 背景与变更声明

用户希望把已有G1/G2组件整合为“拓扑约束＋控制器＋计算器”，增加可视化层，形成方便使用且架构极简的产品。现有图/事件、坐标池、规划、continuation、质量检查、验证和ACP接缝可复用，但仍分散，弱输入、统一模块、模型和完整严格验证未全部验收。

本决策补充宪法§2的产品视图及§5的不同完整度输入语义，沿用§9.6已登记的ChemicalControlSpec等接口族。未改变R1–R6、阶段出口、方法预算或生产默认；未在本轮新增具体schema或迁移目录。

## 决策与影响

1. 运行时产品采用三个逻辑模块和一个横向可视化层，不把G0–G4当作产品组件，也不要求三个独立服务或重排目录。
2. 拓扑模块整合输入适配、化学条件编译及独立规则服务；控制器调用规则服务进行候选预检和响应后验，模型不覆盖规则裁决。
3. 输入支持完整R/P目标、部分事件和坐标设想的设计分支，缺失与假设显式保留。现有输入合同不被空P或新UI绕开；目标不充分时目标p_seed/Q_STOP不可用，新分支按新版本合同及能力逐项验收。
4. 控制器复用Classic，逐步接入PES-N的STOP、残差与MOVE-Q；独立纯推理内核、显式选择、风险及backup边界沿用ADR-0010。
5. 计算器在PES2TS侧是ACP接缝。物理基元、引擎、调度/进程/资源、取消和基础任务/帧展示归ACP；化学目标与实际结果判定归PES2TS。
6. 一个用户工作台聚合输入、编译检查、运行与结果。优先复用ACP Workbench及注册接线；PES2TS提供化学语义和展示投影。预测、物理观测、运行状态和严格证据分别呈现。
7. 三模块通过已登记合同和不可变身份连接，旧产物只读，新旁车绑定原hash。UI与CLI共享应用门面；训练/参考真值留在隔离侧，结果展示不成为在线推理回流通道。

详细责任、组件映射、输入能力、交互和分期验收见设计文档。规范仅以宪法为准，此处记录选择及影响。

## 版本化、证据与同步

本轮同步宪法内容v2.1、AGENT投影v3.1、PES-N计划v2.1、项目发布方案v3.1、台账与索引。设计保留现有目录和生产代码；具体schema、应用门面及前端接缝在实现批次中另登记。

证据范围为源文件/已有接口定位、上游规范一致性、文档链接与变更范围检查。没有运行QC、训练或UI，没有把组件存在升级为smoke_passed。实施验收分别覆盖兼容/回放、规则独立、能力真实收据、UI身份联动、严格验证及全量费用，继续使用既有阶段门。

## 回退

产品适配或新策略未达验收门时保留原CLI、Classic冻结配方和旧产物读取；未来弱输入/模型输出按availability关闭，不将不完整目标补写成确定反应。具体实施变更以新版本回退，不覆盖历史记录。

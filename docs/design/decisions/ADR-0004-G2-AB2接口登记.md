## 背景（Context）

G2-AB2 批次以 24 例首轮端到端战役为唯一主轴，产出四个新版本化接口与一个生产适配器落地。按宪法 P1（接口只以新版本变更、只固定存在性与校验）与 §9.6（登记义务），本 ADR 是该批次的登记决策记录；字段演进不要求新 ADR，语义破坏性变更要求。

## 决策（Decision）

以下接口按"存在性 + 校验"登记（实现落点以代码为准；离线 V0 全部进默认测试套件）：

1. **`pes2ts_campaign_manifest_v1`（战役合同；WP-1，`pes2ts_core/generation/campaign.py`）**
   存在性字段：`cases[{reaction_id, snapshot_path, snapshot_sha256}]`（冻结顺序、唯一、64 位十六进制 hash）、`pilot_cases`、`frozen_parameters{continuation_policy, local_policy, branch_policy, origin_preparation, candidate_top_k∈[1,3]}`、`budget`（每路径上限**必须等于**冻结 continuation policy 的对应字段——单一事实来源，违反即 `BUDGET_POLICY_MISMATCH`）、`acp_wiring`、`review_status`（逐例覆盖全案例集，词表 `needs_review|accepted|rejected`）、`reference_failures`。`content_sha256` 为战役身份：同一输出根目录拒绝不同身份的 manifest（`CAMPAIGN_ROOT_IDENTITY_MISMATCH`——改参数/预算 = 新战役新根）。
2. **`pes2ts_g2t_terminal_state_v1`（逐例 typed 终态；WP-1/WP-4）**
   `terminal_class ∈ {rejected_typed, partial_prefix, complete_path, validated_passed, validated_failed, validated_incomplete, censored_budget, blocked}`；前三类 + `validated_*` 为报告的四类分母，`censored_budget`/`blocked` 为显式非成功审计态，**永不折入成功分母**（§11.4；该规则是 `pes2ts_g2t_feedback_report_v1` 的冻结校验项）。每终态携带：`label_state`（宪法 §9.2 七态）、`stage_reached`、`failure_code`/`blocked_reason`+`blocked_needs`（P2 typed）、`identity_conflict_count`、`n_accepted_frames_beyond_origin`、`last_accepted_lambda`、`candidates`、`costs` 引用、`validation` 子块（默认 `blocked_on_human_review` + 需求清单，不自动生成复核）。幂等纪律：终态已定且输入 hash 未变且非 blocked → 跳过；blocked 可重试；恢复不改参数。
3. **`ORCAOriginPreparation`（起点自由优化 ACP 生产适配器；WP-3，`pes2ts_core/integration/acp/origin_backend.py`）**
   落地 ADR-0003 登记的 `endpoint_method_evidence_v1` 的生产 `evaluate_free`：经 ACP `BatchOptimize` 非 TS profile（`--profile opt`，role `minimum`）执行；fail-closed 能力探测（wiring 解析 + `acp.cli run BatchOptimize --help` 探针）失败 → typed `ORIGIN_BACKEND_UNAVAILABLE` + 需求清单，**无本地回退**（R3）；评估身份内容寻址（`origin-<NNNN>/eval-<content16>`，同址异 binding = `IDENTITY_CONFLICT`）；claim/receipt/log/timeout 纪律与 stage_cli/orca_gradient_transport 同构（本模块加入 `SUBPROCESS_IMPORT_ALLOWLIST`，仅 subprocess 导入豁免，真值检查全量适用）；`landing_free_opt` 为独立 operation 身份。离线 V0：假 ACP 测试（`tests/test_acp_origin_backend.py`）；真实引擎 V2：待 ACP 环境（ACP-G2-04）。
4. **`pes2ts_branch_calibration_v1`（分支参数校准报告；WP-2-A，`pes2ts_core/generation/planning/branch_calibration.py`）**
   存在性：`grid`、`criteria`（branch_selection_ok / biased_only_honest / cumulative_gate_discriminates / probe_budget_respected 四判据）、`conservative_ordering`、`chosen_cell`（最保守通过格：最强 kappa → 最小半径 → 最少释放迭代 → 最严格累计限 → 最小探针预算）、`calibration_set_sha256`（校准集=解析 fixture 身份 hash）、`holdout_touched=false`（R6 冻结声明）。选中值与 `config/defaults.yaml`（`g2.continuation.branch_policy` 等）由测试互锁（`CHOSEN_BRANCH_POLICY`），config 与代码不得漂移。
5. **`pes2ts_g2t_feedback_report_v1`（第一份反馈报告；WP-6，`pes2ts_core/generation/campaign_report.py`）**
   内容清单 1–9 冻结：漏斗（四类分母分列）、typed 失败直方图（码 × 阶段 × 案例 + 中位成本）、B1-1…B1-4 对照（逐例证据引用）、分支证据统计（AB1 字段首次真实统计：接受帧分布/`biased_only` 率/累计漂移/曲率探针）、候选与验证（验证终态或 blocked 原因）、成本总表（R5 汇总/缓存命中率/失败成本占比）、最小 `J_G`（无条件项：无 verified 数据时显式 no-data 并注明完整口径属 G3.0 前置批次）、AB3 改进清单（由直方图机械导出 + 证据引用）、能力状态词表（§11.5 四层）。反过宣称冻结校验：`m0_through_m5_claimed=false`、无 success_rate 字段、`rejected/censored/blocked` 永不入成功分母。
6. **`pes2ts_pilot_replay_report_v1`（试点判定器；WP-2，`pes2ts_core/generation/planning/replay_report.py`）**
   纯函数判定 `passed/failed/blocked` + 冻结判据（零身份冲突；越过参照失败 λ 且 ≥1 接受帧；断键起点须产出完整 `ORIGIN_CONNECTION_LOST` 细节）。判定器无 I/O、判据不可经 CLI 放宽（方案 §10 禁位移门）。blocked ≠ failed（环境缺失带需求清单）。
7. **成本账本采集（`pes2ts_case_costs_v1`；WP-1，`cost_capture.py`）**
   落地 ADR-0003 登记的 `calculation_cost_v1` 计数规则到战役账本：attempt 级 `N_energy=N_gradient`（EnGrad 同次返回）、缓存命中 = 真实零 + `cost_source=cache_hit:*`、`cpu_seconds` 优先 receipt 实测 `wall_seconds`、缺失 = null+reason（禁写 0）、曲率探针独立账本（内部梯度只计一次，父子经 `includes_cost_ids` 去重）、逐例聚合经 `flywheel.aggregate_costs`。blocked 案例写空账本（零尝试的可审计记录）。

## 后果（Consequences）

- 上述校验进入默认测试套件：`tests/test_campaign.py`、`test_cost_capture.py`、`test_acp_origin_backend.py`、`test_replay_report.py`、`test_campaign_report.py`、`test_g2t_cli.py`；放宽任何一条即测试失败。
- 新 CLI 入口：`pes2ts g2t-manifest` / `g2t-run` / `g2t-status` / `g2t-report`（只读状态与报告不新增执行旁路；生成执行链与 AB1 完全同一 ACP 路径）。
- 不改变 R1–R6；`SUBPROCESS_IMPORT_ALLOWLIST` 增补 `origin_backend.py` 一项（argv-only 子进程纪律与既有适配器一致，真值/动态执行检查全量适用）。
- Preparation Layer 缺口维持显式 `preparation_layer_status=absent`（宪法 §8），本批不伪造。
- V2（真引擎试点/全量/验证）与 V3（反馈报告实跑）为 gated：通过前相关能力保持 `implemented`/`fixture_passed`（§11.5），不升 `smoke_passed`。

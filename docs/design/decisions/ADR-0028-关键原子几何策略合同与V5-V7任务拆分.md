# ADR-0028：关键原子几何策略合同与 V5–V7 任务拆分

> 状态：Proposed（设计冻结；实现前需签认）
> 日期：2026-10-20
> 层级：G3.P.0–.3（V5）、G3.2 + G2.T（V6）、G4.0/G4.1（V7）
> 取代关系：局部取代 [V5–V7 v1.2](../../plans/PES2TS_PES-N_V5-V7架构调整与实施计划_v1.2_20261018.md) 的 V5/V6/V7 分工；不覆盖 V5.1a/R1 冻结证据
> 上游依赖：[ADR-0026](ADR-0026-V5冲刺key-atom位移合同与OOF语义.md)、[V5.1a-R1 最终报告](../../../outputs/pesn/v5_1_r1/final_report.md)
> 下游消费者：V5.1-R2、V5.2–V5.4、V6.1–V6.3、V7.1–V7.3

## 1. 背景

V5.1a/R1 的失败暴露出三个任务级问题：

1. **旧任务与新目标未分离**：旧 V5.1a/R1 仍围绕全原子/旧 key-atom 位移构建部分训练与指标；新目标是“仅关键原子位移 + 曲线停止位置”。
2. **幅度问题被误读为全局尺度**：R1 证明 s*≈1.008、6/7 RMSE 变差，全局校准被证伪；strong 欠猜 + dead 虚假变化的相反方向与异方差条件均值收缩相符（尚非唯一统计证明）。
3. **辅助损失梯度尺度失控**：exact_trio 超配 4–6 倍，桶均值项只有 0.42%；继续调 λ 没有信息量。

因此需要冻结新的在线合同，并把“旧任务机制修复”和“新任务架构开发”拆成两个独立阶段。

## 2. 决策

### 2.1 冻结 GeometryPolicyContract v1

在线接口固定为：

\[
\pi(X_t,G)\longrightarrow(\Delta X_{K,t},m_t)
\]

- 输入仅当前唯一完整构型 + 合法拓扑/反应约束；
- 输出仅 K 个关键原子位移 + Move/No-Move；
- 非关键原子参与编码，不输出位移；
- 历史 IRC 只作离线教师；RNN 记忆不得成为在线必要输入；
- No-Move = 反应曲线停止位置选择，不是普通不确定性拒绝；
- No-Move 选中坐标 = 当前 \(X_t\)，是 OptTS 候选初猜，不是已验证 TS。

详见 [GeometryPolicyContract v1](../../contracts/PES2TS_GeometryPolicyContract_v1.md)。

### 2.2 任务拆分

| 阶段 | 任务 | 数据/指标 | 是否正式 OOF |
|---|---|---|---|
| **V5.1a / R1** | 旧 key-atom 任务的机制诊断 | 旧 5-fold、旧 key-atom 标签 | 否；冻结证据 |
| **V5.1-R2** | 旧任务上的损失尺度 + S1 数据质量 | 旧任务、旧 split，仅训练机制修复 | 否 |
| **V5.2** | 新 Key-Atom-only 合同、K 掩码、多尺度 IRC 教师、停止标签 | 新合同/新标签/新分母 | 否（合同阶段） |
| **V5.3–V5.4** | 纯几何 EGNN、路径一致性、rollout/Stop | 新监督门 | 仅预注册开发确认；正式 OOF 另批 |
| **V6.1–V6.3** | xTB 物理修正 MLP/CNN、真实验证 | 物理搜索门 | 否；先开发/验证 |
| **V7.1–V7.3** | RL 环境、离线 RL、受控在线 RL | 真实转移/成本 | 否；按 G4 门 |

### 2.3 V5.1b 保持关闭

- V5.1a B3 `rejected_gate`；R1 无候选准入。
- V5.1b 的 15-run 3-seed OOF **不启动**。
- V5.1-R2 无权自我批准 V5.1b；R2 的正结果最多成为 V5.2 基线候选。
- 新 V5.2 不得通过改名绕过旧封存协议、Confirm/OOD 或 Fit150 禁令。

### 2.4 旧证据冻结

- V5.1a/R1 的 config、protocol、run records、reports、outputs 只读保留；
- 不删除、不改写、不重新解释为 V5.2 证据；
- 旧 V5 OOF 的 RMSE/zero 0.824、cos 0.780、α 0.6757 只作历史参照；
- 新任务必须用新标签重跑匹配基线（zero/Classic/MLP/EGNN/PaiNN）。

## 3. 备选方案

| 方案 | 结论 | 理由 |
|---|---|---|
| 继续在旧任务上调 λ/加 magnitude head | 拒绝 | R1 已证伪全局尺度/当前桶损失 |
| 直接把旧 V5.1a 分数当新任务基线 | 拒绝 | 任务/标签/分母不同，混分不可比 |
| 先做 V6 xTB 再补 V5 几何 | 拒绝 | 几何导航未成立，物理修正无基线 |
| 先做 V7 RL 再补监督 | 拒绝 | 缺少真实环境/转移/成本证据 |
| V5.1-R2 → V5.2 新合同 → V5.3–V5.4 → V6 → V7 | 采用 | 逐级假设，失败可归因 |

## 4. 后果

- V5.2 需要新的数据合同、K 掩码、停止标签、评估分母；旧 `key_atom_bc` 不原地改写。
- V6/V7 继承同一状态/动作语义；V6 只增加一次调用内部的 xTB 探测，不改变 Actor 在线输入边界。
- 新增评估门（监督门/物理搜索门）由 ADR-0029 登记；旧 G5.2/G5.3/G5.4 保留。
- 任何合同字段/语义变更必须新版本 + ADR + fixture，不得静默兼容。

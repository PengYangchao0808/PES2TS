# ADR-0022：v4.1 因果输入合同与特征 v3（观测-only 5 通道）

> 状态：Accepted（用户下达的 v4.1 P01 修复；可执行接口、数据重建与验收测试另验收）
> 层级：G3.P/G3.2、G4.0/G4.1 研究；工作流 R
> 取代关系：局部取代 ADR-0021 关于 `pesn_dual_ts_features_v2` 的 7 通道 node_scalar 布局；不取代 v4 阶段其他冻结决策（近零阈值、监督语义、monitor8 门、disputed-5 规则均不变）
> 上游依赖：开发宪法 §7（数据合同变更 → 新 schema 版本）、ADR-0021、[v4 阶段最终报告](../../reports/PES2TS_v4阶段训练_最终报告与问题复核_20261017.md) P01
> 下游消费者：特征构建/训练/自由运行/评测链路、合同注册表、docs 修订台账
> 当前版本：v1.0 @ 2026-10-17

## 背景与证据

v4 阶段最终报告 P01 确认：dual-TS 策略的 `node_scalars` 原有 7 通道，其中第 5 通道 `is_teacher_endpoint` 与第 6 通道 `near_zero_action_mask` 由教师下一步动作 / 终点标签派生。离线训练时二者语义为“教师离开动作 < 0.01 Å”；自由运行 rollout 时二者改由上一已执行动作计算——同一通道、不同语义，5967 非终态中 4149 态至少一原子掩码不同。这违反红线 R1（真值不得进入状态输入）。修复：网络输入（actor/Q/V）改为纯观测 5 通道；教师标签仅保留在监督目标、损失掩码与离线评估元数据中。

## 决策与影响

1. **拆分数据结构**（`dual_ts_graph.py`）：`build_state_features` 只接收可观测量（state_id、atomic_numbers、coordinates、gradient、delta_e_hartree、s_g、s_delta_e、charge、multiplicity），返回 `node_scalars` 形状 (N,5) = `[z_id, grad_norm_scaled, delta_e_scaled, charge, multiplicity]`；拓扑块由 `build_topology_features` 照旧提供。新增 `build_teacher_supervision` 产出监督记录 `DualTeacherSupervision`（`near_zero_action_mask`、`is_teacher_endpoint`），规则与拆分前逐位一致（终态 → 全 True；非终态且 `action_delta is None` → 保留 `ACTION_MISSING` 拒绝身份；否则逐原子 `‖a_i‖ < 0.01 Å`）。`DualStateFeatures` 仅存观测字段，监督字段移入 `DualTeacherSupervision`。
2. **规格/合同版本升级**：`declared_layout_blocks()` node_scalar 7→5（input_dim 17→15）；`NODE_SCALAR_NAMES` 去掉两名称；`DUAL_TS_FEATURES_FREEZE_VERSION` → `pesn_dual_ts_features_v3_wp41_freeze_v0`。合同 `FEATURES_SCHEMA_VERSION` → `pesn_dual_ts_features_v3` 并新增注册校验器；同时保留 `FEATURES_SCHEMA_VERSION_V2 = "pesn_dual_ts_features_v2"` 继续注册，旧产物仍可读。
3. **shard 构建**（`build_dual_ts_features.py`）：观测块走观测-only builder，监督走 `build_teacher_supervision`；npz 键 `near_zero_action_mask`/`is_teacher_endpoint` 仍写出（监督元数据，供损失掩码/评测消费），其余键不变。`MANIFEST_SCHEMA` → `pes2ts_dual_ts_wp41_features_manifest_v1`，`TOOL_VERSION` → `pes2ts_dual_ts_features_build_wp41_observation_only_v1`；默认 `--out` → `outputs/pesn/dual_ts_v2_20261015/wp3_features_v41`（旧 `wp3_features` 不动）。
4. **自由运行统一**（`dual_ts_freerun.py`）：`build_rollout_state_inputs` 不再传 `is_teacher_endpoint`/`action_delta`——在线路径与离线路径调用同一观测-only builder；`FREERUN_VERSION` 升 v1.1；bundle↔spec digest 门对新 spec digest 继续生效。
5. **训练/评测载入**（`dual_ts_bc.py`、`dual_ts_monitor.py`）：监督键仍读 npz 顶层键；载入时存储-vs-重算掩码校验改经 `build_teacher_supervision`；`DUAL_TS_BC_VERSION` 升 v1.1，`dataset_version` 字符串模式 → `pesn_dual_ts_features_v3@<digest>`。`dual_ts_iql.py` 版本升 v2.1（digest 身份门不变量不变）。
6. **模型侧**：`N_NODE_SCALARS` 派生使形状自动；`state_inputs_to_tensors` 增加载入期宽度守卫——`node_scalars.shape[-1] != N_NODE_SCALARS` 时抛显式命名错误 `NODE_SCALAR_WIDTH_MISMATCH`，7 通道旧 shard 喂新代码即大声失败。旧 checkpoint 与旧 spec 有意不兼容（digest + 形状双门），不做 legacy 载入。

**变更的版本常量清单**：`FEATURES_SCHEMA_VERSION`（v2→v3，新增 `FEATURES_SCHEMA_VERSION_V2` 保留注册）、`DUAL_TS_FEATURES_FREEZE_VERSION`、`MANIFEST_SCHEMA`、`TOOL_VERSION`、`FREERUN_VERSION`、`DUAL_TS_BC_VERSION`、`DUAL_TS_IQL_VERSION`，以及 BC 的 `dataset_version` 字符串模式。

## 替代与取舍

不采用“保留 7 通道但改自由运行语义以与离线对齐”——那会把同一通道继续暴露为状态输入且难以审计，仍违反 R1。不采用“直接改旧产物”——旧 shard/checkpoint/评测记录为历史对照，必须只读。为此新特征写入新目录（`wp3_features_v41`、`wp4_monitor/features_v41`），默认目录显式迁移而非静默覆盖。教师标签信息并未删除，而是仅移出网络输入（监督目标、`dir_mask = valid & ~near_zero`、离线评测元数据保留不变）。

## 状态与验收

本次交付特征 v3 数据合同、观测-only 输入、shard 重建（fit50 与 monitor 波）与两条验收测试（教师标签干预、离线/在线一致性），并跑通全 pesn 测试套件。**不声明**：本修复不证明旧模型曾依赖通道 5/6 做预测（仅证明输入合同存在因果缺陷）；不重新训练、不重跑 monitor8、不改任何门阈值（`NEAR_ZERO_ACTION_THRESHOLD_ANGSTROM=0.01`、monitor8 阈值、监督语义 `dir_mask = valid & ~near_zero` 均保持不变）。旧模型/旧协议/旧结果仅作历史对照。后续 v4.1 统一采样（WP2）与分阶段重训（WP4）在本次冻结基础上推进。

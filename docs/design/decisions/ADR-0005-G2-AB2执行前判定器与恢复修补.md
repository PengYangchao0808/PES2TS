## 背景（Context）

[g2t-real-campaign 计划](../../../.omo/plans/g2t-real-campaign.md) 在执行前审查（[审查记录](../../../.omo/evidence/g2t-real-campaign-review_20261004.md)）中被判定"先修订再执行"：四个已实证的缺陷会在真实战役中静默破坏已完成结果与账本、误判 ACP 能力可用、或以与 G2-AB2 §1.3 D2 原文不一致的判据放行/否决试点。计划 Wave 0 以 TDD 先红后绿修复这四项；本 ADR 是这四项的正式登记决策记录（宪法 P1：接口只以新版本变更、只固定存在性与校验；§9.6：登记义务）。

四项修补的共同纪律：**先修订后执行，非事后放宽**。判定器语义修订（第 4 项）在 S2 试点开跑前完成 ADR 登记、schema 升版与测试锁定；执行阶段禁止任何临时放宽（计划 Must NOT 条款）。第 1–3 项由并行工作流实现，本 ADR 只登记其存在性与校验要求。

## 决策（Decision）

### 1. 战役恢复顺序：已完成终态先于预算检查（T2，`campaign.py`）

**变更**：`run_campaign` 循环改为**先**识别并保留已有终态（终态已定、输入 hash 未变、非 blocked → 幂等跳过，不进预算分支），**后**对未完成例应用会话预算（墙钟与梯度总量）；预算耗尽的未完成例照旧写 `blocked` + 需求清单。
**依据**：审查 §P1-2（mock 复现：预算耗尽重入时已有终态读取 0 次、跳过 0 次，完成例被改写为 blocked 且 `costs.json` 被覆盖为 `ledgers=[]、aggregate=null`；代码位置 `campaign.py:469-485` 实证预算检查先于终态读取）。计划 T2、Scope 第 1 条。
**证据门**：`tests/test_campaign.py` 新增回归测试先红后绿（预算耗尽重入：例 A 终态仍 complete、账本保留、`n_skipped_idempotent≥1`）；`pytest tests/test_campaign.py -v --tb=short -rA` 全绿。
**不能宣称**：不改变预算语义本身（超限仍 `censored_budget`/blocked）；不放宽身份互锁；不证明中断恢复在真实引擎上已完成（该证据属 V2/S3）。

### 2. 缓存复用证据透传：`acp.reused` → `cache_hit` 账本（T3，`gradient_backend.py` + `cost_capture.py`）

**变更**：`ORCALocalCorrector` 命中本地 receipt 缓存（现直接返回旧记录）时，返回结果顶层 `backend_evidence.acp` 必须携带 `reused: true` 及原 evaluation 身份，使 `capture_continuation_costs`（`cost_capture.py:56` 依 `acp.get("reused")`）产出 `cost_source="cache_hit:<attempt>"` 的零成本账本。
**依据**：审查 §P1-3（`gradient_backend.py:372-377` 缓存返回无该标志，真实复用仍按旧梯度数重新记账，T8 双跑验收无法按原断言通过）。计划 T3、Scope 第 2 条。
**证据门**：新增测试先红后绿——合成双调场景二调账本 `cost_source=cache_hit:*` 且 `N_gradient=0`；`tests/test_cost_capture.py` / `tests/test_acp_orca_gradient_transport.py` 全绿。首跑与二跑账本独立归档对照，不以二跑覆盖首跑（T14 双跑协议）。
**不能宣称**：不虚构能量/时间；缓存命中必须真零成本 + 来源；不改身份绑定逻辑（`request_sha256` 冲突仍抛）；不证明真实 ACP 复用在真引擎上触发（属 V2）。

### 3. 起点 BatchOptimize profile：`opt` → `opt_only`（T4，`origin_backend.py`）

**变更**：`ORIGIN_PROFILE` 由 `"opt"` 改为 `"opt_only"`；能量产物 glob/键名与 ACP `BatchOptimize` `opt_only` profile 的实际产物命名核对，不一致则修并留证据。
**依据**：审查 §P1-1（`origin_backend.py:53` 为 `opt`，而 ACP CLI `cli.py:852` 的 choices 仅接受 `opt_only/opt_freq/opt_freq_sp/opt_freq_sp_thermo`；`--help` 可通过，实际请求被 argparse 拒绝——help 成功 ≠ 能力可用）。计划 T4、Scope 第 3 条。
**证据门**：`tests/test_acp_origin_backend.py` fake-ACP 断言请求 `--profile opt_only`（先红后绿）；证据含 ACP 产物命名核对结论（源码行引用或 T11 真实请求实物）。
**不能宣称**：不改 ACP 仓；能量缺失仍诚实 `None`（`ORIGIN_ENERGY_UNAVAILABLE`），不伪造；profile 值对齐不代表起点能力真实可用（真实请求 + 产物联合验收属 T11/V2）。

### 4. 试点判定器语义 v2（T5，`replay_report.py`；本 ADR 核心）

**变更**：

- `PILOT_REPLAY_SCHEMA`：`pes2ts_pilot_replay_report_v1` → **`pes2ts_pilot_replay_report_v2`**（版本化接口变更，P1）；聚合报告新增 **`criteria_revision: "v2_adr0005"`** 字段；
- `judge_pilot_case`：**起点失败例**（`origin_status == "failed"`）→ `verdict = passed` 当且仅当 `identity_conflicts` 通过 且 `origin_failure_typed` 通过；`criteria.progressed_beyond_reference` 记 **`None`（JSON null）** 并附 `criteria_note`（该判据对起点失败例不适用）；
- **其余例**（到达 continuation 的重放例）：三判据照旧全须通过（`progressed_beyond_reference` 仍然必需）；
- `terminal_class == "blocked"`：维持 `blocked`（带 needs 清单），**永不折为 failed**，且优先于起点语义；
- identity 冲突与 `ORIGIN_CONNECTION_LOST` 细节完整性**不降级**：起点失败例 identity 冲突仍 failed；细节不完整（码不符/缺原子对或前后距离/hash 不符）仍 failed；
- `judge_pilot` 聚合：`all_passed` 维持 `counts.passed == len(verdicts) and blocked == 0`；判定器保持纯函数（无 I/O），判据不可经 CLI 放宽（计划 §10 禁位移门）。

**依据**：审查"其他"第 3 条——"判定器目前对正确分型的 `ORIGIN_CONNECTION_LOST` 仍要求接受进度，因此该例会 failed、触发 NO-GO。计划应明确接受此停止结果；**若要把它算独立工程通过，须先正式修订判定语义，不能执行后临时放宽**"。G2-AB2 §1.3 D2 原文（`docs/plans/..._20261004.md:54`）——"越原失败区继续多个接受帧；无 `IDENTITY_CONFLICT`；**断键起点产出 `ORIGIN_CONNECTION_LOST`（含原子对/前后距离）**"：断键试点例的判据即起点分型，"beyond original failure zone with accepted frames" 适用于重放例。v1 的"三判据全必需"会使合法断键例永远 failed，与 D2 原文矛盾（本次修订是**执行前**的规范对齐，不是失败后的门限松动）。计划 T5、Success criteria 3。
**证据门**：`tests/test_replay_report.py` 先红后绿（红：`T5-01-red.log` 3 failed / 10 passed；绿：`T5-02-green.log` 13 passed / rc 0），覆盖：origin-failed 完整分型 → passed；blocked 维持 blocked（即使带起点失败证据）；到达 continuation 的例仍要 progressed；identity 冲突在两条路径都失败；聚合 schema v2 + `criteria_revision`。v1 中"origin-failed 必 failed"的断言按修订**有意更新**并记录在案。
**不能宣称**：v2 仍只证明**工程可用性，不证明化学正确性**（§11.5；聚合报告 notes 固定该声明）；不放宽 identity 冲突判据；不放宽 `ORIGIN_CONNECTION_LOST` 细节完整性；不引入 CLI 参数调整判据；不把 blocked 当成功或失败；不替代成本完整性门（无账本不入报告，由驱动层独立校验，T15）。

## 后果（Consequences）

- 接口登记：判定器 schema 升 v2（ADR-0004 登记的 `pes2ts_pilot_replay_report_v1` 语义被本 ADR 修订；字段演进按 P1 以新版本变更）。
- 测试锁定：`tests/test_replay_report.py` 的 v1 origin-failed 断言作为本次修订的一部分被有意更新；四项修补的回归测试进入默认套件，放宽任何一条即测试失败。
- 执行纪律：S2 起判定器零改动；任何后续语义变更必须再走新 ADR + schema 升版，禁止执行期临时放宽。
- 第 1–3 项由并行工作流在其模块内实现（本 ADR 只登记要求与证据门）；T5 本项由本修订落地。
- 不改变能力层级：四项修补在真实证据（V2/V3）前至多 `fixture_passed`；不声明 M0–M5、无 success_rate、失败/blocked/censored 不入成功侧。

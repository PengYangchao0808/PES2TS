## 0. 背景与问题

仓库 Python 代码约 **44.5 万行**（`archive/` 11.2 万、`tests/` 15.0 万、`pes2ts_core/` 16.2 万、其余约 2 万），但**活跃业务代码不足 2 万行**。问题是结构性的：每一轮战役（V5、V5.1-R3、V5.2-R、V5.3-MP、V5.4.1/2/3、V5.6）都把"新版本"实现为**新脚本目录 + 新 config 目录 + 新训练入口**，导致：

1. 同一件事有多份实现：多个 driver 各自写 `loss.backward()`/`optimizer.step()`，训练循环语义随战役漂移；
2. 文件名即版本号：`v541_*.py`、`v543_*.py`、`run_v5_1_r3.py` 之类以战役版本命名的代码文件持续堆积，活跃区无法回答"当前入口是哪一个"；
3. 依赖方向失控：脚本 import 战役配置，战役配置 import 历史脚本，`archive` 与活跃代码边界模糊；
4. 46 万行里只有顶部约 2 万行是"现在有效的"，其余是**必须可检索但不得被调用**的历史。

本 ADR 不评价任何科学结论，只回答一个工程问题：**如何让"当前代码"有唯一位置、唯一入口、单向依赖，并让违反者在 CI 变红。**

## 1. 决策

### 1.1 五功能区（Zone 1–5）

| Zone | 目录 | 职责 | 读写 |
|---|---|---|---|
| 1 内核 | `pes2ts_core/` | `utils/`、`g0/`、`g1/`、`generation/`、`integration/acp/`、`ranking/`、`evaluation/`；`pes2ts_core/pesn/` 为 V4+V5.1–V5.4 冻结模型区 | 保护；`pesn/` 只读 |
| 2 数据 | `pes2ts_data/` | `contracts.py`（`StandardBatch`）、`splits/`、`ingest/`、`registry.py`、`builders/`（原 `scripts/datastore`） | 活跃 |
| 3 引擎 | `pes2ts_v5/` | **唯一**训练/评估引擎：`configs/`、`data/`、`models/`、`losses/`、`training/`、`evaluation/`、`runner.py`、`screening.py` | 活跃 |
| 4 基础设施 | `infra/` | `runtime/`（WSL/内存/GPU 工具、`sha_sidecar`）、`governance/`（文档门禁、G–V 渲染、`arch_guard`）、`dev/` | 活跃（工具面） |
| 5 归档 | `archive/` | `v4/`、`v5x_scripts/{agent_ops,campaigns,campaign_oneoffs}/`、`v5x_configs/{campaigns,pesn}/` | **只读** |

`scripts/` 根目录清空，不得复活；活跃实验配置统一在 `config/experiments/*.yaml`。

### 1.2 单向依赖（依赖只向下，归档只进不出）

```text
pes2ts_v5  ->  pes2ts_data  ->  pes2ts_core(utils/g0/g1/...)
     \             |                  ^
      \            v                  |
       +-------> infra (工具面)       |
                                      |
archive  --只允许-->  infra.runtime    |   （文档化 sink 例外）
archive  --历史冻结调用-->  pes2ts_core   （grandfathered，不再扩展）
```

- `pes2ts_v5/**`、`pes2ts_data/**` 不得 import `pes2ts_core.pesn`、`archive`、`tests.legacy`；
- `pes2ts_core` 的受保护子包与 `cli.py` 不得 import `torch`、`pes2ts_v5`、`pes2ts_data`、`archive`；
- `infra/**` 不得 import 业务代码（`pes2ts_core`/`pes2ts_v5`/`pes2ts_data`/`archive`）；
- `tests/**`（`tests/legacy/` 之外）不得 import `archive` 或 `tests.legacy`；
- `archive/**` 是冻结的依赖**汇点**：只允许 import `infra.runtime`，不得反向依赖新活跃区。

### 1.3 四个合同（active code 的四个接缝）

| 合同 | 落点 | 语义 |
|---|---|---|
| `StandardBatch` | `pes2ts_data/contracts.py` | 数据区对模型区的唯一张量批次合同 |
| registry plugins | `pes2ts_data/registry.py`、`pes2ts_v5/models/registry.py`、`pes2ts_v5/losses/registry.py` | 新增数据源/架构/损失 = 注册一个插件，不改引擎 |
| 单一 trainer | `pes2ts_v5/training/trainer.py`（`V5Trainer`）+ `pes2ts_v5/runner.py` | 全仓唯一训练循环与唯一 CLI 入口 |
| config-as-experiment | `config/experiments/*.yaml` + `pes2ts_v5/configs/schema.py` | 一次实验 = 一份 YAML，不是一份新代码 |

### 1.4 冻结区（read-only）

| 区域 | 原因 | 门禁 |
|---|---|---|
| `archive/**` | 历史战役代码/配置，保留可检索性 | G3 sink 规则 + G4 |
| `pes2ts_core/pesn/**` | V4+V5.1–V5.4 模型与训练记录，已停止演进 | G4 |
| `tests/legacy/**` | 历史测试层，默认 `-m "not legacy"` 跳过，CI 全量层仍执行 | 不参与活跃区 G1–G3/G5 |

## 2. 五道硬门（自动门禁）

实现：[`infra/governance/arch_guard.py`](../../../infra/governance/arch_guard.py)；测试：[`tests/kernel/test_arch_boundaries.py`](../../../tests/kernel/test_arch_boundaries.py)、[`tests/kernel/test_repo_layout.py`](../../../tests/kernel/test_repo_layout.py)。

| 门 | 规则 | 失败条件 | 豁免 |
|---|---|---|---|
| **G1 单一训练循环** | 活跃区仅 `pes2ts_v5/training/**` 可出现 `.backward()`/`optimizer.step()`（AST Call，注释/文档字符串天然忽略） | 其他文件出现训练步调用 | 无（硬门） |
| **G2 无战役版本代码文件** | 活跃区 `.py` 文件名 stem 匹配 `^v(?:5[4-9]\d*\|[6-9]\d*)_` | 出现 `v54_*.py`、`v541_*.py`、`v563_*.py`、`v6_*.py`、`v7_*.py` 等 | 无（硬门）；`v5_model.py` 按规则不匹配 |
| **G3 单向 import** | §1.2 的 import 矩阵（AST `Import`/`ImportFrom`，字符串与路径断言不算 import） | 任意跨区反向 import | 无（硬门） |
| **G4 冻结区只读** | `git diff --name-only HEAD` 不得触碰 `archive/**`、`pes2ts_core/pesn/**` | 严格模式下出现冻结区改动 | 当前 commit message 含 `[unlock-legacy]`（所有者批准） |
| **G5 活跃区 lint** | `python -m ruff check pes2ts_v5 pes2ts_data infra` | 出现 baseline 未登记的 finding；或 baseline 条目消失 | 仅限 [`arch_guard_baseline.json`](../../../infra/governance/arch_guard_baseline.json) 中逐条登记、带理由的容忍项 |

**模式**：G4 默认 advisory（重组期间工作树常有脏改动），CI 以 `python infra/governance/arch_guard.py --strict-frozen --json` 在干净 checkout 上执行；其余四门默认强制。日常校验命令：

```bash
python infra/governance/arch_guard.py --json        # 五道门 + baseline 报告
python infra/governance/arch_guard.py --no-ruff     # 只跑 AST/结构门（快速）
pytest -q tests/kernel                              # CI 门禁层（无 torch）
```

**G5 baseline**（2026-11-24 快照）：**5 条登记、共 17 个 finding，全部是 G3 遗留 `infra/` 耦合** —— `render_gv_map` 读 G–V registry（1 次 import）；`infra/runtime` 三个旧战役 benchmark/drill 脚本 import 历史 campaign 代码与 `pes2ts_core`（`concurrency_drill` 2 次、`infra_bench` 8 次、`thread_env_ab` 6 次）。**G5（ruff）当前为零容忍**：活跃区 ruff 债务已于 2026-11-24 由所有者清零，新 finding 一律失败。**baseline 是债务台账，不是政策**；条目消失时 guard 会报 stale 并要求同步清理。

## 3. 迁移记录（2026-11-23，commit `ccd31f2`）

| 原位置 | 新位置 | 备注 |
|---|---|---|
| `scripts/datastore/*` | `pes2ts_data/builders/` | Zone 2 数据构建 |
| `scripts/v5/run_screening.py` | `pes2ts_v5/screening.py` | Zone 3 引擎入口收敛 |
| `config/v5` | `config/experiments/` | 活跃实验 YAML |
| `scripts/infra/*` | `infra/runtime/` | Zone 4 运行时工具 |
| `scripts/{check_docs_links,render_gv_map,docs_consistency}.py` | `infra/governance/` | 治理门禁 |
| `scripts/dev` | `infra/dev/` | 开发辅助 |
| `scripts/agent_ops`、`scripts/campaigns`、66 个一次性脚本 | `archive/v5x_scripts/` | Zone 5 归档（agent_ops 66 含 1 个提升为 `infra/governance/docs_consistency.py`；campaigns 31；one-offs 66） |
| `scripts/archive/v4` | `archive/v4/` | V4 冻结 |
| `config/campaigns`、`config/pesn` | `archive/v5x_configs/` | 战役配置冻结 |
| `tests/pesn`、`tests/agent_ops`、`tests/campaigns`、14 个历史根测试 | `tests/legacy/` | 自动打 `legacy` 标记，默认跳过 |
| `scripts/` 根 | —（清空） | 不得复活；`scripts/local` 11 个幽灵脚本已退役并登记 sha256 |

同步门禁改线：CI 与文档/链接/G–V 渲染命令切到 `infra/governance/`，CI 新增 `docs_consistency --strict`、`tests/kernel` 两步。迁移后 `python -m pytest -q tests/kernel` 为新门禁的守门层。2026-11-24 的 Phase-0 F821 冻结区机械修复（`[unlock-legacy]` 豁免，见 §5.2）不改变任何目录归属或运行时语义。

## 4. 后果

**正面**

- 活跃业务代码收敛到约 **1.67 万行**（`pes2ts_v5` + `pes2ts_data`），满足"活跃代码 ≤2 万行"目标；
- 新增一个架构 = **1 个 core 文件 + 1 份 YAML**（registry 插件 + `config/experiments/`），不再新增战役脚本；
- 唯一训练循环、唯一 CLI 入口、唯一数据合同；"当前代码在哪里"有确定答案；
- 五道门 <2s 可跑完（AST + ruff），CI 可在无 torch 环境拦截结构性退化；
- `archive/` 只读且可检索（`.rgignore` 显式排除，检索时不会淹没活跃面）。

**负面 / 代价**

- baseline 中仍有 **5 条历史 G3 债务 / 17 个 tolerated import**（`infra/runtime` 三个旧战役 benchmark/drill 脚本与 `render_gv_map` 的 registry 耦合），需要后续迁移清零；G5 已零容忍；
- `archive/` 中历史脚本仍 import 旧 `pes2ts_core` API：这是冻结调用方的 grandfathered 例外，不扩展、不新增；
- 文档索引（`docs/README.md`、修订台账）需随迁移同步，属后续文档批次。

**回滚**：目录迁移可 `git revert ccd31f2`；门禁与 ADR 为独立提交，可单独 revert。冻结区如需真实修复，走下方豁免规则。

## 5. 豁免、基线与回滚纪律

1. **冻结区豁免（G4）**：仅当提交信息包含 `[unlock-legacy]`、且由仓库所有者书面批准、并在本 ADR §6 追加一条说明时，`--strict-frozen` 才放行。豁免是**一次提交**的范围，不是长期开关。
2. **已登记的冻结区人工豁免（2026-11-24）**：Phase-0 F821 清理对 `pes2ts_core/pesn/models/{dual_egnn.py, v543/move/*}` 补 `from typing import Final` / `# noqa: F821`（PEP 563 前向引用；零运行时改动，`ruff check --select F821 pes2ts_core` 通过）。该提交信息带 `[unlock-legacy]`，不进入 G5 baseline，不改变 `pesn/` 的"只读"语义（仅为跑通 F821 的机械修复）。
3. **baseline 纪律（G5/G3）**：新增容忍项必须在 `arch_guard_baseline.json` 写明 `reason` 与 owner；禁止在 PR 中顺手加基线"修复红灯"。清理债务后运行 `--update-baseline` 收敛条目（guard 对消失条目报 stale）。
4. **硬门不可豁免**：G1/G2/G3 不得通过 baseline 或提交信息绕过；确需架构变更时先改本 ADR 再改代码。
5. **R1–R6 不被本 ADR 修改**；本 ADR 只约束代码位置与依赖方向。

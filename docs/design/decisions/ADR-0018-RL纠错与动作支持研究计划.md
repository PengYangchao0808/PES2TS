## 1. 触发与证据

round0已真实采集258转移/51非零探索，模型残差真实执行369次，但无完成率/费用收益。审查发现CLI训练模式未写入settings，BC日志实际cql且两包权重相同；执行支持门按source标签排除了非零候选。旧报告保留，新纠错报告注明对照资格限制。

## 2. 拟实施决策

1. effective training mode贯穿配置摘要、trainer、run、checkpoint、freeze和包；入口级测试替代仅直接注入settings的验证。
2. 动作支持按相容环境/坐标语义/状态和命令覆盖判断，source仅审计；同一支持规则用于执行和TD后继估值。未支持时保留明确回退。
3. 宿主保存完整控制快照，复用共享宏步进行独立分支诊断；QC仍经ACP。配对监督有独立费用与身份，不补写未执行候选响应。
4. 跨轮转移以episode/decision身份连接，避免相同reaction/index串后继；旧记录按原版本及绑定旁车导入。
5. 先纠错与实测动作优势，再受控2–3轮真实采集；IRC迁移、attention/容量各做独立消融，不同步改变全部变量。
6. 原Demo24仅开发回归。严格TS与新反应/整族评测按既有门，研究proxy不升级正式Q_MOVE/STOP或生产控制。

## 3. 接口与审查边界

快照、episode索引、registry、成对结果和新比较报告的v1/v2名称仅在实施方案中登记为草案；新runtime支持文件拟bundle v3。正式字段/validator/读写白名单及宪法接口登记在实施前同步。新来源、环境、奖励或核心转移语义改变另版本，不就地扩大旧v2能力。

涉及控制状态/支持域/接口及数学条件的实施遵循既有架构审查。当前只规划，不修改R1–R6、受保护目录/guard、默认后端、预算或生产能力。旧bundle仍可读，旧source gate结果不得伪装成新registry验收。

## 4. 成立条件与不能声称什么

有限历史只构成MDP近似，完整快照不保证真正Markov性；邻域支持不保证未知状态物理响应；局部成本优势不证明长期目标TS收益；IRC教师方向不等于执行命令。失败、预算截断、缓存及新增诊断/训练成本按方案分列。

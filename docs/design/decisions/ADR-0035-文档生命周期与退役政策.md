# ADR-0035 — 文档生命周期与退役政策（退役 = 可恢复删除）

> **状态**：Accepted（2026-11-21 仓库所有者授权执行文档清理）
> **层级**：L1 规范 / C 工作流（工程治理面；不涉及 G0–G4 能力、V 战役语义与科学结论）
> **取代关系**：无；**部分修订** [AGENT.md](../../../AGENT.md) §9.4 的"报告永不改内容"适用范围（新增"可退役"例外）；服从 [开发宪法 v2.9](../../PES2TS_开发宪法_v1.md) §12.1（ADR + 版本化 + 同步）、§12.5（Sunset）
> **上游依赖**：[开发宪法 v2.9](../../PES2TS_开发宪法_v1.md) §12、[AGENT.md](../../../AGENT.md) §9、[文档修订台账](../../plans/PES2TS_文档修订台账.md)、[归档方案 v2.0](../../infra/PES2TS_开发文档规范化归档方案_v2_20261121.md) §7、[开发档案树与文档清理方案 v1.0](../../infra/PES2TS_开发档案树与文档清理方案_v1_20261121.md)
> **下游消费者**：仓库所有者、维护者、执行退役的 AI 会话、季度审计、CI 文档门禁
> **当前版本**：v1.0 @ 2026-11-21

## 0. 背景与问题

仓库开发文档达 253 份（4.74 MB），其中约 60% 为过程流水、已被取代的重复件与一次性记录。`AGENT.md` §9.4 规定"报告永不改内容"，`docs/archive/README.md` 规定"快照禁止当墓地"——这些规则保护了证据，但也使**过程性文档只增不减**，导致：索引维护成本高、状态与事实漂移、新人无法判断哪份是当前依据。

**问题不是"报告要不要保真"，而是"过程性文档有没有必要永久占用活跃面"**。本 ADR 给出一个受控的例外：**退役（Retire）**。

## 1. 决策

引入 **退役（Retire）** 动作——从工作树删除文档，但**不是销毁证据**：

> **退役 = 删除工作树文件 + 结论已入档案树 + 清理前 tag/bundle 快照 + 台账登记**
> 任何一条不满足，不得退役。

### 1.1 退役的四个必要条件（缺一不可）

1. **结论已抽取**：该文档的独有结论、负结果、决策依据已写入 `docs/archive_tree/` 对应条目（或已并入现行文档），且条目经所有者抽审。
2. **可恢复**：删除前的 commit 已打 tag（`pre-doc-purge-<date>`）并生成 `git bundle` 备份；恢复命令在台账中登记。删除 = `git rm`（保留 git 历史），**禁止** `git filter-repo` 等历史重写。
3. **无活跃引用**：退役后 `python scripts/check_docs_links.py` 必须 0 error；被引用的链接须先改指档案树条目或现行文档。
4. **台账登记**：在修订台账追加"退役"动作（日期/批次/路径/档案条目/恢复 tag/门禁结果）。

### 1.2 永不退役清单（任何情况下不删除）

- 规范根：`docs/PES2TS_开发宪法_v1.md`、`AGENT.md`、`docs/plans/PES2TS_阶段定义_G0-G3.md`、`docs/plans/PES2TS_完整开发流方案_整合版_v1.md`
- 治理与索引：`docs/README.md`、`docs/plans/PES2TS_文档修订台账.md`、`docs/infra/doc_audit/**`、`docs/infra/doc_cleanup/**`
- 决策记录：`docs/design/decisions/ADR-0001…ADR-0035` **全部 34+1 份**（编号=决策指纹，只读记录）
- 现行合同：5 份 `Active-Normative` 合同及其总表/字段映射（以 `CORE_SET` 为准）
- 证据锚点：`artifacts/**/model_card.md`、`docs/agent_runs/state/gates/**`、`docs/archive/**/manifest|verification|README`、`docs/archive_tree/**`
- 根目录 `README.md`、`CONTRIBUTING.md`、`LICENSE`、`requirements*.txt`

### 1.3 与既有规则的关系

| 既有规则 | 本 ADR 的处理 |
|---|---|
| `AGENT.md` §9.4「报告永不改内容」 | **补充**：报告正文仍不可改写；但允许"整篇退役"（内容不修改，只从工作树移除）。退役不是"修改内容"。 |
| `docs/archive/README.md`「快照禁止当墓地」 | **不变**：本 ADR 不把过时文档搬入 `docs/archive/`；退役是删除+档案树，与快照区无关。 |
| 宪法 §12.1/§12.5（ADR、日落） | 本 ADR 即修订程序产物；退役即日落的一种受控形式。 |
| `docs/superseded/README.md`（已取代区） | **不变**：`superseded/` 仍是"已取代单一文档"的归档位；本 ADR 处理的是"没有保留价值的过程件"。 |

## 2. 执行程序（5 步）

1. **治理**：本 ADR 生效 + `AGENT.md` §9.4 例外条款 + 台账新增"退役"动作类型。
2. **快照**：`git tag pre-doc-purge-<date>`、`git bundle create <file> --all`、`tar -czf docs-<date>.tar.gz docs`；**恢复演练**通过（`git show <tag>:<path>` 能取回原文）。
3. **抽取**：逐条把结论写入 `docs/archive_tree/`（先建树后删档）。
4. **删除**：按批次 D1/D2/D3 执行 `git rm`；每批独立 commit；门禁红即 `git reset --hard <tag>` 回滚。
5. **登记**：台账追加退役记录；`docs/README.md` 与档案树索引同步；退役文件从 `docs_consistency_config.json`/`g_v_map.yaml` 移除（仅当被判死路径时，同 PR 改配置并重渲染 G–V 文档）。

## 3. 后果

**正面**：活跃面从 180 份收敛到约 70–100 份；新人只需读 1 份索引 + 17 条档案 + 44 个核心单元；过程性文档不再占用索引与门禁；历史可由 tag/bundle 完整恢复。

**负面/代价**：① 恢复需要 git 操作（非零成本）；② 档案树条目的质量成为唯一"历史可读性"来源，需所有者抽审；③ 若误删有独有结论的文档且未抽取，信息只存在于 git 历史（可恢复但不易发现）——因此"四个必要条件"不可省略。

**回滚**：`git reset --hard pre-doc-purge-<date>`（未 push）或 `git revert <commit>`（已 push）；最坏情况从 bundle 重建仓库。

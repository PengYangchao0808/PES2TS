# G1 v2 L0 到 G2 的路径与扫描策略设计

> 已并入图谱选择器 P0–P3 (见 docs/design/PES_GENERATION_图论扫描策略选择器设计_v1.md 与 .omo/plans/pes-generation-graph-scan-strategy.md)

> 后续架构决定：G1 应在计算前生成并冻结逐反应扫描计划，G2 只按计划执行。以 [G1 v2：ORCA 扫描模式识别与逐反应计划](G1_v2_ORCA扫描模式识别与计划.md) 的责任划分、ORCA 模式和实施步骤为准。本文保留 L0 统计与初期路径路由分析。

> 状态：设计稿，2026-09-27。本文规定路径生成的路由、失败状态与验证口径；不宣称任何尚未运行的 G2 计算已经成功。G2 的目标是从 R/P 端点生成有能量和几何的候选路径，供后续 TS 初猜排序。这里的“一维 PES 曲线”仅指沿一条候选路径的能量剖面，不是完整多维势能面，也不是已验证的过渡态。

## 1. 先回答分类规模

数据源：`data/interim/g1_v2_class_summary.parquet`、`data/interim/g1_v2_summary.parquet`、`data/interim/inventory.parquet`；分类版本 `g1p2_taxonomy_v2`，数据版本 `zenodo-18551029-rev1`。以下是完整 v2 分类结果的静态快照，G2 最终分母须以完成后的 `g1_v2_gate.json` 和 `g2_scan_ready.json` 为准。

| 人群 | 反应数 | 定向 L0 (`l0_edit_family`) | 方向无关 L0u (`l0u_undirected_family`) |
| --- | ---: | ---: | ---: |
| 全部反应 | 199,217 | — | — |
| 可分类反应 | 191,148 | **638** | **412** |
| 审计为 `clean`，预计进入 `scan_ready` | 183,460 | **615** | **400** |
| 有问题、待复核 | 7,688 | 不用于直接 G2 扫描 | 不用于直接 G2 扫描 |
| 排除 | 8,069 | 不分类 | 不分类 |

L0 的签名是 `F{形成键数}B{断裂键数}O{键级改变数}H{氢伴侣改变数}`。它只说明事件**数量**，不描述具体原子、空间几何、反应机理或适合的计算坐标。L0u 对 F/B 交换取规范形式，适合统计方向互换的化学家族，但运行方向仍必须单独记录。反应规则标签共有 22 种**组合**，与 638 个 L0 签名不是同一套分类。

例如在 `clean` 集合中，`F2B2O2H1` 有 10,406 条，却同时含 `h_transfer|substitution`（8,112）、`h_transfer|ring_opening`（1,159）和 `h_transfer|ring_closure|elimination`（1,135）。因此不能建立“一个 L0 签名对应一个扫描模板”的映射。

分布也极不均衡：`clean` 集合的前 20 个 L0 签名覆盖 99,328/183,460 条（54.1%），305 个 L0 签名各不超过 10 条，其中 121 个只有 1 条。按逐条编辑数 `F+B+O` 看，173,609/183,460 条至少有 4 条编辑；这**不等于**需要至少四维扫描，因为多个编辑可以耦合为同一个物理模式。142,446/183,460 条在 R 或 P 一侧有多个组分。若直接把 638 类逐类指定一维扫描，主要人群将被错误简化。

## 2. “能扫描”必须拆成四个可检验命题

1. **可构造输入**：R/P 原子数、元素、映射顺序、电荷和自旋可一致化；端点几何和多组分摆放无严重碰撞。
2. **可运行方法**：选定的 GFN2-xTB 计算能收敛，并可为所选路径帧给出完整能量。这只是计算可执行性。
3. **可得到目标路径**：路径连续，真正到达目标 P，预期变化键按目标方向改变，且没有主导性的非目标反应。
4. **可得到有用 TS 初猜**：有效内部帧与参考 TS 足够接近，并在后续 OptTS、频率、双向 IRC 验证中到达目标 R/P。这是 G3/V3/V4 的实验结果，不能由 L0 标签或 G2 路径峰值预先保证。

设计结论：**615 个预计可导出的 L0 类均进入端点驱动路径的候选路由；逐条输入检查后，只有合格记录才实际提交计算。不能承诺每一类都能得到有效曲线，更不能承诺每类都适合一维受限扫描。** 每个 L0 的可扫描覆盖率和成功率要通过试运行实测。

## 3. 路由输入：L0 只用于分层，具体策略按逐条反应确定

G2 只读取 `g1_v2/export/<shard>/<rid>.json` 与 `g2_scan_ready.json`。扫描路由至少使用以下白名单信息：

| 特征 | 用途 |
| --- | --- |
| `maps`、`r/p_atomic_numbers`、`r/p_coordinates`、`atom_rows` | 统一原子次序，装配 R/P 端点，回写每帧原子映射 |
| `edits`、`hydrogen_partner_changes`、`aromatic_regions` | 推导候选路径驱动模式与目标键变化 |
| `reaction_center`、`classification` | 对齐和抽样分层；L0/L0u 不直接决定算法 |
| `components`、总电荷、自旋 | 判断多组分摆放、电荷自旋一致性和 xTB 输入设置 |
| `status_summary`、`mapping_provenance` | 审计和溯源，不作为 TS/IRC 真值特征 |

G2 不读取 `ground_truth`、P1 的 TS/IRC 坐标、`ts_irc_index`、真值能量或从 IRC 拟合的扫描距离。`mapping_provenance="truth_assisted_p1"` 必须保留，以便后续报告说明映射来源。端点装配只能依据 R/P 的清单几何、映射和图编辑。

## 4. 路由决策表

`PATH` 指 GFN2-xTB 双端路径搜索；它是默认主方法。下表中的“一维/二维受限扫描”是**可选补救方法**，是否可用取决于实际几何与驱动模式，不能由 L0 计数单独判定。IDPP/NEB 是另一种双端路径补救，不等同于单坐标扫描。

| 逐条反应条件 | 首选准备与方法 | 允许的补救 | 不应自动做的事 |
| --- | --- | --- | --- |
| 单组分，端点可按共同骨架对齐 | 端点对齐 → 正向 `PATH` | 反向 `PATH`；经验证的 IDPP 初始化 + NEB | 仅因 `F+B+O=1` 就认定只有一个反应坐标 |
| 多组分或组分数改变 | 按变化键约束生成**多个确定性**相对摆放，逐个去碰撞 → `PATH` | 调整端点装配；反向；IDPP/NEB | 把相距无穷远的碎片当作数值稳定的单一端点；直接插值重叠片段 |
| 简单成键/断键，只有一个经验证的独立驱动模式 | 仍先试 `PATH`；必要时以目标键距离做受限扫描 | 反向扫描；IDPP/NEB | 把路径能量峰称为正确 TS |
| 明确的 H 转移，含供体/受体 | `PATH`，核对 H 的两个伙伴及几何 | 若 donor/acceptor 唯一且几何合理，用 `d(D,H)-d(A,H)` 作为单驱动坐标；否则双端方法 | 将 H₂ 形成、游离 H 捕获或释放强行标为普通 H 转移 |
| 同步成断键、环化/开环、取代、重排 | `PATH` 并核对所有目标编辑；必要时多装配 | IDPP/NEB；若可证明只有两个独立驱动模式，可试有预算的二维受限扫描 | 逐键串行扫描并默认所得路径代表同一协同步骤 |
| 芳香重排或键级变化 | `PATH`，把同一 `aromatic_region` 作为耦合事件核对 | IDPP/NEB；经过预实验才能定义区域级集体坐标 | 把环上每个交替键都独立扫描，或只用一个键长代表键级变化 |
| 端点不合格、xTB 不支持/不收敛、可行装配耗尽 | 记录拒绝或失败 | 人工复核或进入方法开发队列 | 伪造完整能量曲线，或把 `needs_review` 绕过关卡放入 G2 |

这里的“独立驱动模式”必须从**编辑涉及的原子、共享原子/环区域、H 伙伴关系及端点几何**构造耦合图，再经小样本路径结果检验。`F+B+O` 是离散编辑计数，不是扫描维数。一个 L0 类内可以有不同的耦合图和不同的路由。

## 5. 可执行的逐条决策顺序

```text
assert reaction_id in frozen_g2_scan_ready
read exactly one whitelisted export; validate schema and atom/map order
validate R/P atom inventory, charges, spin, finite coordinates, xTB support
derive coupled edit groups (shared atoms, H partner, aromatic region, ring event)
generate deterministic endpoint assemblies from endpoint data only
reject assemblies with irreparable clashes or inconsistent target geometry
for each assembly within frozen budget:
    run forward GFN2-xTB PATH
    if invalid: run reverse PATH and reorient accepted frames R→P
    if still invalid and applicable: try IDPP-initialized NEB
    if still invalid and a justified <=2-mode coordinate exists:
        try bounded constrained scan; verify all target edits
choose the first valid candidate under a recorded deterministic ranking
if none valid: emit failure with every attempt, cost, and reason
```

先运行完整的双端路径基线，再评估受限扫描是否能提高有效率。xTB 官方路径文档说明其推拉偏置的参数依赖体系，复杂反应可能需要替代方法；文档中的参数只能作为**试验起点**，必须锁定版本并在验证集调参，不能逐条借助 TS 真值调参。[xTB Reaction Path Methods](https://xtb-docs.readthedocs.io/en/latest/path.html)。ASE 的 IDPP 用距离目标改进中间图像初猜，NEB 仍需能量/力计算及后续路径检验。[ASE NEB 文档](https://docs.ase-lib.org/ase/neb.html)、[ASE IDPP 教程](https://ase.gitlab.io/ase/examples_generated/03-tutorials/neb_idpp.html)。

## 6. 成功判据与数据合同

`path_manifest.json` 应逐条记录 `reaction_id`、输入文件 SHA256、分类版本、L0/L0u/L1、路线及尝试序列、端点装配编号/种子、xTB/ASE 版本与参数、总电荷/自旋、计算预算、每次运行时间、终止码、拒绝原因、最终路径帧文件和能量文件。每帧保留相同的 map 升序原子排列、反应坐标弧长、全部目标变化键距离、能量、非中心碰撞与非目标拓扑变化标志。

建议分开的状态：`input_rejected`、`assembly_failed`、`method_failed`、`path_incomplete`、`wrong_endpoint`、`off_target_topology`、`energy_incomplete`、`valid_path`。阈值（最少内部帧、端点距离/拓扑容差、非中心碰撞距离、路径连续性、最长运行时）应先在训练/验证集试点确定并冻结，再评估测试集；不在此凭空给出成功率。

`valid_path` 至少要求：端点映射/元素一致；至少有预设数量的内部帧；每帧有限能量；到达目标端点；目标键编辑在路径方向上实现；非反应中心无严重碰撞；没有取代目标反应的主要拓扑漂移。`valid_path` **不等于**一阶鞍点，也不等于 IRC 正确。G3 才用 DFT TS/IRC 衡量 oracle gap；V4 才用 OptTS、频率和双向 IRC 判定正确 TS。

## 7. 试验与报告：回答“每类是否都能扫”

1. **覆盖性试点**：先从高频 L0、低频 L0、纯/混合 H 变化、芳香区域、环化/开环、多组分、不同中心规模中抽样；不能只测最容易的单分子反应。抽样必须保持既有 train/validation/test 划分，开发时不看测试真值。
2. **方法消融**：固定相同装配与核时预算，依次比较仅正向 `PATH`、加反向、加多装配、加 IDPP/NEB、加适用子集的受限扫描。分别报告新增有效路径及额外成本。
3. **逐级汇总**：按 L0、L0u、规则标签、H 类型、芳香区域、多组分、编辑耦合模式报告 `输入合格率`、`方法完成率`、`目标路径有效率`、`有用初猜率`。每项分母都保留被拒绝/失败反应，不用成功样本重新定义覆盖率。
4. **稀有类判读**：对样本数很小的 L0 只报告逐条状态和置信区间，不声称“此类必然可扫/不可扫”。高频类优先优化，稀有类仍保留独立失败和覆盖清单。
5. **转段要求**：任何路线的有效性由冻结的几何/拓扑规则判定；“哪个 L0 能用哪个方法”由实测成功率与预算决定，写入版本化策略表。不能因为某类曾有一条成功路径就宣布全类可行。

推荐的逐类报告字段：`n_total`, `n_scan_ready`, `n_input_valid`, `n_attempted`, `n_path_valid`, `n_seed_useful`, `n_strict_ts`, `method_attempts`, `failure_histogram`, `median_core_hours`, `ci_95`。其中 `n_strict_ts` 只有完成 V4 后才可填写。

## 8. 与现有实现的边界

当前仓库实现了 G1 v2 的编辑、分类、验证和导出；以上 G2 路由、PATH/NEB/受限扫描及逐类成功率**是待实现和待测的设计**。在 G1 `v2-gate` 导出完成、关卡清单写入并核验以前，不启动全量 G2。G2 首批应先做方案现有的 100–200 条合同试验，再约 1,000 条分层路径和 oracle gap 验证，确认路径本身值得训练后才扩大规模。

## 0. 结论速览

**一句话**：PES2TS 的文档问题不是"文件太多"，而是**状态没有成为契约**——216 份 `docs/**/*.md` 里 `docs/archive/` 与 `docs/superseded/` 的分区规则是清楚的，但活跃面存在 42 份无状态头文档、40 余种状态取值、40 份索引双缺文档、21 个多版本家族中 6 组状态自相矛盾；同时 **`docs_consistency` 从未接入 CI**，门禁只存在于"训练前手工执行"的口头约束里。因此本方案的重心不是"搬家"，而是**给每份文档一个可机检的身份与状态、一条收敛的状态机、一条可回滚的归档路径**。

**体检数字（2026-11-21 全量扫描，可复跑）**：

| 指标 | 实测 | 判读 |
|---|---:|---|
| 全量文档记录（含 html/txt/LICENSE/模型卡） | **253** | 4,972,194 B / 55,452 行；249 已跟踪 + 4 本轮新增未跟踪 |
| `docs/**/*.md` | 216 | 其中 `archive/` 36、`agent_runs/` 14、`superseded/` 5，活跃面 180 |
| 根目录开发文档 | 15 | 13 份 md（含 7 份战役 memo）+ 3 份 requirements + LICENSE |
| 顶部有状态块 | **177 / 253**（全量口径）；doc 口径 167 / 216 | 缺 76；其中活跃面缺 42 |
| 状态取值 | 原始值 **137 种**；归一化后 17 个归并桶 | 官方图例只定义 5 种（`Canonical/Active-Proposed/Executed-Frozen/Superseded/Evidence-Historical`，`docs/README.md:118`） |
| 状态头书写格式变体 | 5 | `> 状态：` 160 份为主，另有 4 种变体 |
| 被 `docs/README.md` 索引 | 133 / 180 活跃 | 索引滞后 |
| 被修订台账索引 | 100 / 180 活跃 | 台账滞后 |

| 版本家族 | 21 组 / 53 成员 | 其中 6 组需所有者裁决 |
| 文档门禁是否进 CI | **否** | `docs_consistency` 只在训练前手工执行；CI 仅 3 类文档相关检查 |

**五条不变式（本方案的硬约束，任何归档动作不得违反）**：

1. **证据永不删除**：`docs/reports/**`、`docs/archive/**`、`docs/agent_runs/state/gates/**`、`artifacts/**/model_card.md` 只增不改不删。
2. **规范唯一**：`docs/PES2TS_开发宪法_v1.md` 是 SSOT；本方案及一切 plan/design **只引用不复制**宪法条款。
3. **门禁钉死路径不动**：`docs_consistency_config.json` 的 `historical`(17) / `required_files`(27) / `root_scope`(9)、`g_v_map.yaml` 引用的文档路径——**移动即断门禁**，只能"同 PR 改配置"或"不移动"。
4. **报告只读**：`docs/reports/**` 永不改内容，只能加顶部指针（`AGENT.md` §9.4）。
5. **归档 ≠ 删除**：归档只有三种落点——原位加横幅降级、`docs/superseded/`、`docs/archive/YYYYMMDD_pre_<主题>/`。**不存在第四个落点，也不存在"直接删"**。

**推荐路线（决策 D-01，见 §4.1）**：采用 **路线 A「状态优先 / 路径稳定」**——先把状态、元数据、清单、门禁做成契约，再做**小批量、可回滚**的物理迁移；**不采用**一次性目录编号化重构（路线 B）。理由：本仓库的价值在可追溯性，而 60+ 处门禁钉死路径与 172 条既有 warning 链接决定了大搬家的收益远低于断链风险。路线 B 作为可选远期项挂起，触发条件见 §14-Q3。

1. **本方案不新增规范**：不修改宪法、不修改红线 R1–R6、不修改 G0–G4 阶段定义；只规范"文档作为工程资产"的管理方式。

3. **本方案不改写历史**：已发生的路径、已发布的报告、已提交的台账条目一律不改写；迁移只新增映射记录（见 §9.3）。

**结论性缺口（C-09）**：现行门禁里**没有一项**检查"状态头是否存在 / 状态是否合法 / 是否单权威 / 是否被索引"；宪法 §12.4（`docs/PES2TS_开发宪法_v1.md:426-428`）要求的 CI 校验并未实现。**"门禁全绿"≠"文档合规"**——本轮 12 项冲突全部在 CLEAN 基线下并存。这正是 §10.3 要补的 **G5**。

**172 条 warning 的性质（C-11）**：不是"可忽略"，而是**冻结的容忍债务**（报告只读导致结构上不可清零）；新方案的要求是"**不得静默增长**"：任何新增 warning 须在 PR 说明。

## 4. 规范化目标模型

### 4.1 总原则（四条）

1. **一文档一职责**：一份文档只承担一种职责（规范/计划/设计/合同/证据/运营记录/索引）；职责变更 = 新文档 + 旧文档降级，**不原地改性质**。
2. **状态即契约**：文档的状态不是注释，是**消费方可以依赖的承诺**（能否作为执行依据、能否被引用为当前口径）。状态必须可被机器解析、可被门禁校验、必须与所在目录相容。
3. **清单可机检**：全量清单、索引、状态三者由**生成物 + `--check`** 保证一致，不靠人工誊抄（复用 `render_gv_map.py` 先例）。
4. **证据永不删除**：归档只有降级、迁入 `superseded/`、迁入 `archive/` 三种落点；删除仅限可再生缓存。

### 4.2 五层分类法（L0–L4）

| 层 | 名称 | 定义 | 允许目录 | 是否可被当作执行依据 |
|---|---|---|---|---|
| **L0** | 治理层 | 规范根本身与执行投影、索引、流水 | `docs/` 根（宪法）、`AGENT.md`、`docs/plans/`（阶段定义/完整开发流）、`docs/README.md`、台账、`docs/infra/` | 是（冲突时以宪法为准） |
| **L1** | 规范层 | 当前有效的任务合同、几何/接口合同、阶段定义 | `docs/contracts/`、`docs/design/decisions/` | 是（须标 `Active-Normative`/`Accepted`） |
| **L2** | 执行层 | 活跃计划、冻结预注册方案、WP 清单、设计文档 | `docs/plans/`、`docs/design/`、`docs/demo/`、`docs/infra/` | 是（仅在其声明范围内） |
| **L3** | 证据层 | 报告、审计、快照、模型卡、HTML 可视化 | `docs/reports/`、`docs/archive/`、`artifacts/**/model_card.md` | **否**（只读；可引为证据，不可当规范） |
| **L4** | 运营层 | 战役编排、交接、门禁 JSON、会话 memo | `docs/agent_runs/` | 否（运营记录，审计豁免） |

**判定顺序**：先问"它是否是规范/执行依据"（L0–L2），再问"它是否是某次动作的证据"（L3），最后才是"它是否是过程记录"（L4）。**不允许一份文档同时是 L2 与 L3**——如果计划里混入大量执行结果，应拆出报告。

### 4.3 文档身份

- **ID = 仓库相对路径**（posix 风格）。**不引入**不透明编号（如 `DOC-0001`），因为路径本身已被 60+ 处门禁引用、git 历史与外部链接依赖；引入编号会产生第二套身份，且不解决任何问题。
- 迁移后**旧路径保留映射记录**（§9.3），保证可追溯；不要求旧路径 301 重定向（仓库内链接同批修）。
- `git mv` 是唯一允许的迁移手段（保留 `--follow` 历史）。

## 5. 生命周期状态机（核心）

### 5.1 九个规范状态（封闭词表）

| 状态（canonical token） | 中文显示 | 定义 | 允许所在目录 | 门禁判定 |
|---|---|---|---|---|
| `Canonical` | 权威 | SSOT 与执行投影、阶段定义、索引、台账 | `docs/` 根、根目录、`docs/plans/` 指定 4 份 | 全库唯一性由 `required_files` + 人工复核 |
| `Active-Normative` | 现行规范 | 当前有效的任务/几何/接口合同 | `docs/contracts/` | 每类合同同一时刻**只能一份** `Active-Normative` |
| `Accepted` | 已接受 | 已裁决生效的 ADR 与设计决策 | `docs/design/decisions/` | ADR 编号唯一、链式取代关系可解析 |
| `Active-Proposed` | 活跃提案/执行中 | 已被批准、尚未执行完或仍在迭代的方案/计划 | `docs/plans/`、`docs/design/`、`docs/infra/` | 必须有"当前版本 + 日期" |
| `Frozen-Preregistered` | 冻结预注册 | 阈值/预算/配方已签认、执行前不可改 | `docs/plans/` | 与 `config/**` 预注册一致；改即需新版本 |
| `Executed-Frozen` | 已执行冻结 | 已执行完毕、结果冻结、不可改写 | `docs/plans/` | 必须能链到对应 `docs/reports/` 报告 |
| `Superseded` | 已取代 | 自身声明被更新的文档取代；**仍在原目录或 `superseded/`** | `docs/plans/`、`docs/design/`、`docs/contracts/`、`docs/superseded/` | 必须写"被 X 取代"；`historical` 名单内者**不得移动** |
| `Historical` | 历史 | 不再作为依据、无直接取代者（早期提案/历史记录） | 原目录（不移动） | 必须带历史横幅 |
| `Evidence-ReadOnly` | 只读证据 | 报告/审计/快照/模型卡/HTML 证据 | `docs/reports/`、`docs/archive/`、`artifacts/` | **内容不可改**，只能加指针 |
| `Snapshot` | 版本快照 | 某修订时点的原始拷贝（`YYYYMMDD_pre_*`） | `docs/archive/` | 只读、不移动、链接检查排除 |

## 7. 归档与保留策略

### 7.1 归档三问判定法（唯一判定入口）

对任一份非证据类文档，依次回答：

1. **它还是当前执行依据吗？** 是 → `keep`（原位保留，状态为 `Active-Proposed` 及以下活跃态）。
2. **它被明确取代了吗？** 有取代者且自身应声明 → `Superseded`：
   - 2a. 它在 `docs_consistency_config.json.historical` 名单里，或被 ≥1 处活跃文档引用？ → **原位 + 横幅**（`move` 禁止）。
   - 2b. 0 引用 + 不在钉死名单 + 自身已有 `Superseded` 声明 → **迁入 `docs/superseded/`**。
3. **它是某次动作的证据吗？** 是 → `Evidence-ReadOnly`，**永不移动**（`docs/reports/`、`docs/archive/`、`artifacts/`）。
4. 都不满足 → `Historical`（原位 + 历史横幅）；若从未生效 → `Deprecated`。

**禁止的判定方式**："看起来旧""文件名有 2026-10""作者已经不在""最近没人提"——**不构成归档依据**（沿用 v1 方案 §2 判定原则）。

### 7.2 处置动作矩阵

| 动作 | 含义 | 是否移动 | 必须同步 | 门禁风险 |
|---|---|---|---|---|
| `keep` | 原位保留 | 否 | 无（若状态变更则登记） | 无 |
| `banner` | 原位加状态/取代横幅 | 否 | 台账 | 低（historical 须保 `ADR-0030` 横幅） |
| `move` | 迁入 `superseded/`（审计证据迁入 `docs/infra/doc_audit/`） | 是（`git mv`） | 链接修正 + superseded README 索引 + 台账 + 映射记录 | **中**（断链/断门禁） |
| `merge` | 并入另一文档（仅限证据性重复，且须所有者批准） | 否 | 台账 + 被并文档加横幅 | 高（内容合并不可逆） |
| `retain-readonly` | 只读保留（证据） | 否 | 战役索引 | 无 |
| `out-of-scope` | 非开发文档 | — | — | 无 |

**默认动作是 `keep` 与 `banner`**；`move` 只在 B1 批次、且满足 §7.1-2b 时执行；`merge` 默认禁止（本方案不推荐任何合并动作，只标注候选）。

### 7.3 保留期与删除红线

| 类别 | 保留期 | 依据 |
|---|---|---|
| 宪法/AGENT/阶段定义/台账/索引 | 永久 | 治理根 |
| 合同（含已取代版本） | 永久 | 追溯 |
| 方案/计划（含已取代/历史） | 永久 | 项目审计 |
| 报告/审计/快照/模型卡/门禁 JSON | 永久（只读） | 证据链 |
| 运营记录 `agent_runs/` | ≥12 个月，之后可迁 `archive/YYYYMMDD_agent_runs/`（需所有者批准） | 协作追溯 |
| 根目录战役 memo（7 份） | 永久 | 已由 `root_scope` 管理，移动需同 PR 改配置 |
| 会话临时文件/缓存 | 随时可删 | 可再生 |

**删除红线（不可突破）**：禁止删除 SSOT、合同、报告、快照、`state/gates/*.json`、`manifest/verification/source_hashes`；禁止用 `git rm` 处理"过时但未被取代"的文档（必须先降级归档）；禁止删除 `docs/archive/**` 内容。

### 7.4 三种归档落点的关系（防混用）

| | `docs/archive/` | `docs/superseded/` | `docs/reports/` |
|---|---|---|---|
| 存什么 | **修订时点的整体快照** | **自身已被取代的单一文档** | **动作产出的证据/结论** |
| 粒度 | 批次（多文件 + manifest/哈希） | 单文件 | 单文件 |
| 是否只读 | 是（永不改） | 是（仅修链接/加横幅） | 是（仅加指针） |
| 能否搬入"过时文档" | **禁止**（R6） | 允许（唯一入口） | **禁止**（R4） |
| 命名 | `YYYYMMDD_pre_<主题>/` | 保留原文件名 | 原文件名（含日期） |
| 索引 | `archive/README.md` | `superseded/README.md` 索引表 | `docs/README.md` reports 节 |
| 判定入口 | 修订前快照生成 SOP | §7.1-2b | 产出即证据 |

### 7.5 大文件、二进制、HTML 与外部路径

1. **入库阈值**：单文件 > 5 MB 不直接入库，走 `outputs/`（已 ignore）或 Release 附件；入库面最大文件现状 2.77 MB（`Demo24_双人化学复核.xlsx`），无 LFS 需求。

4. **外部/绝对路径**：文档正文中出现的 `E:/...`、`/mnt/e/...` 只会产生 warning（既知 172 条），新文档禁止新增；历史报告中的保留（只读，不改写）。

5. 本地跑 4 道文档门禁（改动代码/测试时加跑全仓 pytest）；PR 描述附门禁输出。

### 11.3 SOP-2 状态转换

1. 确认事件已发生（签认记录/执行完成/新版发布）——**无证据不转态**。
2. 改元数据头状态 + 当前版本。
3. 写转换原因（台账一条，含证据链接）。
4. 若为 `Superseded`：同时写"被 X 取代"并检查是否需 `historical` 配置。
5. 重生成清单（G5 落地后）。

### 11.4 SOP-3 归档

1. 跑 §7.1 三问 → 得到动作。
2. 动作 = `banner`：加横幅（`> 状态：Historical/Superseded` + 原因 + 日期）→ 台账。
3. 动作 = `move`：执行 §9.2 全流程。
4. 动作 = 快照：按 `archive/README.md` 规则 4 生成 `YYYYMMDD_pre_<主题>/` + manifest + 哈希 → 更新 `archive/README.md`。
5. **任何情况下不删原件**。

### 11.5 SOP-4 删除（仅缓存）

仅允许：`__pycache__/`、`.pytest_cache/`、`.ruff_cache/`、`.mypy_cache/`、本地临时目录（`.slim` 内）。删除前后 `git status` 必须不产生入库改动；一旦发现"删了却有 git 变更"，说明误删入库文件 → `git checkout -- <path>` 立即恢复。

### 11.6 SOP-5 批次迁移

按 §9 执行，记录 `MIGRATION_LOG.md`；一批一 PR；门禁红即回滚，不带病合并。

## 12. 风险、回滚与反模式

| # | 风险 | 触发 | 后果 | 缓解 |
|---|---|---|---|---|
| 1 | 门禁红 | 移动 `historical`/`required_files`/`g_v_map` 引用路径 | CI 失败 / 阻塞 | §2.3 清单先排除；迁移前 `git grep` |
| 2 | 断链 | 移动未修引用 | `check_docs_links` error | 每批必跑；`superseded` 迁入单独验 |
| 3 | 误删证据 | 把 `reports/**`、`state/gates/*.json` 当垃圾 | 治理违规（不可恢复） | 不变式 1 + SOP-4 |
| 4 | 状态通胀 | 随手新增状态词 | 词表再度发散 | 封闭词表 + G5 校验 |
| 5 | 双索引漂移 | 只改 README 不改台账（或反之） | 读者读到旧口径 | G5 索引覆盖校验 + 同步矩阵 |
| 6 | 大文件入库 | `git add -f` 或白名单误开 | 仓库永久膨胀 | 5 MB 阈值 + P0 体检命令 |
| 7 | 目录重构失控 | 一次性大搬家 | 断链风暴 + 历史割裂 | 路线 A（路径稳定）；大搬家挂起 |
| 8 | 方案空转 | 只有方案没有门禁 | 3 个月后回到现状 | M4 接入 CI + 季度审计（§13） |

**反模式（明令禁止）**：以"整理"为名批量删除旧文档；把 `archive/` 当过时文档墓地；用 `merge` 抹掉失败证据；给报告"更新结论"；在 `reports/` 里放"当前方案"；用绝对路径链接替代相对链接。

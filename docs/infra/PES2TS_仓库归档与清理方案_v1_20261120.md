## 0. 结论速览

**体检结论一句话**：这个仓库的"大块头"已经被 `.gitignore` 挡住了（`data/` 12.15 GB、`outputs/` 1.3 GB+ 都不入库），**真正要处理的是"入库面里的历史沉淀"**——根目录 7 个战役 memo、`docs/plans/` 的多版本残留、`scripts/` 根的一次性战役脚本，以及本地缓存目录。

**三档处理**（详见 §3）：

| 档 | 含义 | 动作 | 影响入库面 |
|---|---|---|---|
| **A 清理** | 可再生 / 无引用 / 纯本地缓存 | 删除或确认已被 ignore | 只清本地，不进 git 历史 |
| **B 归档** | 有证据价值但已不在活跃面 | **移动**（不删），并补索引/状态头 | 路径变化，必须修链接与门禁 |
| **C 保留** | 规范/证据/被引用的活跃面 | 不动 | 无 |

**四条硬约束（先记住，否则一定翻车）**：

1. **CI 有 4 道门**（`render_gv_map --check`、`check_docs_links.py`、registry tests、两档 pytest）——任何移动文档/脚本的动作都必须让这 4 道门继续绿。
2. **`docs/archive/` 是"版本快照"，不是"过时文档墓地"**——[archive/README.md](../archive/README.md) 明文禁止把过时文档搬进去。归档目标要另立目录（本方案建议 `docs/superseded/`）。
3. **`docs/reports/` 永不改内容**（AGENT.md §9.4）——只能加顶部指针，不能删/改/移。
4. **`g_v_map.yaml` 里钉死的 `code_scope` / `evidence` 路径**与 `docs_consistency_config.json` 里的 `required_files` / `historical` 路径是**门禁输入**，移动即断门禁（要么不动，要么同 PR 改配置）。

## 4. 执行顺序（5 个 commit，逐步可回滚）

> 每一步都**先只读检查、再改、再跑门禁**；任一门禁红 → `git checkout -- .` 回滚本步。

### P0｜体检与基线（不改任何文件）

```bash
# 1) 工作区状态（哪些未跟踪、哪些被 ignore）
git status --short
git status --ignored --short | head -50

# 2) 入库面到底有什么、多大（按体积降序，找隐藏的大文件）
git ls-tree -r -l HEAD | sort -k4 -nr | head -25

# 3) 有没有被 git add -f 塞进来的大件（>5MB 入库即需处理）
git ls-files | xargs -I{} du -k "{}" 2>/dev/null | sort -nr | head -20

# 4) 现有 .gitignore 是否真的挡住了 data/ 与 outputs/
git check-ignore -v data/raw/reaction_qm/B3LYPD3_TZVP.h5 outputs/pesn/v53mp
```

PowerShell 等价（体积排序）：

```powershell
git -c core.quotepath=false ls-tree -r -l HEAD |
  ForEach-Object { $p = $_ -split '\s+',4; [pscustomobject]@{Size=[long]$p[3]; Path=$p[4]} } |
  Sort-Object Size -Descending | Select-Object -First 20
```

把结果存成 `docs/agent_runs/repo_baseline_20261120.md`（**只读快照，不改任何证据**），后续每步对比。

**关于 `render_gv_map --check`**（重要，非本次引入，已于同日修复）：它读 `config/registry/g_v_map.yaml` 里 `campaigns.V5.4.1/V5.4.2.data_manifest` 指向的 `/pes2ts_data/v53mp_50k_data/split_manifest_v53mp.json`——该路径只在 WSL 内存在。校验器 `pes2ts_core/gv_registry.py` 原来对所有 label 一律要求 `(root / value).exists()`，于是在 **Windows 与 GitHub CI（ubuntu-latest 同样无此挂载）上都必然失败**，`master` 自 2026-10-31 起的每一次 run 都红。

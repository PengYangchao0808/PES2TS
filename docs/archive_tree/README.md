# PES2TS 开发档案树（docs/archive_tree/）

> **状态**：Canonical（档案树入口；只追加，不改写已冻结条目）
> **层级**：L3 证据 / 开发档案树（工程治理面，不涉及 G0–G4 能力与 V 战役语义）
> **取代关系**：无；其内容由 `docs/plans/PES2TS_文档修订台账.md` 的“退役/档案条目”动作维护
> **上游依赖**：ADR-0035、`docs/infra/PES2TS_开发档案树与文档清理方案_v1_20261121.md`
> **下游消费者**：未来的维护者、新人、外部评审、季度审计
> **当前版本**：v1.0 @ 2026-11-21

## 这是什么

本目录用 **7 个分期 / 17 个条目** 记录 PES2TS 从 2026-09-25 到 2026-11-21 的
核心开发思路、关键技术决策、量化成果与**负结果**。它取代“保留全部过程文档”的
做法：**结论留在档案条目里，原文的字节留在 git 历史里**（见 ADR-0035）。

## 怎么读

1. 先读 `_INDEX.md`：一期一行，看“项目怎么一步步走来的”。
2. 想深入某期：读对应目录的 `E##_*.md`（每期 1–4 条）。
3. 想知道“现在的权威口径”：读 `00_global/authority_map.md`。
4. 想追某条结论的证据：条目末尾“证据指针”给出原始文档路径或 `git log` 命令。
5. 想找失败/负结果：`90_evidence/negative_results.md`（N01–N21）。

## 与四个既有目录的边界（不搬家）

- `docs/archive/`：某次修订的字节级快照（只读）；本目录是**结论化叙述（人读）**。
- `docs/superseded/`：已被取代的单一文档；本目录**不接收**过时文档。
- `docs/reports/`：只读证据；本目录**只引用**不复制。
- `docs/plans/`、`docs/design/`、`docs/contracts/`：现行与历史文档；本目录**只新增、不移动**。

## 目录结构

- `_INDEX.md`：分期×条目总表 + 主题交叉索引 + 负结果索引
- `_TEMPLATE.md`：条目模板（9 字段 + 四级完成度词表）
- `CHANGELOG.md`：档案树自身变更（append-only）
- `00_global/`：横切常青层 X0（权威指针、期边界证据）
- `10_p1_…` – `70_p7_…`：7 个分期目录，共 17 个条目
- `90_evidence/`：负结果总表、指标账本、决策索引、映射 csv
- `99_meta/`：模板/命名规则/后续执行清单

## 写作纪律（摘要，完整见 `_TEMPLATE.md`）

1. **只写文档事实**：指标必须能在原报告结论段/主表找到；找不到写“未留档，不引用”。
2. **负结果不豁免**：失败实验、被否方案、被裁剪 run 必须进“负结果”段，不得美化。
3. **状态与时间双轴**：“当时判定 → 事后修正”并列，不覆盖当时结论。
4. **四级完成度**：`implemented / fixture_passed / smoke_passed / scientifically_validated`。
5. **条目不回改**：冻结后只可追加“后续指针”；档案树自身变更登记 `CHANGELOG.md`。

## 如何新增一期

每期/每战役收口时：抽结论 → 按模板写条目 → 更新 `_INDEX.md` 与 `CHANGELOG.md`
→ 台账登记 → 按 ADR-0035 退役过程稿（可选）。

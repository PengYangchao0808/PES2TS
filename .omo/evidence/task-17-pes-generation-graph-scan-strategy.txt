all_release_gates_pass
----------------------
- False when candidates empty or every candidate carries PRUNED_BY_BUDGET
  (runnable subgraph empty)
- True only when runnable subgraph non-empty AND every fallback_ids entry
  named by any candidate exists in registry.STRATEGY_REGISTRY
- Unit tests: empty / pruned-only / valid NETWORK_PATH fallback /
  undefined fallback ref

DESIGN/CONTRACT DECISIONS RECORDED
----------------------------------
1. Proposal profiles: electronic_review_complete=False,
   geometry_review_complete=False (no ReviewRecord consumed at proposal
   stage); has_usable_target_definition stays True (endpoint hypothesis).
   Direction readiness therefore False until review+assembly complete —
   correct §10.1 semantics; execution_eligible stays false regardless.
2. Mode projection: contracts_v2 requires SINGLE_1D => 1 driver and
   COUPLED/SCHEDULED_1D => 2..3 drivers, while schedules.py suggests
   SCHEDULED_1D for single-driver smoothstep. Selector projects
   single-driver schedules as SINGLE_1D with schedule_kind +
   per-driver schedule_values carrying non-linearity; original
   suggested_mode preserved in candidate extensions
   (selector._contract_mode docstring).
3. Cross-module defect (NOT fixed here — orchestration-only guardrail):
   schedules.assert_schedule_integrity rejects any coordinate origin text
   containing "difference"; coordinate_pool conformational D legitimately
   emits geometry_kind="torsion_difference". Selector catches the
   ValueError per candidate, records typed SCHEDULE_INTEGRITY
   failure_reasons and emits fallback schedule rows (uniform lambda grid)
   so the candidate stays visible. Affects 23/24 demo24 records.
   Follow-up plan needed: vocabulary alignment between todo 12 and todo 14.
4. Cross-module defect (NOT fixed here): coordinate_pool ring-attack
   torsion generation can emit D coordinates with duplicate terminal map
   (e.g. RXN_0000100071 coord-0004 maps (2,1,3,2)); contracts_v2 rejects
   duplicate driver maps. Selector skips such pool candidates and records
   case-level COORDINATE_DRIVER_MAPS_NOT_UNIQUE reasons (never silently
   rewrites chemistry). Follow-up: coordinate_pool ring torsion atom
   selection.
5. Candidate budget object: proposal stage authorizes no compute —
   max_attempts=1, max_cpu_hours=0.0, max_wall_seconds=0 by default
   (overridable via scan_strategy.proposal_budget).
6. Budget interaction: schedules.py applies its own conservative
   n_active x direction_budget <= max_total_candidates.scan projection, so
   selector-level budget tests must pick budgets where schedules survive
   (e.g. scan=4 for the 10-driver-set H-transfer fixture).
7. schema_name vocabulary: contracts_v2 uses schema_name="StrategyProposal"
   with schema_version="g1_strategy_proposal_v1" (not the reverse).

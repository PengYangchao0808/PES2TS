INTERFACE DECISIONS (design §10.1 + 谱系归一裁决 §3)
- Proposal: execution_eligible forced False (factory raises ContractError on True;
  validate rejects True). needs_review status allowed (reasons required); rejected
  requires blocking_reasons. Per-candidate failure_reasons and whole-case
  blocking_reasons stored separately; top-level reasons[] per design §10.1.
  epistemic_status pinned to "endpoint_hypothesis". Candidates at proposal stage
  are scan-mode only (mode ∈ SINGLE_1D/COUPLED_1D/SCHEDULED_1D); path proposals
  arrive with the PathRequest todo.
- GenerationPlan: frozen; candidates is a discriminated union on candidate_kind
  ∈ {ScanCandidateV2, PathCandidateV1}. Cross-kind key contamination rejected
  (scan-only: mode/drivers/lambda_values/schedule_id/schedule_kind/assembly_id;
  path-only: endpoint_geometries/image_chain/method_kind). ScanCandidateV2 covers
  SINGLE_1D (exactly 1 driver), COUPLED_1D/SCHEDULED_1D (2..3 drivers,
  MAX_SCAN_DRIVERS=3 = config scan_strategy.max_scan_coordinates); shared
  lambda_values + schedule_id; SCHEDULED_1D requires schedule_kind
  (linear/event_A_early/event_A_late/smoothstep). PathCandidateV1 minimal:
  n_atoms + endpoint_geometries{reactant,product} (N×3 finite, row count ==
  n_atoms) + image_chain{n_images>=1}; method_kind ∈ {NEB} optional.
  Plan top-level: policy_hashes (non-empty), backend{engine,adapter_version,method},
  candidate_graph (unique node_ids, terminal bools, edges reference known nodes),
  budget, compiled{kind: hashes|recipe}, quality_tests; status frozen/superseded
  (superseded requires supersedes). Empty candidates rejected.
- BackendCapability: orca_capabilities_v1.json shape — engine_version,
  adapter_version, supported_modes ⊆ {SINGLE_1D,COUPLED_1D,SCHEDULED_1D,PATH_NEB},
  coordinate_kinds ⊆ {B,A,D}, max_scan_coordinates int>=0,
  point_limits{baseline,max} positive ints baseline<=max, custom_schedule_support
  bool, constraint_support{native_scan,per_point_constraints,simul_scan} bools,
  method_element_coverage {method: [elements]}, probe_receipts
  [{probe_id,status,receipt_sha256?}]. Statuses active/retired.
- Identity sealing: REUSES pes2ts_core.contracts.seal_document verbatim (imports it)
  so volatile-key semantics are identical to v1: created_at/generated_at/producer
  volatile, content_sha256 stable. stable_json_dumps from utils/hashing.py.
- FORBIDDEN keys: single source — imports contracts.FORBIDDEN_TRUTH_KEYS +
  g1.v2_verify.FORBIDDEN_EXPORT_KEYS (lower-cased union) as FORBIDDEN_KEYS.
  Importing v2_verify creates no cycle (g1 does not import scan_strategy) and does
  not trip truth_guard (no ground_truth/truth_sources strings, no truth imports).
  validate_v2_document ALWAYS rejects forbidden keys at any depth (unlike v1 which
  gates on production_input).
- Legacy ScanPlan exporter stubs deliberately absent (todo 18).

   - build_coordinate_pool(route_result, edit_graph, context, coupling,
     bundle, materials) -> CoordinatePool
   - CoordinateRecord {coordinate_id, role, kind, atom_maps (map ids),
     units, event_ids, origin: OriginRecord}
   - roles: driver|monitor|guard|target_test (design §6.1); kinds B|A|D;
     units angstrom|degree
   - origin source_kind ∈ {edit, hydrogen_event, ring_geometry,
     conformational_difference}; O-edit origins carry
     note="order_change_monitor_by_default"
   - Generation rules (design §6.2):
     * F/B edits → B (driver-nominated) + target_test companion
     * O edits → B monitor-only (never drivers by default)
     * H events → TWO separate partner B records (donor-H / acceptor-H;
       never one B = d1−d2), ∠DHA as A, optional D–A as B, H2 → hh B
     * genuine ring events → attack A/D from endpoint adjacency
       (formed→R-side neighbours, broken→P-side)
     * conformational Δtorsion ≥ 10° (materials required) → D drivers
       + target_test companions, top-3 by |Δ| (stable tie-break)
   - Event coverage per driver SET: direct | coupled_monitor (shared
     support atom / same H / same aromatic region / same ring group /
     shared edit membership evidence) | uncovered; coverage vocab single-
     sourced from contracts_v2.COVERAGE_KINDS
   - default_automatic requires: no uncovered event AND ≥1 driver AND
     route candidate review_required=False; otherwise typed
     non_default_reason (UNCOVERED_EVENT | NO_DRIVER_COORDINATES |
     ROUTE_REVIEW_REQUIRED) — candidate stays listed
   - constraint_rank(n_drivers, n_guards) = n_drivers + n_guards;
     monitors never count; guard role defaults empty on every candidate
   - all_edits_monitored invariant: every edit pair covered by
     driver∪monitor coordinates in every candidate (drivers monitor
     themselves; unselected driver-nominated records act as monitors)
   - determinism: coordinates sorted by (atom_maps, kind, role, origin);
     candidates by driver-id tuples; to_json via stable_json_dumps

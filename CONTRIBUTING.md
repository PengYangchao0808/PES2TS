# Contributing to PES2TS

## 1. Setup

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
# optional PES-N runtime / training
pip install -r requirements-pesn-runtime.txt
pip install -r requirements-pesn-training.txt
```

The repository is run from source; there is no packaging metadata yet. The CLI
entry is `python bin/pes2ts` (or `bin/pes2ts`).

## 2. Tests

```bash
pytest -q --ignore=tests/pesn     # base tier: no torch
pytest -q                          # full tier: requires torch
python scripts/render_gv_map.py --check
python scripts/check_docs_links.py
```

Gated markers (`realdata`, `xtb`, `acp`, `orca`) are deselected by default; see
`pytest.ini`. New tests must be synthetic or use `tests/fixtures/`; do **not**
read `outputs/` (fresh clones do not have it).

## 3. G–V rules

- **G = code/physics capability** (G0–G4.2). Code modules are named by
  capability: `key_atom_egnn.py`, `xtb_freeze_transport.py`.
- **V = training/test campaign** (V4.x/V5.x/V6/V7). Campaigns own config,
  frozen data manifest, runs and reports.
- The mapping is in `config/registry/g_v_map.yaml`; the human-readable table is
  generated by `scripts/render_gv_map.py`. Never hand-edit the generated doc.
- New V campaign: add a YAML entry, run `--write`, add config under
  `config/campaigns/`, and put outputs under `outputs/pesn/<campaign>/`.
- New run record must carry a `gv` block (see ADR-0025); V5+ records are
  validated by `pes2ts_core.gv_registry.validate_gv_run_record`.

## 4. Storage rules

Never commit:

```text
outputs/                 # local run artifacts (except explicit whitelist)
data/interim/            # parquet/shards (except small g2_needs_review.json)
data/manifests/g1_cluster_report.json
artifacts/**/weights.pt
.omo/ .pytest-* .ruff_cache .review_tmp_*
scripts/local/
config/*.local.yaml
```

Model weights go to a GitHub Release asset; the repo keeps
`model_card.md` + `checksums.json`.

## 5. Configuration paths

Do not hardcode local paths. Use `${ENV}` placeholders (fail-closed) and the
variables listed in `scripts/README.md`:

```text
PES2TS_ACP_ROOT
PES2TS_ACP_PYTHON
PES2TS_ACP_CONFIG
PES2TS_GPU_PYTHON
PES2TS_CPU_PYTHON
PES2TS_DISK_ROOT
```

## 6. Pull-request checklist

- [ ] `pytest -q` green (or documented skips for missing local artifacts)
- [ ] `python scripts/render_gv_map.py --check`
- [ ] `python scripts/check_docs_links.py`
- [ ] no staged `outputs/`, `*.pt`, large parquet or local paths
- [ ] G stage and V campaign declared in the map
- [ ] docs index + ledger updated for new plans/reports
